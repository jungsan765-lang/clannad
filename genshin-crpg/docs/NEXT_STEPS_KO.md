## 최신 사용자 결정 — 0.15.22의 계획보다 우선

- 0.15.24부터 UI와 튜토리얼을 같은 담당이 이어 한다. 튜토리얼은 **엠버가 이야기 속에서 도와주는 형식**(여행자의 첫 이동은 페이몬). 말풍선은 누를 곳 옆 빈자리에, 위쪽 막대·메뉴 줄을 가리지 않게.

- 튜토리얼은 강제 스포트라이트다. 배경을 어둡게 하고 실제 조작 대상만 밝힌다. 고정 안내 칸·접기·나중에 계속·의미 없는 다음 버튼을 넣지 않는다. 첫 전투는 원소폭발까지 가르친다(0.15.25).

- '우리 소환체'라는 표현은 금지. **아군 소환체 / 적 소환체**를 사용한다.
- 성장 체감이 최우선이다. 지역별 적 레벨과 편성은 고정하며 파티 인원·평균 레벨에 따라 따라 오르지 않는다.

- **이야기에서 만난 4★은 장이 끝날 때 나눠 준다**(「적어도 4인은」, 「리월에서도 좀 많이 퍼주기도」, 「4인 말고도 그냥 더 많이 퍼줘도 되긴 해」). **기원(가챠)은 손대지 않는다**(「가챠는 냅둬」).

## 이어서 할 순서

1. **다인 모드 남은 것:** 0.16.0 테스트 판을 사용자가 두 계정으로 해 본 결과부터 고친다. 그다음 이야기(퀘스트) 전투에 끼기(지금은 「이야기 전투는 방장 혼자 합니다」)와 방장이 이야기 중일 때의 다인 기록. 한 사람에 캐릭터 하나, 이야기 건너뛰기 없음은 그대로.
2. 실물 Android/iOS 설치·회전·안전영역·터치·확대·자판 검증. Chromium 뷰포트 검사와 구분한다.
3. **밸런스 담당:** `PATCH_0.16.1_KO.md`의 현재 수치와 검증 경계를 먼저 읽고, 자연 새 여정의 동료 획득 → 재료 공급 → 해금 비경 단계 → 보스·치유 → 실제 성장 시간을 확인한다. 이야기 4★ 합류가 있으므로 「4인 완성 파티」가 몬드 첫 장 뒤의 기본이다. 과거 보고서 수치로 되돌리지 않는다.
4. 실제 새 여정 보상만으로 1→10→20→30을 잇고, 30→60 및 시장/파밍 시간을 별도로 확인한다. 합성 강한 캐릭터의 이야기 분기 검사를 밸런스 증거로 쓰지 않는다.

## 게시·보호 규칙

- 완료 후 테스트 게시는 이미 승인됐다. 작업 `crpg/ui-overhaul`, 테스트 `test/crpg-v01414-story`, Draft PR #20. 같은 게시의 재승인을 요구하지 않는다.
- **게시 후 GitHub 워크플로를 기다리지 않는다.** 게시한 40자리 SHA에 고정한 설치 명령과 검사 링크를 바로 전달한다. GitHub 게시·묶음 준비·실제 VPS 설치는 다른 상태다.
- 테스트 설치: `VPS_TEST_INSTALL_KO.md`. 운영 적용 명령도 요청받았다. 같은 SHA를 테스트에 설치한 뒤 `tools/promote-test-release-to-production.sh`로 승격하는 명령을 준다. 현 담당이 운영에서 실행하지 않는다.
- main 병합·운영 접속·운영 DB/저장 초기화는 하지 않는다. VPS에서 npm/build/test를 돌리지 않고 자동 업데이트 타이머를 켜지 않는다.
- 다른 담당 보호 파일: `source/app_av.js`, `source/app_online.js`, `server/worker.mjs`, `.github/workflows/crpg-sync-dist.yml`.
- 이야기 원고·말투·사건을 수정하지 않는다. 과거 미적용 이야기 패치를 자동 적용하지 않는다.
- `dist/`, `reports/`, `evidence/`, 합성 저장·사진은 커밋하지 않는다. 사용 중인 전투 미리보기를 새로고침하지 않는다. 새로고침은 전투 이탈 패배다.
- 계정 비밀값을 문서에 적지 않는다. 숨은 위치/나선비경 공략은 노출하지 않는다. 새 자산 다운로드는 별도 기존 승인 규칙을 따른다.

## 재현

`node tools/gen_liyue_theme.cjs` → `python tools/build.py`가 **끝난 뒤** `python tools/verify_release.py` 및 `node tools/check_tutorial_v01523.cjs`. 브라우저는 `CHROMIUM_PATH`로 시스템 Chromium을 지정할 수 있다. 빌드 중인 dist로 화면 검사를 시작하지 않는다.

기존 `check_ui_v01522.cjs`의 긴 강제 튜토리얼 시나리오는 폐기된 설계다. 현재 안내에는 `check_tutorial_v01523.cjs`를 사용한다. UI 전체 개편의 통과 기준을 이 튜토리얼 검사로 대신하지 않는다.
