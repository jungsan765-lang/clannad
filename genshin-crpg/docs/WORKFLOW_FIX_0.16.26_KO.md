# 0.16.26 워크플로 실패 복구

이번 수정은 게임 밸런스를 다시 바꾸는 패치가 아니라, 조정된 전투를 제대로 검사하고 검증한 정확한 소스로 배포본을 만드는 수정이다. 게임 버전과 엔진은 0.16.26 그대로이며 제품 런타임·DB·이미지·게임 화면·경제 수치는 기존 게시 소스를 유지한다.

## 실제 실패와 수정

원래 실패는 [Actions #308](https://github.com/jungsan765-lang/clannad/actions/runs/38056743739)의 회귀 검사 8개다. 네 묶음 모두 실패해 verify와 test-package가 생략됐다. 당시 source UI 성공이나 일부 381개 계약의 성공을 전체 배포 검사가 성공했다고 해석하면 안 된다.

## 배포 경로

- 회귀·source UI·verify의 checkout을 PR head SHA로 고정했다. 기존 PR 병합 결과를 빌드하면서 배포본에는 head SHA를 적던 불일치를 해소한다. 일반 push/수동 실행은 github.sha를 사용한다.
- tests/tools/server 수정도 같은 워크플로를 실행한다. 기존 source/content/assets 경로와 archive 제외는 유지한다.
- 기존 190개 검사 프로그램을 유지하고, 캐릭터 변경·치유 귀속·나선 오류의 최신 검사 3개를 추가했다. 전체 193개이며 삭제·중복·실패 무시는 없다.
- 네 회귀 묶음과 두 실제 backend의 source UI가 성공해야 verify를 수행하고, 빌드된 UI까지 성공해야 test-package를 생성한다. client/API 엔진 일치와 마지막 SHA 표식 업로드 순서도 유지한다.

## 확인한 범위와 해석

전체 실행 결과는 `data/workflow_fix_v01626/verification.json`에 기록했다. 회귀 검사 193/193개, source/dist × SQLite/Worker 브라우저 4경로, 빌드된 배포 경계 14개 계약, 설치 스크립트 문법과 client/API 엔진 일치가 모두 통과했다. 네 묶음 결과는 51/51·52/52·52/52·38/38이다. 원격 authored DB·이미지와 정확한 기존 게시 소스를 복사한 별도 실행 환경에서 회귀 검사를 수행하고, 같은 입력으로 server/client를 빌드했다. 다섯 실행 환경의 제품 입력 290개 파일은 실행 후에도 원격 Git blob과 일치했으며, 모든 검사 프로그램의 실행 파일과 게시 파일도 일치한다. 과거 v0.13.43 저장 검사는 실제 불변 커밋의 소스와 Git blob이 일치하는 DB를 내보내 로컬 검사에 제공하며 CI는 전체 Git 이력을 사용한다. 새 GitHub 실행의 완료 여부는 이 로컬 결과와 별도로 확인해야 한다.

새 나선 참조는 1~2층에 기존 basic/guard, 3층 이상에 공개 E/Q·guard·전투 치료품을 사용한다. 3층은 +9·자연 성유물, 6층 Lv45, 8층 Lv60/+12로 준비를 높였다. 3~6층은 C0, 7층 이상 주인공과 4성 동료는 C6, 12층은 종려·진·다이루크 고정 편성 C6·문턱 장비다. 재고는 음식 각각 12개, 치료품 각각 3개로 한정하며 방 사이에 HP/재고를 초기화하지 않는다. 10층은 기존 방어구와 별도 화력 공략을 유지한다. 실제 조건은 `tests/helpers_abyss_ci_v01626.cjs`와 나선 원자료에 전부 기록한다.

10·11층 마지막 방의 주인공 KO 후 동료 승리는 기존 허용 규칙대로 정복으로 구분한다. 첫째·둘째 방의 주인공 KO는 NEXT로 이어지지 않는다. 12층은 세 방 전원 생존이다. 따라서 36방 전부 무KO라고 쓰지 않는다. 일일보스 검사에 표시된 잔여 HP는 퇴장 정산 이후이며 무KO 증거가 아니다. Geo/Electro 공개 참조만 종료 직전 전원 생존을 따로 확인한다.

이 검증은 명시한 준비와 공략의 회귀 검증이다. 모든 명함 편성의 난도, 최소 육성 조건, 자연 계정의 전체 육성 시간이나 시장 경제가 완벽하다는 증명이 아니다. 이 한계를 없애려고 현재 밸런스를 약화하거나 옛 검사를 무시하지 않았다.

## 다음 담당자

1. 이 문서와 `data/workflow_fix_v01626/verification.json`을 먼저 읽는다.
2. Actions 실패 8개와 옛 소스 보충 fixture를 임의로 삭제하지 않는다. 수정한 계약과 193개 등록은 모두 유지한다.
3. 최신 규칙의 과거 전투 보존·첫 속도·KO·효과 귀속은 최신 회귀 검사에서 계속 확인한다.
4. 추가 밸런스 조정은 실제 플레이/자연 수급 증거와 사용자 승인 범위로 구분한다. CI 성공을 전 조합 밸런스 완성으로 쓰지 않는다.
5. 테스트 브랜치 고정 SHA 소스와 별도로 전달한 적용 명령을 사용한다. 실제 VPS 설치와 main 병합은 이번 작업에서 실행하지 않는다.
