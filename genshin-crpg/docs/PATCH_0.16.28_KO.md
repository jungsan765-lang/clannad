## 무엇이 느렸고 어떻게 고쳤나

기존 서버는 최대 16개 계정의 실행 객체를 보관합니다. 활성 계정이 그보다 많으면 객체를 다시 만들 때 전체 이야기 그래프와 콘텐츠 조회표까지 반복 조립했습니다. CPU 측정에서 이야기 조립이 큰 병목으로 확인됐습니다.

이제 같은 콘텐츠와 같은 운영자 밸런스 설정을 사용하는 계정은 콘텐츠 조회표와 조립된 이야기 그래프를 재사용합니다. 각 계정의 저장 데이터·진행·이름·선택·전투 객체는 따로 유지합니다. 운영자 설정 판과 DB 소유자가 다르면 공유하지 않습니다.

SQLite 질의의 준비 작업을 최대 128개까지 재사용하고, 저장 변경분에서 공개 응답을 바로 만듭니다. 행동 응답 JSON도 한 번만 변환합니다. 실행 객체는 기본 16개를 유지하되 10분 이상 쓰지 않으면 메모리에서 정리합니다. 저장 데이터와 영수증은 삭제하지 않습니다.

처리가 빨라진 뒤 기존 검사에서 드러난 **신규 계정의 공개 프로필이 최대 5초 동안 조회되지 않는 오류**도 고쳤습니다. 새 계정을 만들면 공개 ID 조회 캐시에 즉시 추가합니다.

## 검증

## 적용과 다음 확인
