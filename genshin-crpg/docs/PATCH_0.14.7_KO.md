# 0.14.7 테스트 후보 — 테이바트 UI 전면 개편, 효과음, 채팅·교환

테스트 서버(https://test.clannad.shop) 확인용 후보입니다. 사용자 승인 전에는 main 병합과 운영(clannad.shop) 반영을 하지 않습니다.

## 플레이어가 보게 되는 것

- **화면 틀**: 위쪽 HUD(장소·시간·진행 상태·레벨 고리·체력·모라)와 아이콘 메뉴. Esc로 페이몬 메뉴처럼 전체 메뉴를 엽니다. 휴대폰에서는 아래쪽 메뉴 막대로 바뀝니다.
- **PC 단축키**: F1 모험가 핸드북 · J 임무 · L 편성 · C 장비·성장 · B 가방 · O 호감도 · M 지도 · T 이야기 · / 채팅. 이야기에서는 Space·Enter·F로 넘기고 1~9로 선택지를 고릅니다. 전투의 E·Q 선택은 그대로입니다.
- **스크롤 없는 화면**: 1280×720 기준으로 메인 화면 3,425px → 720px, 가방 6,279px → 720px처럼 페이지가 한 화면에 들어갑니다. 긴 내용은 구역·탭·안쪽 스크롤로 나눴습니다.
- **메인 화면**: 왼쪽에 장소·다음 여정·탭(할 일 / 시설 / 지맥·보스 / 지역 정보)·기다리기, 가운데에 큰 지도와 목적지. 안전한 거점은 시설 탭이 먼저 열립니다.
- **이야기**: 장소 배경이 화면을 채우고 아래 대화창에 대사. 대화창 아무 곳이나 눌러 넘기기, 선택지 위에 직전 대사 표시, 「자동 재생」(선택지에서 멈춤).
- **전투**: 적을 크게(레벨·원소 표시), 오른쪽 1~4번 파티 목록, 원형 스킬 버튼(재사용 차례 숫자, 원소폭발 빛남), 최근 기록 3줄, 결과 화면은 승리 배너와 보상 타일.
- **모험가 핸드북(F1)**: 여정(지금 할 일·오늘의 기록) / 토벌(필드 보스·이틀 주기 보스 상태와 길 안내) / 지맥의 꽃(이번 시간·단계표) / 나선비경 기록 / 동료 획득 조건.
- **캐릭터 화면**: 왼쪽 파티원 목록, 가운데 캐릭터 그림, 오른쪽 능력치·장비, 경험치 책.
- **움직임**: 지역별 강조색(몬드 바람색, 리월 금색, 드래곤스파인 얼음색, 층암거연·나선비경 보라색 등), 카드·버튼에 마우스를 올리면 기울어지며 빛이 흐름, 메뉴 배경의 빛 입자, 이동·작업 화면의 로딩 팁. 설정의 「움직임 줄이기」나 시스템 설정을 따르면 꺼집니다.
- **효과음 전면 점검**: 40종을 하나씩 다시 만들었습니다. 버튼은 원작 공식 클릭음(마우스를 올릴 때는 같은 클릭을 높고 짧게), 임무·의뢰·획득·장착·요리·단조·합성은 본편 녹음을 그대로 씁니다. 나머지는 실제 소리가 나는 원리를 본떠 합성했습니다 — 하프·고쟁(줄을 튕기는 소리), 첼레스타·유리·강철·나무(때리면 울리는 소리), 물(작은 거품 수십 개), 불(일렁이는 불길과 탁탁 튀는 소리), 번개(불규칙한 방전), 바위·풀(자갈·나뭇잎 알갱이). 음이 미끄러지는 소리(또잉)는 하나도 없고, 차임은 공식 클릭음과 같은 음계(D 펜타토닉)로 맞췄습니다. 크기는 원작 녹음과 비슷하게 맞추고, 폰·노트북 스피커에서도 들리도록 중음역 위주로 만들었습니다.
- **전투 결과 음악 고르기**: 승리는 원신 OST 끝부분 4곡(Gallant Challenge 기본, His Resolution, Wrath of Monoceros Caeli, Wind-Washed Mountains)·본편 도전 성공·공식 웹 이벤트 성공음·합성 중에서, 패배는 본편 도전 실패(기본)·웹 이벤트 실패음·OST 2곡(Moonlike Smile, Fragile Fantasy)·합성 중에서 고릅니다. OST는 게임에 이미 있는 곡 파일에서 잘라냈고 앞뒤를 부드럽게 줄입니다. 결과 음악이 나오는 동안 배경음을 잠시 낮춥니다.
- **효과음 고르기**: 설정 → 소리·전투 연출 → 「효과음 고르기」(타이틀 화면 설정 창에도 있음)에서 모든 소리를 들어 보고 녹음/합성 중 마음에 드는 쪽을 고를 수 있습니다. 고른 소리는 기기에 저장됩니다. 배경음과 새·활·멧돼지 녹음은 그대로입니다.
- **채팅(테스트 서버)**: 전체 채팅 한 채널. 140자, 1.2초에 한 번·30초에 8번까지, 글자만 표시(링크·서식 없음), 이 기기에서 모험가 숨기기, 운영자 가리기.
- **교환소(테스트 서버)**: 가방처럼 타일을 눌러 담는 교환 창. 받는 사람은 최근 채팅 상대에서 고르거나 아이디로 입력. 받은 제안 수락·거절, 보낸 제안 취소. 가방의 아이템 정보에 교환 가능/불가와 「교환 바구니에 담기」.

## 교환 규칙(기초 단계)

- 교환 가능: 음식, 몬스터 재료, 식재료, 가공 식재료, 광물, 제작 재료, 지역 특산물, 기계 부품, 연금 재료, 소모품, 전투 치료품, 탐험 도구, 전술 도구, 장착하지 않은 일반 장비·성유물.
- 교환 불가: 모라, 임무 아이템, 경험치 책, 보스 재료, 필드 보스 재료, 무기 원형, 특수 재료, 특별 보상, 외형·탐험 장치, 기본 생활 도구, 시스템 항목, 전용 무기, 이야기 핵심 장비, 장착 중인 장비.
- 한 제안에 6종류, 종류당 999개까지. 보내는 사람의 대기 중 제안은 5건까지.
- 수락은 두 사람 모두 자유행동 중일 때만 됩니다(이야기·전투 중이면 거절). 서버가 두 세이브를 한 번에 바꾸고 각자 revision을 1 올립니다. 화면은 서버 기록을 다시 받아 맞춥니다.
- 로그인 아이디는 교환 목록과 채팅에 보이지 않습니다. 채팅 상대는 공개 채팅 ID로 고릅니다.

## 구조(다음 작업자용)

- `source/app_shell.js`: 화면 틀. 기존 화면 함수가 만든 DOM을 **그대로 옮겨** 배치합니다(버튼·처리기·클래스 유지). HUD, 페이몬 메뉴(`CRPGShell.extraTiles`), HUD 도구(`CRPGShell.extraTools`), 화면별 배치(메인·이야기·전투·결과·메뉴), 탭(`tabset`), 단축키, 여행 안내 팝오버, 이야기 자동 재생, 레벨업 배너.
- `source/app_motion.js`: 포인터 기울기·빛, 지역 강조색(`body[data-region]`), 빛 입자 캔버스, 로딩 팁.
- `source/app_sound.js`: 효과음(`GameAudio.buffer/play/unlock` 교체). 소리마다 `j(d)`가 샘플 단위로 소리를 계산하고(Karplus-Strong 현, 부분음별로 따로 줄어드는 타악기, 거품, 알갱이, 불규칙 방전), 오프라인 오디오로 잔향·압축을 거친 뒤 **150 Hz 위 50 ms 최대 크기**로 맞춥니다. `v`는 그 위의 재생 크기입니다(원작 녹음 0.45와 귀로 비슷하게 맞춘 값). 녹음/합성 선택은 `settings.sfxChoice`, 승리·패배 후보는 `VARIANTS`, 마우스 올림처럼 녹음을 변형해 쓰는 소리는 `DERIVED`. 소리를 켠 뒤 한가할 때 자주 쓰는 합성음을 미리 만들어 둡니다(`warm`). 행동별 소리와 레벨업 감지도 여기 있습니다.
- 소리를 들을 수 없는 작업 환경이라 스펙트로그램과 수치(길이, 음높이 미끄러짐, 중심 주파수, 저음 비율, 크기)로 원작 녹음과 비교해 맞췄습니다. 실제로 들어 보고 어색한 소리가 있으면 「효과음 고르기」에서 녹음으로 바꾸거나 이 파일의 해당 소리만 고치면 됩니다.
- `source/app_handbook.js`, `source/app_chat.js`, `source/app_trade.js`, `source/runtime_trade.js`(교환 규칙·이동, 서버와 공유), `source/shell.css`(모든 새 스타일, `body.teyvat` 범위).
- 서버 `server/fixed-region-live.mjs`: `/chat/recent`, `/chat/send`, `/chat/delete`, `/chat/stream`(인증된 SSE), `/trade/list`, `/trade/offer`, `/trade/accept|decline|cancel`. `CRPG_FEATURES` 환경변수로 켭니다. 지정하지 않으면 DB 경로에 `live-staging`이 들어간 테스트 서버만 `chat,trade`를 켜고, 운영 DB(`production.sqlite3`)는 끈 채 테이블도 만들지 않습니다.
- 테스트: `tests/test_fixed_region_live.mjs`에 채팅·교환·운영 꺼짐 검사를 추가했습니다(자동 배포 검증에도 쓰임). 브라우저 흐름 검사(`tests/test_online_browser.mjs`)는 새 UI에서 그대로 통과합니다.
- 주의: 브라우저 테스트는 `data-screen` 선택자를 씁니다. body나 HUD에 `data-screen`을 붙이지 마세요(셸은 `data-shell-screen`을 씁니다). 버튼 안에 CSS 글자(::after content)를 넣으면 접근성 이름이 바뀌어 테스트가 실패합니다.

## 운영 반영 때 할 일(승인 후)

1. main 병합 → 테스트 팩과 같은 엔진으로 운영 서버 재시작과 운영 클라이언트 교체.
2. 채팅·교환을 운영에서 켜려면 운영 서비스 환경에 `CRPG_FEATURES=chat,trade`를 넣고 재시작합니다(테이블은 시작할 때 생성).
3. 운영 서비스는 테스트와 같은 코드 폴더(`/opt/genshin-crpg-fixed/repo/genshin-crpg`)에서 `server/generated/engine.mjs`를 시작할 때 한 번 읽습니다. 테스트판 자동 배포는 이 폴더를 새 코드로 바꾸고 엔진을 다시 만들지만 운영 서비스는 재시작하지 않으므로 평소에는 운영이 그대로입니다. 그러나 그 사이 운영 서비스가 어떤 이유로든 재시작되면 새 엔진을 읽고, 엔진 호환 목록(`ENGINE_COMPATIBILITY`)이 현재 엔진 하나뿐이라 기존 운영 클라이언트의 모든 행동이 「게임 업데이트를 맞추고 있습니다」(VERSION_MISMATCH)로 거절됩니다. 테스트판을 올리기 전에 운영 서버를 별도 폴더(또는 고정된 커밋)에 두는 것을 권합니다.

## 다음 큰 작업: 다인 모드(사용자 요청, UI 개편 뒤)

- 주인(호스트)의 세계에 다른 모험가가 들어옵니다. 주인은 반드시 자신의 주인공으로 플레이합니다.
- 들어오는 사람은 자기 캐릭터 하나를 골라 입장합니다.
- 전투 중에도 중간에 참여할 수 있어야 합니다.
- 나선비경처럼 혼자 하는 도전은 함께 들어갈 수 없습니다.
- 설계 메모: 주인의 세이브가 기준(서버 권한), 참가자는 자신의 캐릭터 상태(레벨·장비)를 가져와 주인의 전투에 아군 행동자로 추가, 차례가 오면 참가자 화면에서 입력(시간 제한 후 자동 행동), 보상은 각자 세이브에 별도 지급, 세션은 `/coop/*` 경로와 실시간 스트림(채팅 스트림 재사용)으로 구현.
