# 0.14.13 패치 노트 (테스트 서버 후보)

지도 길 정리, 막힌 버튼의 이유 표시, 보상 창 가독성, 채팅 Enter·폰 채팅, 폰 화면 전체 점검, 운영 반영 도구를 묶었습니다. 사용자가 테스트 서버에서 확인하고 「운영 반영」이라고 한 뒤에만 운영에 올립니다.

## 지도의 길 (`tools/trace_terrain_roads.py`, `source/terrain_map.js`, `source/runtime_world.js`)

사용자 의견: 「왜 돌아서 가는 길이 생기는 거야? 상식적으로 이해가 안 되는 길이 너무 많아」.

- **원인 1 — 그림 읽기**: 길 추적기가 드래곤 스파인의 눈·얼음(푸른 회색)을 물로 읽어, 설산 안의 길이 산 전체를 돌아갔습니다. 물은 빨강 값이 낮은 진한 청록(바다·호수 r≈42~55)만으로 좁혔습니다(`r < 68`).
- **원인 2 — 비용**: 그려진 길만 고집하도록 들판 비용이 7배였습니다(길이 7배 돌아도 그 길을 탐). 들판 1.9, 물 22로 낮춰 길이 조금 더 길 때만 그려진 길을 따르고, 좁은 물목은 건너며, 호수·바다는 여전히 피합니다.
- **원인 3 — 연결이 없음**: 지도에서 맞닿은 곳끼리 길이 없어 가장 빠른 길이 몬드성 쪽으로 빙 돌았습니다(울프 영지 → 숲 → 초원 → 왕랑 구역 등, 직선의 최대 11배). 이웃끼리 바로 잇는 길 15쌍(양방향 30개, `CRPG_LOCAL_V01413`, 조건 없음)을 놓았습니다.
  - 울프 영지↔북풍의 왕랑 구역(10분), 다운 와이너리↔울프 영지(15), 서풍 매의 사당↔바람이 시작되는 곳(10), 시드르 호수 낚시터↔몬드 외곽 초원(10), 우인단 보관고↔바람이 시작되는 곳(10), 매의 해안↔우인단 보관고(10), 매의 해안↔북풍 늑대의 사당(10), 북풍 늑대의 사당↔천풍 신전(15), 남풍 사자의 사당↔바람이 시작되는 곳(20)·타타우파 협곡(15)·설산 탐사 야영지(20), 설산 탐사 야영지↔일식 부족 야영지(15), 맹세의 갑각↔매의 문 비경(10), 몬드 동쪽 광산↔숲(10)·북풍 늑대의 사당(15).
  - 시간은 비슷한 길이의 기존 길에 맞췄고, 샘물 마을→바람이 시작되는 곳이 설산 쪽으로 도는 일이 없게 확인했습니다.
- **결과**: 모든 길이 직선의 1.7배 이내(전에는 2.95배), 가장 많이 돌던 이동이 11배 → 3.7배(드래곤 스파인 안쪽처럼 원래 굽은 곳만 남음).
- 그림을 바꾸거나 연결을 더하면 `python tools/trace_terrain_roads.py`로 다시 그려 `CRPGTerrainMap.roads`에 붙입니다.

## 왜 안 되는지 보이기 (`source/app_reasons_v01413.js`)

사용자 의견: 「지맥에 레벨 모자라서 못 들어간다는 경고 표시가 있어야 할 것 같아. 아이템을 못 낀다던가 등등 전체적으로」.

- 막힌 버튼은 이유를 마우스를 올렸을 때만(폰에서는 아예) 볼 수 있었습니다. 이제 회색 버튼을 누르면 그 옆에 말풍선으로 이유가 뜹니다(창·모달 위에서도 보이게 맨 위 층에 그림).
  - 이유는 버튼이 가진 것(`actionButton`이 엔진의 이유를 `data-reason`에 담음, 또는 title), 없으면 버튼 옆에 적힌 안내문입니다.
  - 막힌 버튼은 누름이 아래로 지나가게 했고(`button:disabled{pointer-events:none}`), 그 자리의 버튼을 찾아 이유를 보여 준 뒤 누름은 그대로 막습니다.
- 지맥의 꽃: 레벨이 모자라면 카드에 「⚠ 아직 도전할 수 없습니다 · 주인공 Lv. 5부터 (지금 Lv. 3)」.
- 시설 칸: 들어갈 수 없는 칸에 이유가 칸 안에 적히고(전에는 CSS가 숨김), 칸이 흐리게 표시됩니다.
- 가방의 「캐릭터 화면에서 장착하기」도 막힌 이유를 가집니다.

## 보상 창 (`app_adventure.js`, `shell.css`)

- 「채취 완료」 등 보상 칸이 가방과 같은 모양(등급 색 그림 + 이름 띠)이고, 받은 개수가 어두운 배지에 크게 나옵니다. 전에는 크림색 바탕에 옅은 금색 글씨였습니다. 모라는 금색 칸입니다.

## 채팅 (`app_chat.js`)

- Enter로 엽니다(/도 그대로). 마우스로 누른 버튼이 포커스를 가진 채 Enter를 누르면 그 버튼이 다시 눌리던 브라우저 동작 대신 채팅이 열립니다(키보드로 옮긴 포커스면 버튼을 누름).
- 빈 줄에서 Enter를 누르면 닫힙니다.
- 폰: 위쪽 막대에 채팅 버튼이 들어갈 자리가 없어서, 아래쪽 왼편에 동그란 채팅 버튼(안 읽은 수 표시)을 두고 창은 아래 메뉴 바로 위에서 올라옵니다. 이야기·전투 중에는 버튼을 숨깁니다.

## 폰 화면 점검

사용자 의견: 「폰 UI도 잘 바꾼 거 맞지?」, 「아주 개판이군?」, 「몬드 리월 싹 다 체크해야 될 거야. 있는 장소 없는 장소 화면 전부 다」.

- 점검 방법: 375×812와 360×760 화면에서 몬드·리월의 모든 지역 86곳(각 지역 화면의 모든 탭)과 그 안의 모든 시설을 차례로 열어, 글자끼리 겹치는 곳·내용이 칸 밖으로 넘치는 곳·화면 옆으로 삐져나가는 곳·잘린 글자를 자동으로 찾고 화면을 직접 확인했습니다. 메뉴 화면, 핸드북, 나선비경, 기원, 전투, 보상, 이야기도 같은 방법으로 봤습니다.
- **위쪽 막대**: 장소·안내·레벨·모라·원석·버튼이 서로 겹쳤습니다. 장소 이름만 줄어들고 나머지는 제 크기를 지키며, 핸드북·풍경 보기 버튼은 폰에서 메뉴로 옮겼습니다(풍경 보기 칸 추가).
- **페이지 화면(편성·가방·상점·임무·캐릭터)**: 데스크톱용 열 배치가 폰에서 세로로 쌓일 때 각 부분이 화면 높이를 나눠 가지며 찌그러져(내용 1351px을 183px에) 글자가 다음 부분을 덮었습니다. 폰에서는 제목까지 포함해 화면 전체가 한 번에 스크롤되고 각 부분은 제 높이를 지킵니다.
- **시설 화면(천사의 몫·캐서린 등)**: 같은 이유로 오른쪽 탭과 버튼이 겹쳤습니다. 그림·안내·탭이 차례로 쌓입니다.
- **전투**: 적 카드가 「우리 파티」 위를 덮었습니다. 적·파티가 제 높이를 지키고 전투판이 스크롤됩니다.
- **탭**: 화면 밖으로 잘리던 탭(지맥·보스, 핸드북 동료 등)이 화면 폭에 맞게 줄어들고, 많으면 두 줄이 됩니다.
- **지도**: 「현재 위치」 표시가 옆 장소 번호를 가리지 않게 번호를 위에 그리고 표시는 누름을 통과시킵니다(PC도 같음).
- **기원**: 기원 종류 탭과 × 버튼이 배너 뒤에 숨어 있었고(페이지의 `header{height:66px}` 규칙이 기원 머리에도 걸림), 배너 그림이 흰 막에 가려졌고, 0.14.11의 세로 화면 규칙이 0.14.12 연출과 부딪혀 무기가 반쯤 잘렸고, 10회 결과가 화면 아래로 넘쳐 「확인」을 누를 수 없었습니다. 머리 세 줄(제목·닫기 / 재화 / 기원 종류), 그림이 보이는 배너, 스크롤되는 결과 목록(아래에 「확인」 고정)으로 바꿨습니다. 「건너뛰기」는 밝은 배경에서도 보이게 어둡게 했습니다.

## 운영 반영 도구 (`tools/promote-test-release-to-production.sh`)

- 테스트 서버에서 확인한 바로 그 묶음(같은 커밋)을 운영(clannad.shop)에 그대로 올립니다. VPS에서는 복사와 교체만 하고 npm·빌드·테스트를 하지 않습니다.
- 순서: 테스트 서버가 그 커밋을 쓰는지 확인 → 운영 저장 DB 백업(`VACUUM INTO`, 서비스는 계속 실행) → 운영 API를 `/opt/genshin-crpg-production-server/releases/<sha>`로 바꾸고 새 엔진으로 올라오는지 확인(아니면 즉시 되돌림) → 화면 묶음을 운영 주소로 바꿔(TEST 띠 없음, 운영의 현재 sw.js 유지) `/var/www/genshin-crpg-production/current`에 연결.
- 그대로 두는 것: 운영 DB·환경 파일, Caddy 설정(`/genshin-crpg/dist/` 경로 포함), 테스트 서버, `/opt/genshin-crpg-fixed`. 업데이트 타이머는 켜지 않습니다.
- 끝나면 되돌리는 명령을 출력합니다.

## 운영자 도구 설정 명령

- `server/admin-console-setup.mjs`와 `server/fixed-region-live.mjs`가 직접 실행됐는지 판단할 때 실제 경로를 비교합니다. 릴리스 폴더의 `current` 심볼릭 링크로 부르면 아무 출력 없이 끝나던 문제가 없어졌습니다.
