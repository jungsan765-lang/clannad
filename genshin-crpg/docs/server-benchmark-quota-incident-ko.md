# 2026-09-30 성능시험 쓰기 한도 초과

시험 프로그램의 설계 오류입니다. Windows CMD의 사용 한도가 아닙니다. 사용자가 제공한 Cloudflare 메일은 Durable Objects의 무료 일일 쓰기 100,000행 초과를 알립니다. 재설정 시간은 2026-10-01 00:00 UTC, 한국 시간 10월 1일 오전 9시입니다. 메일은 저장 데이터 삭제를 알리는 내용이 아닙니다. 실제 운영 저장 데이터나 계정 전체 사용 내역을 조회한 것은 아닙니다.

## 원인

기존 시험은 4개 시나리오에서 각각 30회와 준비 2회, 총 128회 행동을 실행합니다. 행동 전에 시험 상태를 복원하면서 약 945~974개 state 조각을 전부 삭제하고 다시 넣었습니다. 초기화만 약 24만 행의 삭제·삽입이 필요하며, 삭제도 쓰기 사용량에 포함됩니다. 여기에 행동 저장과 부가 표·인덱스 쓰기가 더해집니다. 기존 시험은 하루 10만 행 무료 한도 안에서 완주할 수 없습니다.

실행기에 전체 시험을 최대 3회 시도하는 코드도 있었습니다. 실패 후 다시 시작하면 쓰기가 더 늘어날 수 있었습니다. 사용자에게 전달하기 전에 이 사용량을 점검하지 못했습니다.

## 수정

- 처음 한 번만 시험 상태를 넣고, 이후에는 달라진 조각만 복원합니다. 운영 게임 저장 로직은 변경하지 않았습니다.
- 전체 자동 재시도를 제거했습니다. 실패한 위치의 결과를 `latency-partial.json`에 남깁니다.
- 날짜별 시험 계정이 고정되므로 ZIP 복사본이나 시험 비밀키 변경으로 하루 한 번 제한이 초기화되지 않습니다. 로컬 실행기도 당일 재실행을 막습니다.
- 서버에서 다음 복원·행동에 필요한 쓰기 예산을 보수적으로 예약하고, 합계 25,000행을 넘기기 전에 중단합니다. 시험 전용 추정 예산이며 계정 전체의 사용량 상한이 아닙니다.
- 이번 한도가 초기화되기 전에는 Cloudflare 작업을 시작하지 않습니다.
- Windows 실행기는 ASCII/CRLF와 `call npm.cmd`를 사용합니다. 새 안전장치 모듈도 ZIP에 포함합니다.

## 검증 결과

운영 인증을 사용하지 않는 로컬 Cloudflare workerd와 실제 SQLite DO에서 128회 전체 시험을 완주했습니다. 구현 식별자는 `server-43155ce13daa0765167c`입니다.

| 항목 | 결과 |
|---|---:|
| 복원·행동 SQL cursor에서 관측한 전체 쓰기 | 7,514행 |
| 보수적으로 예약한 시험 쓰기 예산 | 19,350행 / 최대 25,000행 |
| 시험 MOVE 한 번의 SQL 쓰기 | 20행 |
| 시험 COMBAT 한 번의 SQL 쓰기 | 25행 |
| 같은 날 두 번째 시험 시작 | 계정 생성 전에 거부 |
| 상태가 같은 복원 | 전체 다시 쓰기 없이 처리 |
| 예산 초과 후 복원 | 거부, SQL 쓰기 0행 |

7,514행은 Cloudflare 청구서의 계정 전체 사용량이 아닙니다. 시험 계정 준비, 플랫폼 alarm 저장, 다른 서비스 사용량은 별도입니다. 실제 원격에서는 플랫폼 사용량도 함께 확인해야 합니다. `reports/server-v2/quota-validation.json`과 `latency-local.json`에 결과를 남겼습니다.

추가 검사로 초기화 시간 경계, 표본 수 제한, 오류 시 단 한 번의 호출, 부분 결과 보존, 비밀값 제외를 확인했습니다. 중복 요청 복구도 실제 workerd에서 검사했습니다. 기존 43개 전체 회귀 검사는 `validation.json`의 이전 기록으로 유지하며, 이번에 43개를 다시 실행했다고 표시하지 않습니다. 이번 수정 범위는 시험용 Worker·실행기·검사·문서입니다. Windows 실제 실행과 한국 원격 속도 측정은 아직 확인하지 못했습니다.

## 지금 할 일과 운영 판단

기존 시험 파일을 다시 실행하지 않습니다. 한도 초기화 후 수정된 ZIP으로 한 번만 시험하고, 결과 또는 부분 결과를 전달합니다. 이 문제를 해결하려고 D1이나 DO를 삭제하거나 유료 플랜으로 변경할 필요는 없습니다.

시험기 수정이 무료 플랜의 운영 용량 문제까지 해결한 것은 아닙니다. 시험에서 행동당 20~25행을 썼으므로 10만 행을 단순히 나누면 약 4천~5천 행동이며, 계정 생성·이전·백업 정리·alarm·다른 서비스까지 포함하면 여유는 더 작아집니다. 이는 사용자 수나 운영 가능량의 보증값이 아닙니다. 운영 이전 전 실제 하루 행동량과 행 쓰기 예산을 확인해야 합니다. 한국 latency 기준과 사용량 검토를 모두 마치기 전 운영 승격을 보류합니다.

이번 대응에서 Cloudflare 원격 배포, 운영 데이터 변경, DB 삭제, Pages 배포를 수행하지 않았습니다.
