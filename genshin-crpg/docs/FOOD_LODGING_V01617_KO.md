# 0.16.17 · 요리와 숙박 비용 검증

## 적용한 내용

기존 회복 요리45종의 제조 모라를 **0에서2~4모라**로 나눴다. 쉽게 확보할 수 있는 재료로 만드는 달걀·무 수프·스튜 등은 상대적으로 높은 제조비, 송이버섯·솔방울·지역 특산물이 필요한 요리는 낮은 제조비를 부여했다. 기존 재료 수량과 회복량은 유지했다. 같은 음식이라도 계정/대상 레벨에 따라 제조비를 바꾸지 않는다. 음식은 먹는 사람의 레벨에 맞춰 회복하므로, 저레벨 계정으로 싸게 만들어 고레벨 시장에 파는 가격 우회를 만들지 않는다.

기존 요리 화면에는 모라 비용 숫자만 연결하고, 지갑으로 가능한 대량 제작 수량을 정확히 제한했다. 새 화면·음식·재료·시스템을 만들지 않았다. 실제 견적·CRAFT 차감·영수증이 같은 값을 사용한다.

숙박 요금은 그대로다. **기본료20×지역요율 + 각 대상별4×자신의 레벨×자신의 손실HP비율×지역요율**을 올림하여 합한다. 부상한 저레벨 동료 때문에 건강한 고레벨 동료의 요금을 더하지 않는다. 적 HP/공격력·기술·편성, 성장/돌파/특성 보상과 요구량, 음식 회복량·같은 음식 연속 금지·전투불능 회복 제한·패시브·시장은 변경하지 않았다.

## 비용을 읽는 기준

- **제조 현금:** 보유 재료를 쓰고 제작에 직접 낸 모라. 재료가 공짜라는 뜻은 아니다.
- **재료 매각 포기 포함:** 제조 현금에 사용 재료의 실제 NPC 매각값을 더한다. 팔아서 숙박할 선택과 비교하는 값이다.
- **전부 구매:** 해당 도시의 재료/가공/완성음식 가격 하한. 상점 재고·재입고 대기·첫 레시피 구입·이동을 제외한 하한이며, 무제한 구매를 실행했다고 주장하지 않는다.
- **준비 시간:** 재고0에서 채집/사냥/낚시→가공→제조까지 걸리는 시간. 미리 만든 음식의 현장 사용 시간과 구분한다.

## 레벨별 비교: 4인 모두 HP50% 손실

여행자+엠버+케이아+리사, 레벨별 합법 제작장비+3/+6, native 회복/식사/숙박. 다음 표는 **몬드의 쉬운 음식6종 안에서 전부 구매 비용을 최소화한 메뉴**다. 제조비와 재료를 포함해 실제로 같은 HP를 완전히 회복했다. 도시 가격은 하한이다.

몬드에서는 재료를 전부 사는 쉬운 메뉴가 Lv.50에서약13%, Lv.55에서약20%, Lv.60에서약27% 숙박보다 저렴하다. 직접 모은 재료를 쓰면 지갑 지출은 더 줄지만, 재료 수집 시간과 매각 포기값을 함께 봐야 한다. Lv.1~40에서는 전부 사는 요리가 숙박보다 비쌀 수 있다. 초반 숙박을 싸게 유지한 결과이며 “모든 레벨에서 모든 음식이 이득”이라고 쓰지 않는다.

전체45종까지 함께 고르는 별도90메뉴에서는 리월의 쌀 찐빵+달걀 메뉴가 Lv.50에서560모라(숙박492), Lv.60에서560모라(숙박586)였다. **리월은 만렙에서 약4.4% 저렴**, 그 전에는 구매 요리보다 숙박이 저렴한 구간이 있다. 재료를 가진 경우 같은 메뉴의 제조비는56모라다. 몬드 음식6종만 비교해 리월 최적이라고 오인하지 않았다.

낮은 레벨의 희귀 재료형 메뉴는 예를 들어4인 반피에8인분/제조16모라로 회복할 수 있지만, 레시피와 희귀 재료를 이미 갖고 있다는 조건이다. 실제 신규 계정에 무료로 제공된다는 뜻이 아니다. Lv.1의4인 전원 부상에서는 쉬운 재료형 요리 제조비만으로 숙박을 넘는 사례도 남는다. 한 명만 부상하거나 미리 갖춘 희귀 재료형 메뉴, 현장 사용에서는 결과가 다르다.

## 실제 재고0 수급·제조·식사

Lv.55 4인, 처음 재료/음식0개, 지도12곳×32시드, 대표6종×3시드. 실제 LIFE_START/장면 입력/LIFE_FINISH와 조우 전투, 필요한 NPC구매·가공·제조·식사를 실행했다. 아래는 **4인에게 각1개씩 제공하는 준비**이며, 달걀·닭꼬치1회가 반드시 완전 회복을 뜻하지 않는다. 순수 숙박 왕복18초는 해당 초원/도시의 비교 모델이고 모든 지역에 일반화하지 않는다.

첫 레시피 구입·낚싯대는 일회성 비용으로 분리했다. 남은 재료/음식과 각각의 NPC 매각값을 기록했다. 식재료를 다시 사는 비용과 그 재료의 매각 포기값을 동시에 더하지 않는다. 예를 들어 감자 구매64모라를 실제 지출에 넣었다면, 사용한 감자의 매각값16모라를 또 더하지 않는다.

**재고0에서 당장 준비하면 요리가 시간상 우위가 아니다.** 평소 이동·임무 중 모은 재료를 미리 조리하고 현장에서 소비할 때 숙박 왕복을 줄인다. 준비시간은 완벽한 장면 입력과 행동당3초 입력, native 조우/연출을 사용하는 모델이다. 장면 제한시간까지 기다리는 민감도도 원자료에 있다. 게임 내 조리10~40분을 실제10~40분으로 계산하지 않았다.

## 반복 전투: 같은 6승, 같은 완전 회복 도시 종점

두 경로×Lv.10/30/55×불/물 돌파×숙박 전용/미리 요리+부족분 숙박=24조건이다. 시작 때만 완전 회복한다. 실제 HP·난수·레벨/날짜/재고를 이월하고, 누군가 사망하거나 HP50%미만이면 기존 회복 경로를 사용한다. 요리는 기본 해금 스튜+닭꼬치, 최대5개씩 실제 CRAFT.6승 뒤에는 실제 이동→숙박으로 모두 완전 회복한 같은 도시에서 종료해 최종 남은 HP 차이도 분리했다.

음식 전략의 숙박5회는 실제 재고 부족/동일 음식 교대 제한 때문이다. 이144승 캠페인에는 전투불능으로 인한 숙박은 발생하지 않았다. KO식사 거절과 숙박 전원 회복은 별도 경계 검사에서 확인했다.

## 파일과 재현

제품 변경은 `source/runtime_economy.js`, `source/app_cooking.js` 두 파일이다. 버전·릴리스 설명, 새 검사·감사 도구·증거·인수인계 문서는 함께 게시한다. 성장·숙박·전투·UI배치·원격 DB/이미지는 덮어쓰지 않는다.

```bash
node tests/test_food_lodging_v01617.cjs
node tools/audit_food_lodging_v01617.cjs --out docs/data/food_lodging_v01617_final.json
node tools/audit_food_supply_v01617.cjs --out docs/data/food_supply_v01617_final.json
node tools/audit_food_campaign_v01617.cjs --out docs/data/food_campaign_v01617_final.json
python tools/summarize_food_lodging_v01617.py
```

기준본은 부모 커밋`11b45a5ce8a870fdfc5be74b80aa41683201ed18`의 native runtime/index/package와 같은 QA DB를 보존한 별도 소스로 실행했다. 도구의 `--source-root`(메뉴/전투), `--runtime-root`(수급)로 기준 소스를 지정할 수 있다. 원자료 gzip은 JSON으로 완전히 복원되며 요약에 압축/원문SHA·byte수와 실제 로드 source/DB/도구 지문을 남겼다. 전체45종 추가 메뉴의 명단은 `food_lodging_v01617_all`의 `menus.ALL`에 있다.

전체45종 추가 메뉴 재현:

```bash
node - <<'NODE'
const fs=require('node:fs');
const a=require('./tools/audit_food_lodging_v01617.cjs');
a.MENUS.ALL=JSON.parse(fs.readFileSync('docs/data/food_supply_v01617_final.json')).foods.map(x=>x.food);
a.audit({out:'docs/data/food_lodging_v01617_all.json',levels:[1,10,30,50,60],routes:['ROUTE_TRAVELER'],regions:['MOND','LIYUE'],menus:['ALL'],extras:false});

```
