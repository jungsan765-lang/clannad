# 0.16.14 · #294 실패 수정

0.16.14 소스 `a19199f520e05ec4b46d4194e7472a6e4643995b`의 [#294](https://github.com/jungsan765-lang/clannad/actions/runs/37731445119)는 회귀156개 중154개 통과·2개 실패로 배포본 생성이 건너뛰어졌다. 앞서 보고한 관련 로컬12개 통과는 전체 배포 검증 통과를 뜻하지 않았다. 이번에는 실패한 두 파일을 직접 재현하고 수정했다.

## 실제 원인

0.16.13에서 자연스러운 한국어 임무명으로 바꿨지만, 예전 검사 두 곳은 거절 안내에 옛 임무명에 들어 있던 단어가 반드시 포함되길 기대했다. 게임은 미완료 임무를 정상적으로 차단했다. 실패는 돌파800/1,600이나 임무 집계 규칙 때문에 발생한 것이 아니다.

| 실패 파일 | 오래된 검사 | 실제 차단 안내 |
|---|---|---|
| `test_tasks_expanded_v0168.cjs` | 실제/수락/승리 중 하나를 찾음 | 몬드 순찰 · 제1차 (0/1) |
| `test_tasks_edge_v0168.cjs` | 실제/수락/요리 중 하나를 찾음 | 원정 음식 준비 · 제1차 (0/1) |

미완료 임무의 선택지 실행 검사에서 `ACTION_LOCK` 오류 코드·현재 임무명과 정확한 진행량·실행 전후 저장 불변을 모두 확인하게 했다. 이후 실제 활동·보고·재접속·중복 보상 차단 검사도 그대로 실행한다. 실패한 검사를 삭제하거나 게임의 행동 차단을 완화하지 않았다.

두 검사 파일의 가상 날짜는 월요일 KST정오로 고정했다. 기존 하루 경계 검사는 ‘주가 유지되는 날’을 전제했는데, 실제 일요일에 실행하면 월요일에 주간 집계도 초기화되는 것이 정상이다. 월요일 시작으로 해당 조건을 명확히 하고, 다른 일괄 보고 검사는 스스로 다음 월요일을 계산한다. 이는 재발 예방이며 이번 #294의 실제 두 실패 원인은 옛 이름 검사다.
