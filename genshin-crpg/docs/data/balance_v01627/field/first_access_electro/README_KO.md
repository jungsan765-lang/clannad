# 무상의 뇌전 첫 재료 획득 경로 재확인

> 추가 +6 검사: [몬드 장신구 보완 6건](minimum6_appendix/README_KO.md)에서 수메르 전용 제작인 치유사의 브로치를 첫 접근 증거에서 제외했다. 몬드 매의 눈 장식 +6 대체 편성은 2/3 승리. 아래 기존 +10 브로치 조건은 지급 준비에 대한 전투 가능성 검사이며 자연 몬드 첫 접근 보장이 아니다.

**리월 제작 방어구를 쓰지 않아도 Lv20 4성 명함 편성이 첫 토벌을 완료하는 경로를 확인했다.** 향릉·중운·바바라와 이세계인, 일반 제작 무기·철제 수호갑·회복 장신구 +10으로 seed 717/929/1237 모두 승리했다. 실제 기본 특성은 평타/E/Q **2**, 별자리는 모두 0이다. 캐릭터 소유권·제작/강화 재료·모라·지역 접근을 준비용으로 지급했으므로, 처음 시작한 계정의 자연 수급이나 모든 편성의 첫 토벌을 보장하는 결과는 아니다.

제품 코드 변경 없이 공개 입장·전투 입력과 실제 동료 AI로 현재 15건, genuine 0.16.26의 동일 준비 비교 9건을 기록했다. 현재 15건은 4승·11전멸, 옛 버전 9건은 1승·5전멸·엔진 STALEMATE 3건이다. 서로 다른 버전을 합쳐 현재 승률로 계산하지 않는다. 엔진 예외와 80회 입력 한도 도달은 모두 0건이다.

## 첫 토벌에 사용한 준비

- Lv20 이세계인 + 향릉·중운·바바라 명함. 해당 레벨 합법 돌파 1단계, 실제 기본 특성 2.
- 4인 모두 일반 제작 무기·`EQ_ARMOR_IRON_GUARD`·`EQ_ACC_HEALER_BROOCH` +10. 성유물, 전용/보스 장비, 음식, 뇌전 방어구, 보스 재료를 사용하지 않았다.
- 수호 진형 `DIAMOND`, 앞에서 향릉→중운→바바라→이세계인. 향릉·중운 공격 우선, 바바라 지원 우선.
- 주인공은 공개 프리즘을 우선 공격하고 핵 노출/위험 예고를 읽는 제한된 수동 정책. 동료 카드를 임의로 실행하거나 전투 중 HP를 재설정하지 않았다.
- 초기 회복 뒤 진형 HP 보정이 적용되어 실제 바바라 시작 HP는 최대의 약 95.24%, 나머지는 100%다. 실제 초기 배우 객체를 원시 자료에 보존했다.

| seed | 승패 | 라운드 | 전투불능 | 보상 전 합산 HP | 프리즘 재생 | 첫 재료 보상 |
|---:|---|---:|---:|---:|---:|---|
| 717 | 승리 | 22 | 0 | 72.64% | 2 | 뇌광 프리즘 3 |
| 929 | 승리 | 31 | 0 | 73.29% | 4 | 뇌광 프리즘 4 |
| 1237 | 승리 | 16 | 0 | 92.22% | 1 | 뇌광 프리즘 4, 기존 정수 1 |

이 표는 힐/방어 준비와 프리즘 대응을 포함한 가능한 경로다. 재생을 여러 번 허용하는 제한된 수동 정책이며 최적 사람 공략이나 특정 소요 시간을 입증하지 않는다. 현재 표준 Lv20 본체는 HP 16,800 / ATK 1,785 / DEF 210이다.

## 구 버전과 정말 같은 준비였는가

처음 측정한 옛 9건은 동료 순서가 현재와 달랐다. 그 자료를 `PRELIMINARY_DIFFERENT_ORDER`에 분리하고 비교에서 제외한 뒤, **현재와 정확히 같은 순서로 옛 9건을 다시 실행했다.** 초기 내부 공유에서 특성 4라고 부른 값도 원시 자료에 따라 실제 특성 2로 정정했다.

최종 9쌍은 작성 DB SHA, 장비 12개의 소유자/ID/강화/상한, 실제 특성 2, 별자리 0, 공개 진형 설정과 실제 순서, 동료 전술, 초기 아군 객체 전체(HP/ATK/DEF·버프·방패·traits 포함), 관리자 revision 0이 모두 일치한다. 수동 `choose` 함수 바이트도 같다. 선언 seed 717/929/1237과 공통 준비 함수의 초기 PRNG 설정은 동일하다. 원시 자료에 입장 직전 PRNG 상태를 별도로 저장하지 않았으므로 전투 중 난수 소비나 구·신 전체 저장 데이터까지 같다는 주장은 하지 않는다. 물리 수치·결과가 바뀌면 후속 난수 소비도 달라질 수 있다.

| 동일 준비 편성 | 옛 0.16.26 | 현재 | seed별 옛 결과 → 현재 결과 |
|---|---|---|---|
| 케이아·베넷·노엘 +6 | 0/3 승리 | 0/3 승리 | 717: 전멸 13R→10R, 929: STALEMATE 610R→전멸 12R, 1237: 전멸 33R→15R |
| 케이아·베넷·노엘 +10 | 0/3 승리 | 0/3 승리 | 717: 전멸 25R→15R, 929: STALEMATE 610R→전멸 16R, 1237: STALEMATE 610R→전멸 39R |
| 엠버·향릉·베넷 +10 | 1/3 승리 | 1/3 승리 | 717: 전멸 11R→승리 9R, 929: 전멸 11R→11R, 1237: 승리 9R→전멸 17R |

노엘 편성 실제 순서는 노엘→베넷→케이아→이세계인, 불 편성은 향릉→베넷→엠버→이세계인이다. 옛 본체 수치는 HP 16,000 / ATK 1,700 / DEF 210이었다. 옛 STALEMATE는 주인공 사망 뒤 노엘만 생존하며 재생을 반복하여 기존 자동 진행의 2,000 내부 단계 안전장치가 종료한 경우다. **전원 사망이나 80회 공개 입력 한도와 구분했다.** 이 검사는 옛 엔진의 해당 종료 경로를 발견한 자료이며 새 제품에서 같은 세 조건은 전멸로 정상 종료했다.

현재의 추가 향릉·베넷·노엘 +10도 3건 전멸(13/26/24R)이었다. 향릉·중운·바바라 편성은 3/3 승리였다. 따라서 어떤 준비든 쉽게 된다는 결론이나, 이번 변경만으로 실패가 새로 생겼다는 결론으로 넓히지 않는다.

## 제작 경로와 기존 192조건의 한계

[기존 필드 192조건 기록](../README.md)의 무상의 뇌전 준비에는 `EQ_LY_ARMOR_THUNDERWARD`가 있었다. 리월 제작 방어구에 의존한 그 기록만으로 **리월 진입 이전 첫 돌파 재료 획득**을 입증하면 안 된다. 이 보완 24건은 뇌전 방어구를 제외한 검사다. 향릉·중운 소유권은 지급했으므로 그 두 캐릭터를 자연스럽게 확보했다는 뜻도 아니다.

철제 수호갑은 기존 [공개 제작 영수증](../public_craft_receipts_after.json)의 `EQ_ARMOR_IRON_GUARD` 항목에서 몬드성 바그너 제작 성공을 확인했다. `REC_ARMOR_IRON`, 제작/착용 Lv5, 백철 4 + 정제 가죽 2 + 220모라, 공개 제작 120분이다. 보스 재료나 리월 제작 장소를 요구하지 않는다. 영수증도 재료와 모라·접근을 지급한 검사다. 전투 검사는 수호갑 소유/강화 준비를 지급하여 실제 `EQUIP`으로 장착했다. **+10까지 자연 채광·제작·강화 비용을 벌어온 전체 시간을 측정한 것은 아니다.**

## 소스와 원시 자료

구 버전은 `tests/test_enemy_balance_v01627.cjs`의 `loadBefore()`가 읽은 0.16.26 commit `7f33d2b34c48834c67c9134e2548d48932782e5c`, 작성 DB SHA `dcc2800000f20684e2c57420404aa3a3a7fe68b9042c608306ba2ec62bd178da`다. 수정 중인 현재 코드를 구 버전이라 부르지 않았다. 옛 fingerprint는 `b69a8b91e0d0df86e2e9adc4edf1ab0493e0ff26354c7a3e026b1884ae7b9159`다.

현재 5그룹은 실행 시점이 달라 전체 fingerprint 3종이다. 모두 필드 파일 SHA `6ce35466b5af8c222139a9ceb1544ffd140b0904177436dd198041fbd4b2c250`, 실제 보스 수치, 작성 DB SHA가 같다. 전체 소스가 하나의 동일 snapshot이라고 주장하지 않는다. 각 원래 header/options/fingerprint는 `source_headers.json`에 그대로 기록했다. 재실행은 최종 현재 소스를 사용하므로 전체 fingerprint가 달라질 수 있다.

- `summary.json`, `rows_24.json`: 현재 15건/구 버전 9건을 구분한 요약과 초기 배우·실제 특성·보상.
- `matched_preparation_9_pairs.json`: 9쌍의 준비 전체 비교와 수동 함수 SHA.
- `CURRENT/*/rows.json.gz`, `BEFORE_SAME_ORDER/*/rows.json.gz`: 실제 공개 입력, 로그, 피해/회복 계량, 장비, 결과가 들어 있는 전체 원시 자료.
- `source_headers.json`, `archive_manifest.json`: 원래 소스 증명과 압축 전후 SHA.
- `same_order_execution_ledger.json`: 최종 옛 9건 3실행 모두 exit 0. `execution_ledger.json`은 제외한 첫 비교의 이력이다.
- `PRELIMINARY_DIFFERENT_ORDER`: 순서가 달라 폐기한 옛 9건의 별도 보관. 24건 집계에 넣지 않았다.
- `runners/*`: 구 버전/현재의 원래 측정 runner. 전투 수치·적 처치·동료 카드·난수를 주입하지 않았다. 피해/회복/종료 메서드는 원래 함수를 그대로 호출하는 관측 wrapper로 계량했다. 준비 지급과 결과 관측을 구분한다.

현재 가능한 경로 재현 예시(저장소 루트에서):

```bash
FIELD_INPUT_ROOT="$PWD" node --max-old-space-size=640 --expose-gc \
  docs/data/balance_v01627/field/first_access_electro/runners/audit_electro_firstclear_original.cjs \
  --out /tmp/electro-firstclear-check --bosses FB_ELECTRO_HYPOSTASIS \
  --investments FOUR_C0 --policies MANUAL --seeds 717,929,1237 \
  --level 20 --enhance 10 --talent 10 --prepared yes --formation DIAMOND \
  --order LIYUE_XIANGLING,LIYUE_CHONGYUN,MOND_BARBARA,PLAYER_CUSTOM
```

요청 `--talent 10`은 제품 합법 상한으로 제한되어 실제 값 2가 기록된다. 구 버전 runner는 같은 인수와 `noelle_before.cjs`/`pyro_before.cjs`, 표의 정확한 `--order`를 사용한다. 자연 수급 검사는 별도 범위이며 이 문서는 현재 첫 토벌의 가능한 준비 및 구·신 실패 조건 비교만 확정한다.
