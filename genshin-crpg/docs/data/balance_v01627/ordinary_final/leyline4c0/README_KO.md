# 4성 명함 지맥 실전·실제 숙박 장부

**Lv60 4성 명함 편성이 최고 단계 지맥을 이용하고 실제 숙박까지 마치는 경로를 확인했다.** 기본 두 편성의 24건은 21건 승리·완전 회복, 3건 전멸이다. 전멸한 치유 편성도 같은 장비·특성·적·seed에서 기존 수호 진형·지원 역할·후열 배치·가드를 준비한 별도 3건은 모두 승리하고 숙박으로 완전히 회복했다. 힐 캐릭터만 넣고 Q/E를 반복하는 것과 기존 전투 설정을 준비하는 것의 차이를 원시 기록으로 남겼다. 제품 전투·보상·캐릭터·회복 수치는 변경하지 않았다.

## 실제 준비와 검사 범위

기본 24건은 Lv60 바람 여행자 명함 + 동료 3인 명함, 일반 제작 무기·강화 가죽 방어구·치유사의 브로치 모두 +6, 실제 기본 특성 6, 해당 레벨 합법 돌파 상태다. 성유물·전용/보스 장비·음식은 없다. 치유사의 브로치는 수메르 제작 장비이므로 이 표는 **Lv60 준비 계정**의 실험이며 초보 몬드 첫 돌파 접근 증거로 쓰지 않는다. 캐릭터 소유·장비/강화·성장 재료·지역/이야기 접근·초기 모라 100만을 준비용으로 지급했다. 소유나 제작 재료를 자연스럽게 모으는 시간은 제외했다.

- 기본 편성: 여행자·엠버·케이아·리사 / 여행자·케이아·행추·바바라.
- 기본 진형/전술은 실제 새 저장의 `DOUBLE_LINE`·균형. 주인공 Q→홀드 E→평타 우선, 실제 동료 AI를 사용했다.
- 각 편성 × 몬드/리월 × 부의 꽃/계시의 꽃 × seed717/4242/9031 = 24건. 각 조건은 독립 시험 저장이며 한 계정으로 한 시간에24회 보상을 받은 기록이 아니다.
- 적정 단계는 두 지역 공통 `tier5 / 적 Lv60`이다. 실제 단계 Lv 배열은 6/15/30/45/60이다.
- 꽃이 있는 지도에서 시작해 공개 `PLACE_ENTER`→`BOSS_ROUTE`→`COMBAT_BEGIN`/`COMBAT`을 실행했다. 초기 접근 이동은 제외했다.
- 전투 승리 후 HP/PRNG를 이어받아 실제 `MOVE` 복귀 전투와 숙박 `BUY`를 실행했다. native가 고른 숙박 시설에서 실제 완전 회복으로 끝났다. 지역·꽃 지도에 따라 선택된 숙박 시설은 다를 수 있다.
- 초기 회복 1회이며 전투 중 HP 재설정·적 처치·동료 카드·명중/난수 주입은 없다. 피해/회복/종료 관측은 원래 native 함수로 위임했다.

## 치유 편성 3전멸의 원인과 기존 공략 보완

현재 검사 시각의 리월 부의 꽃은 **층암거연 지상**이다. Lv60 유적 가디언 HP69,259 / ATK25,648 / DEF1,753 한 기와 척후병 HP23,800 / ATK15,680 / DEF1,249 두 명이 등장했다.

치유 편성은 주인공이 회전 강타로 2/3/3라운드에 쓰러진 뒤 14/11/11라운드에 전멸했다. 마지막 유적 가디언 HP는 6,491/18,451/14,622였다. 실제 회복량은 20,414/18,253/17,750, 빙결 반응 32/18/18회·확산 11회이며 명시적 면역 로그는 없었다. 전투가 중단되거나 보호막을 무시해서 생긴 native 예외는 발견되지 않았다.

같은 적·레벨·장비·seed의 엠버·케이아·리사는 과부하 10~13회·초전도 3~6회와 함께 3/5/3라운드에 승리했다. 치유 편성의 긴 처치 시간과 주인공 조기 사망이 패배에 연결됐다는 판단이다. 이 해석을 확인하기 위해 기존 공개 설정만 바꾼 별도 새 저장 3건을 측정했다.

- 수호 진형 `DIAMOND`, 앞에서 케이아→행추→바바라→주인공 후열.
- 케이아 공격 우선, 행추·바바라 지원 우선.
- 주인공 HP80% 미만이면 유한 가드 최대3회, 나머지는 원래 Q/E/평타. 귀환 전투는 원래 정책이다.

## 현금 효율과 시간당 제한

부의 꽃의 실제 지급은 **1회40,000모라**, 종류별 **현실 시간당1회**이며 몬드와 리월이 같은 보상 제한을 공유한다. 두 지역을 모두 돌아8만모라를 받는 모델이나 연속전투 속도로 시간당 수백만모라를 버는 모델은 사용할 수 없다.

기본24건의 성공한 부의 꽃9건 중 가장 느린 순 현금 환산은 **109.60초 / 순39,616모라 = 1만모라당27.67초**다. 공략 보완3건까지 포함하면 가장 보수적인 성공 조건은 **175.59초 / 순39,691모라 = 1만모라당44.24초**다. 실제 실패 확률·시간당 보상 대기·최초 이동·준비 수급을 포함한 장기 평균 수입은 아니다.

이 검사는 **꽃에서 출발→실제 완전 회복 숙박**까지다. 재료 비경에서 출발해 꽃에 다녀오고 재료 비경으로 복귀하는 별도 약267초 검사와 출발/종점을 섞어 그 보수적 현금 조달 비용을 낮추면 안 된다. 전체 육성 시간표에는 같은 출발/종점을 가진 더 긴 왕복 검사와 보상 제한을 우선 적용한다.

계시의 꽃은 최고 단계 **영웅 경험치책180권 = 계정 전체에 나눠 쓸180,000XP**와 직접 전투XP400을 참여자마다 지급한다. 경험치 비경의 **캐릭터마다24,000XP = 4인 합계96,000XP**와 단위를 구분해야 한다. 책18만을 4명 각각18만으로 계산하지 않는다. Lv60 준비 계정의 보상 검증이므로 이미 최고 레벨인 4명이 그 XP로 레벨이 오른다고 측정한 실험도 아니다. 계시의 꽃 역시 종류별 현실 시간당1회이며 반복 가능한 비경의 회당 속도와 제한을 함께 봐야 한다.

## 시간 모델·소스·원시 자료

2배속 표시 모델은 `H.observe/H.recover`의 실제 프레임 계량, 전투 입력당3초, 결과/재입장6초, 꽃 입장4초, 이동당4초, 실제 숙박 입력10초와 native 패배 대기다. CPU 실행 시간은 게임 이용 시간으로 쓰지 않았다. 최초 이동, 개인 반응 시간·네트워크 지연·재료/캐릭터 획득·시간당 제한 대기는 포함하지 않았다.

최종 fingerprint는 **`7147e88113388e51a3042d1d51c9bde3e084213502f976f52202012542f0dbe2`**다. 123입력 파일을 별도로 동결하고8건씩3batch를 순차 실행했다. 각 batch의 소스 전후 SHA가 같았으며 모두 exit0다. 관리자 수정은 revision0다. 전투 개시 저장과 종료 저장을 native 생성자로 다시 읽어 PRNG/실제 전투·현금·보상 제한을 확인했다. 실패·입력 한도·native 예외를 숨기지 않았다.

- `summary.json`: 기본24와 별도 공략3건, 원래 실패3건, 조건별 시간·HP·숙박·순 현금 장부.
- `batch_01.json.gz`~`batch_03.json.gz`: 기본24건 전체 초기/개시/종료 저장, 공개 입력·native 로그·피해/보상·숙박/귀환 결과.
- `manual_counter3/rows.json.gz`, `manual_counter3/summary.json`: 보완3건 및 원래3건과 같은 준비/적을 확인한 비교.
- `manifest.json`, `input_manifest.json`, `source_headers.json`: 압축 전후 SHA와 실제 동결 소스.
- `runner.cjs`: 저장소 `tools/audit_leyline_final_v01627.cjs`의 도구 사본. 저장소 루트의 도구를 사용하면 `node --max-old-space-size=640 --expose-gc tools/audit_leyline_final_v01627.cjs --root . --out /tmp/leyline4c0 --start 0 --count 8`처럼 실행한다. 다음 batch는 start8/16이다.
- `runner_original_batches_01_02.cjs`: 초기 두 batch의 정확한 runner. 최종 버전은 결과 장부에 패배 시 실제 모라 차감을 관측하는 필드만 추가했다. 전투 동작은 동일하다.
