# 0.16.20 음식 실제 식사 전후 증거

동일한 45개 기존 회복 음식으로 변경 전 0.16.19와 확정된 0.16.20에서 각각 2,856회 식사를 실행했다. 39종의 기초 회복량을 높였고 6종은 유지했다. 같은 대상·레벨·장비·최대 HP·시작 HP의 요청량과 실제 회복량을 1:1로 연결했으며 HP와 장비 자체는 전후 완전히 같다. 이 폴더를 마무리하면서 제품 소스와 테스트를 수정하거나 완료된 실행을 재실행하지 않았다.

## 비교 결과

| HP 1 출발, 45종 × 7레벨 × 4명 × 2장비 | 2,520회 | 2,520회 | 2,184쌍의 요청/실제 회복 증가, 336쌍 유지 |

| 25% 손실 측정의 부족 HP 상한 적용 | 163회 | 272회 | 이전부터 상한이던 163쌍은 실제 회복 동일 |

원자료의 `requestedHealing`은 대상의 성장 배율을 적용한 회복 요청량이고 `healed`는 생명의 계약 흡수 및 부족 HP 상한을 적용한 실제 회복량이다. 25% 손실 측정에서 더 좋은 음식도 실제 회복이 같을 수 있다. 이것을 음식 기초값이 동일하거나 밸런스 변경이 실패했다는 근거로 쓰지 않는다. 전체 비교 CSV는 두 값을 별도 열로 보존한다.

Lv.60, 장비 없는 여행자, 최대 HP 18,383, 시작 HP 1의 실제 요청/회복은 다음과 같다. 이 조건에서는 모든 값이 부족 HP 상한 아래다.

|---|---:|---:|
| 장원 팬케이크 | 170→240 | 5,209→7,353 |
| 생선 볶음면 | 170→360 | 5,209→11,030 |
| 꽃게알 두부 | 170→280 | 5,209→8,579 |

기초값 전체 범위는 90~270에서 90~440으로 바뀐다. 유지한 6종은 달걀 프라이90, 닭고기 스튜180, 스테이크110, 침옥 차 이슬90, 현재 공급불가 글루포프 호밀빵200·베리 아이스크림200이다. 카탈로그 45개 항목의 기존 조리비·재료·시간·해금은 모두 같다. 품목 행에서는 회복[8]과 이에 의존한 구매가/매각 상한[14/15]의 허용된 숫자만 달라졌다. 108개 조리법 및 실제 수급은 인접 `../recipes/` 증거로 확인한다.

## 조건과 네이티브 경로

Lv.5/10/20/30/40/50/60, 여행자·엠버·진·종려, 장비 없음/해당 레벨에 허용된 실제 장비의 두 조건이다. 장비는 Lv.30 미만 +3, 이후 +6이며 아이템 최소 레벨을 지켰다. 실제 장비 ID·강화값·희귀도·돌파·최대 HP는 원자료 `hp[]`와 `CONDITIONS.json`에 남아 있다. HP 손실·보유 캐릭터·레벨·음식1개 지급은 효과 검사용 합성 설정이다.

`USE_ITEM` 및 `MEAL_BATCH`를 실제 런타임에서 실행했다. 회복 함수나 런타임 메서드를 대체하지 않았다. 요청량은 대상 자신의 `foodHealingAmount`와 같고, 격자 측정의 실제 회복은 `min(요청량, 최대HP−시작HP)`이며, 최종 HP는 시작 HP+실제 회복이다. 식사마다 음식1개 차감과 10게임분 영수증을 검사했다. 같은 콘텐츠 DB SHA와 같은 고정 감사 시계를 사용했다.

이 측정은 음식 효과를 확인한다. 재료 획득·가공·사냥·낚시·NPC·시장 효율, 왕복 또는 캠페인 실시간을 무료라고 간주하거나 측정했다고 주장하지 않는다. 그것은 인접 수급/조리/경제 증거의 범위다.

## 경계와 회귀

- KO 대상에게 달걀 프라이·스테이크·모라육·꽃게알 야채찜: `TARGET_DOWN`, 저장/재고/시간 불변.
- 같은 회복 음식 바로 연속 사용: `MEAL_REPEAT`, 저장 불변. 감자전으로 교대하면 원래 닭고기 스튜를 다시 먹을 수 있다. 교대용 감자전의 실제 회복만 1,070→1,653이며 다시 먹는 스튜는875로 동일하다.
- 실제 전투를 시작한 뒤 식사: `ACTION_LOCK`, 저장 불변.
- 바바라 특제: 스튜 기초180×1.1을 대상 성장에 한 번 적용해6,066 요청/회복, 특제1개 소비. 이 기초값은 전후 유지했다. 신규 회귀는 바뀐 채식 전복360→특제396과 잔여 lot/저장 재로드도 검사한다.
- 생명의 계약100: 스튜 요청5,515 중100을 먼저 흡수해 실제5,415 회복. 신규 회귀는 바뀐 농어440으로 계약100과 부족 HP7 상한을 함께 검사한다.
- 버프 음식: 식사 회복0, 다음 전투에서 `STATUS_FOOD_ATK` 및 `rounds:null`, 예약 효과 소비 확인. 회복 음식의 지속 회복으로 계산하지 않는다.
- 혼합 레벨5/10/30/60의4명 일괄 식사: 각자 요청279/420/1,719/6,866, 음식4개 소비와 한 행동10분. 신규 회귀는 바뀐 농어440으로 각 대상 계산을 다시 검사한다.

`new_test_v01620_complete.log`는 이미 완료된 `tests/test_food_balance_v01620.cjs`의 원문이며14/14통과다. 원문 DB/공용객체 불변, 복제 런타임 독립성, 재설치 멱등성, 기존 구매·매각 상한, 과거 결제/식사 영수증 재시도, 바바라 특제, KO/전투/연속/잘못된 대상의 원자성, 조리비·재료·출력, 가방/요리/나선 숫자 권위를 포함한다. 이 포장 작업에서는 테스트를 반복하지 않았다.

## 파일과 출처

- `before_native_effects.json.gz` / `after_native_effects.json.gz`: 각2,856격자 식사, 실제 영수증, HP14조건과 경계11개를 담은 JSON 원문 바이트.

- `native_comparison.json`, `CONDITIONS.json`: 기계 판독 비교·조건·경계 원문 쌍과 제품/테스트 해시.
- `before_native_effects.csv.gz`, `before_original_MANIFEST.json`, `before_original_AUTHORITY_AND_FINDINGS_KO.md.gz`: 최초 변경 전 실행의 원문 보존. 최초 조사 문서는 당시 권고/설명 기록이며 현재 판정은 이 README와 비교 JSON을 따른다.
- `original_audit_native_food_v01619.cjs.txt.gz`: 최초 실행 스크립트 원문. 압축 해제 SHA `1ff0c4e472d21389d9665f50ae7dcb62539aa5c3cc9f3f9550eb5424388cd8e3`.
- `audit_native_food_v01620.cjs`: 저장 위치와 `--source-root`/`--out`을 사용할 수 있도록 이식한 실행기. SHA `728167ec340906c9478fe3761656f2aadb4e90f56f3a5bcf45a3a0ef55896b31`. 변경 후 원자료의 `runnerSha256`과 일치한다. 원본과 이식본 해시는 서로 다른 항목으로 기록한다.
- `after_native_run.log`: 완료된2,856식사/11경계 실행 로그. 신규14검사 로그도 원문 그대로 별도 보존했다.

이식본의 파일 경로/이름/runner 해시 기록은 최초 실행기와 다르지만 같은 실제 식사 격자와 경계 방법을 사용한다. 변경 전 원자료의 `sourceRoot`는 당시 사용한 작업 경로의 역사 기록이다. 그 경로의 현재 파일을 변경 전 권위로 취급하지 않고 원자료의 각 loaded source SHA와 복원본을 대조했다. 변경 전후 각118개 로드 소스의 해시를 모두 검증했다. 변경 전233개 제품 파일은 별도 보존한235파일 복원본(소스/DB와 package2개)에 모두 일치하고, 변경 후233개는 확정 제품에 모두 일치한다.

`MANIFEST.json`은 모든 저장 파일의 SHA와, `.gz` 파일의 압축 해제 후 바이트 수/SHA도 기록한다. gzip은 원문을 재직렬화하지 않았다. 변경 전/후 원자료 SHA는 각각 `423164c610ba990820072ea553d86622163dde885000c36036eb17f93bd705d5` / `f7eccaa0eeb69b10ff76916bf5fc1a81c9aa35f38e5d3328c67956cce0633f2f`다.

## 재현

저장소 루트에서 새 출력 폴더로만 실행한다. 확정 제품을 변경하거나 과거 저장을 덮어쓰지 않는다.

```bash
python3 docs/data/food_balance_v01620/restore_baseline.py --out /tmp/food-v01620-before-restored
node docs/data/food_balance_v01620/native/audit_native_food_v01620.cjs --source-root /tmp/food-v01620-before-restored --out /tmp/food-v01620-before-recheck
node docs/data/food_balance_v01620/native/audit_native_food_v01620.cjs --source-root . --out /tmp/food-v01620-after-recheck
node tests/test_food_balance_v01620.cjs
```

재실행 원자료는 새 실행기의 provenance(경로/runner 해시)를 포함하므로 최초 원자료와 파일 전체 SHA까지 같아야 한다고 판정하지 않는다. 제품 개별 SHA, 대응 조건/HP/요청/실제/영수증/경계의 값을 비교한다. 운영 설치·main 병합·운영 승격은 이 증거의 범위에 포함하지 않는다.
