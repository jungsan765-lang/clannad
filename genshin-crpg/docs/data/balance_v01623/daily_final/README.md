# 최종 일일 보스 8조건 공개 입장 검증

타르탈리아 대상 수정은 실제 전투에서 확인됐다. **다만 공략이 필수인 일일 보스 난도를 달성했다고 판단할 수는 없다.** 종려·다이루크·진 명함 조합은 타르탈리아 4라운드 후 HP 100%, 야타용왕 4라운드 후 HP 98.587%였으며 보스별 전용 공략을 선택하지 않은 기본 정책으로도 모두 승리했다.

## 실행과 최종 카탈로그 변경

부모와 담당 에이전트의 source freeze 확인 후 전체 source 233개, authored content/db.json, setup/observe helper를 독립 `daily_targeting_final_input`에 복제했다. 총 235개 복제 전후 및 native 실행 직후 snapshot/product SHA는 drift 0이었다. 실제 로딩 123개도 실행 전후 drift 0이다. 이 에이전트는 제품 source와 기존 원장을 수정하지 않았다.

**native 완료 이후** 운영 도구 카탈로그에서 지원되지 않는 damage 조절 항목 7개가 제거됐다. XIANYUN_Q 회복 조절은 유지됐다. 담당자의 확인상 실행 규칙/값은 바뀌지 않았으므로 8조건을 중복 실행하지 않았다. 이 원장은 자체 동결 입력을 검증하며, 이후 최종 제품의 전체 해시가 동일하다고 주장하지 않는다. 실제 차이는 runtime_balance_admin_v01623.js 한 파일이며 `post_native_catalog_delta.json`에 기록했다.

## 조건과 한계

- 공식 `adminBalance.createRuntime`을 사용했다. 8조건 모두 profile revision 0이고 config는 공식 `emptyConfig()`와 일치한다. 신규 전투의 adminBalanceRevision은 0이다. 타르탈리아의 신규 일일 전투 두 조건만 dailyTargetingRevision 1이다.
- **HP 후보 A는 제외했다.** runtime_growth_v01522.js, authored content/db.json, helper SHA는 기존 daily8와 정확히 같다. 생성 서버 DB를 별도로 대조한 검증은 아니다.
- 기존 daily8 대비 실제 로딩 입력 차이는 index.html, 새 runtime_balance_admin_v01623.js, runtime_liyue_combat.js, runtime_field_bosses.js 네 경로다. 필드 코드는 behaviorRevision 4 반복 공략 창을 포함한다. 따라서 대상 수정 하나만 적용한 빌드라고 표현하지 않는다. 이번 네 일일 보스의 초기 적/아군 주요 스탯은 모두 동일하고, 타르탈리아 외 6조건 결과와 피격분포도 같다.
- seed 717. 보스 고정 레벨 25/28/50/60과 같은 레벨의 4인 편성. 주인공은 여행자 C0이며, 4성 동료는 실제 공개 CONSTELLATION_UNLOCK 6번씩 수행했다. 5성 동료는 C0다. 기본 특성은 현재 돌파 단계의 법정 상한이다.
- 기본 제작 무기·방어구·회복 브로치의 실제 강화는 모두 +10, cap 10이다. 성유물/전용 무기/보스 요구 장비/음식은 사용하지 않았다. 이전 baseline 문서의 브로치 +0 설명과 실제 입력이 달랐으므로 이번 비교는 **실제 양쪽 +10 상태**를 따른다. 기존 봉인 문서는 수정하지 않았다.
- 소유 캐릭터/돌파/특성/진단 자금/제작품/STELLA, 선행 스토리와 첫 보스 클리어 flag는 준비 fixture다. 자연 계정의 준비 파밍·선행 획득을 처음부터 완주한 기록이 아니다. 야타의 선행 클리어 flag도 명시적으로 설정돼 있다.
- 공개 MOND_MATERIAL_CHALLENGE / LIYUE_ARTIFACT_CHALLENGE 입장과 native 실제 KST 일일 입장 소비를 유지했다. 8개는 독립 save다. 공개 COMBAT_BEGIN / COMBAT, 풍경로 우선 → 여행자 Q → E HOLD → 기본 공격과 동료 balanced AI 정책을 썼다. 보스별 최적 수동 공략이나 직접 damage/동료 private 실행은 하지 않았다.
- 시작 전 HP를 한 번 채웠고 전투 중 HP 리셋/숙박/음식은 없다. native 세 번째 편성 슬롯의 전투 maxHP +5% 때문에 생기는 시작 HP 공백도 회복 합계에 포함된다. 이 공백을 장비 조건부 효과나 받은 피해로 해석하지 않는다.
- 각 조건 최대 40개 플레이어 입력/확인 경계. 환산 시간은 native 2배속 연출 + COMBAT 입력 3초씩 + 결과/재입장 6초다. 네트워크·사람 반응·준비 파밍·이동 시간은 포함하지 않는다.

## 실제 대상 차이

- 4성 풀돌 타르탈리아: 보스 피해 패킷 대상(반응 틱 포함)은 여행자 3/향릉 2 → 여행자 2/향릉 3. FOUL_LEGACY_WAVE 순서가 실제 선택 대상을 따른다. 4라운드 승리와 시간은 같지만 종료 여행자 HP는 8,315/12,690 → 6,563/12,690, 향릉 HP는 8,576/13,889 → 10,104/13,889로 재분배됐다.
- 5성 명함 타르탈리아: 여행자 5/종려 7 → 여행자 3/종려 7/다이루크 1. 2라운드 ELECTRO_ARC가 후열 다이루크를 실제로 선택했고 1,134 피해가 보호막에 흡수됐다. 반응 틱도 달라져 총 패킷은 12 → 11이다. 진은 이 단일 seed에서 선택되지 않았다. 후열 전원이 항상 맞는다는 증거가 아니다.
- 위 조건에서 진 실제 회복 합계는 양쪽 모두 2,083이다. 여행자의 실제 상처 1,043와 다이루크 편성 슬롯 HP 공백 1,040을 채운 양이다. 결과 HP 100%와 낮은 전투 시간은 유지됐다.
- 상세 카드별 흡수/HP 감소/순서는 targeting_comparison.json에 있다. 대상/MAX 제한을 바로잡은 회귀 확인이며 일일 보스 전체 난도 목표의 완료 증거가 아니다.

## 주변 비용과 남은 판단

8조건의 실제 XP/모라/아이템/성유물 결과는 기존과 같고 입장 소비도 유지됐다. 대상 재분배로 회복 비용은 달라질 수 있다. 종료 HP를 기존 숙박 공식에 대입하면 4성 풀돌 타르탈리아의 몬드 요율 견적은 166 → 172모라, 리월 요율은 208 → 215모라다. 실제 숙박 구매·접근·이동 전투를 추가 실행하지 않은 **공식 대입 비교**다. 5성 명함은 양쪽 모두 HP 100%라 회복 비용 성분 0이다. 객실 기본료만 있는 견적과 숙박을 하지 않아도 되는 결과를 구분한다. 음식·식재료·돌파 요구량·드롭·강화 비용을 이번에 바꾸지 않았다.

같은 수준 일일 보스 수급 가능성은 이 준비 편성에서 확인했지만 공략을 해야 깨는 목표와 다르다. 5성 C1/C2/C6 투자 차이, 여러 seed 승률, 모든 편성, 자연 획득 순서, 조작 재미는 측정하지 않았다. 종별 고정 레벨 차이가 있어 Lv30 필드 결과와 섞어 정밀 동레벨 난도 비율을 주장하지 않는다. 후보 A HP 증폭은 거절됐고 이 코드와 원장에 포함하지 않았다.

## 검증기 정정과 파일

최초 시도는 검사기가 공식 emptyConfig의 중첩 빈 growth 객체를 변경값으로 오인해 8건 모두 **전투 전 FIXTURE 오류**로 중단됐다. 최초 실행기/profile/원장/입력/결과는 sibling daily_targeting_final_identity_fixture_attempt에 보존했다. 승패에 포함하지 않았다. 검사기의 검사식만 공식 emptyConfig 전체 구조 비교로 정정했고 product/snapshot source는 수정하지 않았다.

- native.json.gz: 8개 실제 원장과 공개 카드/단계 경계
- summary.json: 결과, operator profile, 태그, 입장 소비
- targeting_comparison.json: 기존/최종 초기 스탯과 카드별 실제 피해 패킷
- economy_and_equipment_comparison.json: 보상 차이 0, 종료 HP/장비, 숙박 공식 비교
- full_source_*: 235개 snapshot/product 실행 전후 SHA
- inputs_before.json / inputs_after.json / final_hash_verification.json / snapshot_provenance.json: 실제 로딩 123개, 전체 입력 및 baseline 동일 증거
- post_native_catalog_delta.json: 실행 완료 이후 최종 제품 카탈로그의 별도 SHA 변화
- 실행기/추출기 원문과 로그를 포함했다. MANIFEST.json은 자기 자신을 제외한 이 폴더 파일 SHA다. 재현 시 실행기의 --root에 동결 입력을 지정하고 --out은 새 폴더로 지정해야 한다.
