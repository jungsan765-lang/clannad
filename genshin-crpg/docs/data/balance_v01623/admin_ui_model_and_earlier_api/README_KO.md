# 운영자 밸런스 화면 검증

실제 `source/admin.js`와 `source/admin.css`를 Chromium에서 실행한 화면·조작 검사다. 게임 화면 소스는 바꾸지 않았다. `RESULT.json`의 30개 검사가 모두 통과했고 브라우저 예외는 0개다.

- 실제 네이티브 카탈로그와 `adminBalance.validateConfig`를 사용했다. 검색·숫자 입력·항목/탭 이동 뒤 초안 유지·미리보기·적용·적용 대기 중 수정 보존·409 충돌 후 초안 재반영·JSON 가져오기·8마리 제한·복구 전후 비교·비경 재료 보상 설정/삭제를 검사했다.
- 390×844 휴대폰에서도 검색→편집→미리보기→적용 및 이력 복구를 실제 버튼으로 실행했다. 가로 페이지 넘침은 없고 숫자 입력은 한 열이다.
- API 응답과 이력 저장은 로컬 HTTP 검사용 모델이다. 이 검사는 실제 운영 서버 설치나 SQLite 영속성의 증거가 아니다. 실제 서버의 권한·원자적 저장·전투별 버전 유지 검사는 서버 담당의 별도 원장으로 확인해야 한다.
- QA 컴퓨터에 한글 글꼴이 없어 캡처 페이지에만 Noto Sans KR을 적재했다. 제품의 기존 시스템 글꼴과 패키지 의존성은 바꾸지 않았다. Chromium과 글꼴 패키지는 QA 임시 경로에만 설치했다.
- `desktop.png`, `phone.png`, `phone_preview.png`는 실제 브라우저 캡처다. 적의 빈 칸 아래는 고정 최종 HP처럼 읽히지 않게 **기준 Lv.의 수치**로 표시한다. 빈 칸의 실제 수치는 전투 레벨·기존 규칙을 따른다.

`RESULT.json`에 제품 소스 SHA256와 네이티브 입력 지문, API 요청을 기록했다. 검사용 77개 보상·5,000 HP 등의 숫자는 이력 모델 안에서만 사용했고 제품 기본값이나 공개 설정에 적용하지 않았다.

## 별도 네이티브 API 검사

`NATIVE_RESULT.json`은 실제 운영자 API와 `:memory:` SQLite를 연결한 추가 브라우저13검사다. 이 앞선 원장은 0.16.22 generated 엔진에 당시의 현재 밸런스 모듈을 명시적으로 한 번 적재한 조건이다. 제품 0.16.23 최종 빌드의 검사와 혼동하지 않는다. 최종 빌드는 옆 `admin-ui-final-native/`의 별도 결과를 본다.
