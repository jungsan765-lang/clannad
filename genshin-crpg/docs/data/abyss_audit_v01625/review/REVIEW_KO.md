# 0.16.25 나선비경 독립 검토

이 문서는 결과를 과장하지 않도록 실행기·음식 상태·준비 fixture·게시 입력의 연결을 별도로 읽은 검토다. 제품 소스와 native 실행기는 수정하지 않았다. 기준 게시 커밋은 `46190377b713e6218e66b26bc4292f18fb5a348d`, 검사 런타임 지문은 `aeb110f1cb71c11b2d515e71c1a8f24189463d09eb26fd9959afe10b576aadd1`이다. 최종 승패 표는 native 담당자의 최종 원장을 따른다.

## 확인한 사실

|항목|판정과 해석|
|---|---|
|실제 공개 전투|실행기는 `ABYSS_ENTER`, `COMBAT_BEGIN`, `COMBAT`, `USE_ITEM`, `EQUIP`, 진형·동료 방침 행동을 사용한다. 적 수치나 전투 피해를 임의 배율로 덮는 모의 전투가 아니다. 주인공 1명과 실제 동료 AI 3명이다.|
|준비 지급|Lv60·돌파6·특성10·캐릭터 보유·장비 보유·강화/돌파·이전 층 기록·음식은 진단 지급이다. 전투 능력의 조건부 비교는 가능하지만 그 준비를 계정이 실제로 획득하는 시간·모라·뽑기 비용을 측정한 자료가 아니다.|
|성유물|직접 능력치를 만든 성유물이 아니라 실제 `rollArtifact`가 낸 첫 통과 개체를 사용한다. 그러나 최대 4,000회 탐색과 +5 직접 지급은 자연 수급을 생략했다. 첫 통과 개체도 능력치가 임계값에 정확히 붙은 최저 개체를 뜻하지 않는다.|
|전용 무기|`EXCLUSIVE`는 동료 3명의 전용 무기를 지급하는 조건이다. 5성 명함의 보유 조건과 전용 무기 획득·+12 비용은 서로 다르다. `CRAFT`와 분리해서 읽어야 한다.|
|방 사이 상태|HP를 임의 완치하지 않고 기존 정산과 식사로 다음 방에 간다. 첫 입장 전에만 전원을 최대 저장 HP로 맞춘다. `room.before`는 식사 전, `initialActors`는 식사·전투 슬롯 보정 후, `room.after`는 전투 정산 후 저장 HP다.|
|방어 반복 정책|`GUARD` 성공은 주인공이 방어를 반복하고 동료 AI가 공격·치유·보호막을 처리한 성공이다. 이를 세밀한 주인공 수동 공략이 필수인 난도라고 부르면 안 된다.|
|준비 부족 실패|12층에서 종려·진·불 동료 또는 장비 조건을 못 맞춘 실패는 피해 면역 조건의 실패다. 적이 강해서 졌다는 실패와 분리한다. 다른 5성 명함/4성 풀돌 조합의 전투력 비교 표본으로 쓸 수 없다.|
|시즌 전체|층별 fixture는 이전 층 클리어 기록을 지급한다. 동료의 층별 각인과 전체 시즌 인원 확보를 자연 진행으로 검사한 자료가 아니다.|

## 다섯 음식이 실제로 작동하는가

[공개 행동 probe](effect_probe.cjs)와 [실측 원장](effect_probe.json)에서 정상 `USE_ITEM`을 거쳐 전투를 시작했다. 다섯 효과가 모두 실제 초기 전투 상태에 들어가고 다음 전투 대기 목록에서 소비되는 것을 확인했다.

|음식|실제 상태|수치|
|---|---|---|
|선도장|`STATUS_FOOD_FEAST`|ATK +12%, 치명타 확률 +5%p|
|비옥야채쌈|`STATUS_FOOD_ATK`|ATK +8%|
|만족 샐러드|`STATUS_FOOD_CRIT`|치명타 확률 +5%p|
|어부 토스트|`STATUS_FOOD_DEF`|DEF +8%|
|크림 스튜|`STATUS_FOOD_SPEED`|SPD +4|

ATK 두 효과는 순차 곱이라 실제 합계는 **+20.96%**, 치명타 확률은 **+10%p**다. DEF는 레벨별 방어 환산을 적용한 뒤에도 같은 음식 없는 값보다 8% 높았다. 같은 ATK 음식을 다시 먹으면 음식을 추가 소비하지만 상태는 한 개로 대체되어 두 배로 늘지 않는다. 서로 다른 위 다섯 상태가 중첩하는 현상과 동일 상태 음식의 교체를 구분해야 한다.

4인 × 3방이면 다섯 음식은 총 60개다. 모두 방마다 실제 소비되는 조건이며, 단순히 ‘음식 조금 준비’한 상황으로 설명해서는 안 된다. 회복 음식은 이 60개와 별도다. 음식의 `rounds:null`은 해당 전투에서의 유지이며, 다음 방에 무료로 다시 적용된다는 의미가 아니다.

## 결과를 읽을 때 반드시 나눌 것

1. `CLEARED`와 전원 무KO 클리어를 나눈다. native.actor가 HP0인데 정산 후 저장 HP가 양수인 조건이 실제 원장에 있다. `finalKo:[]`만 보고 무KO로 읽지 않는다. `rooms[].ko`, `nativeDownedPersistentRevived`, 최종 native.actor HP를 함께 본다.
2. `TIMEOUT`은 생존 실패와 다르다. 12층의 높은 잔여 HP와 시간 초과가 함께 나오는 조건은 보호막·치유 생존과 화력/치명타 조건이 별개임을 보여준다.
3. 세 개 시드의 승패는 해당 편성·장비·정책에 관한 표본이다. 모든 5성 명함의 일반적인 승률로 바꾸지 않는다.
4. 같은 초기 시드라도 음식이 동료 기술 선택·행동 순서·난수 소비를 바꾸므로 결과가 매 조건에서 단조롭게 좋아질 필요는 없다. 특정 음식 하나가 항상 승리의 원인이라고 주장하려면 추가 분리 검사가 필요하다.
5. 다른 캐릭터 편성은 성유물 통과 조건과 탐색 경로도 다르다. 서로 다른 편성의 승패만으로 희귀도·캐릭터 한 명의 순수 효과를 계산하지 않는다.
6. +12 장비를 빼자 면역이 생기는 결과와, 조건을 통과한 제작 무기/전용 무기의 실제 화력 차이를 나눈다. 전자는 설계된 통과 조건이고 후자가 전투 준비 효율이다.

검토 도중 의약품은 처음에는 보유만 지급했지만, 최신 실행기는 전투 아이템 카드 선택과 `COMBAT` 전후 실제 소모량 수집을 추가했다. 최신 `counter_preparation`에서 MEDKIT/POTION의 실제 소비가 기록된다. 초기 probe를 의약품 사용 실험으로 합산하면 안 된다.

## 게시 DB와 QA DB의 연결

처음에는 원문 SHA가 달라 관련 행의 동등성 근거가 누락됐을 가능성을 점검했다. 이후 [현재 입력 확인](../inputs/input_provenance.json)과 기존 `docs/data/qa_v01619/db_runtime_semantic_parity_v01619.json`의 연결을 확인했다.

- 현 QA DB 원문 SHA256: `254c9294c7787b421f38c84b3ad8fed9f00c207a8ef74855868c0cda48dc0962`.
- 기존 게시 authored DB Git blob: `cc3996929c885d41289038ff501640039a4cc71e`. 0.16.25 보호된 DB도 이 값이다.
- 기존 게시 서버 DB와의 **64개 런타임 표 동일성** 자료가 있고, 현재 QA의 64개 표 해시가 모두 그 자료와 다시 일치한다. 캐릭터·기술·장비·음식·재료 표도 포함한다.
- 게시 원장은 해당 DB를 바꾸지 않고 비선택 파일 9,741개를 보존한 사실을 기록한다.

따라서 원문 SHA 차이만으로 전투 행이 다른 DB라고 추정하는 우려는 해소됐다. 이번에 운영 서버 계정에서 플레이하거나 새 원격 원문을 다운로드한 검사는 아니다. 기존 게시 원문/서버 표 증거와 현재 동일 표·동일 보호 blob을 연결한 검사다. 운영 DB를 QA 원문으로 덮어써서는 안 된다.

## 최종 해석에 권하는 표현

현재 확인은 ‘좋은 장비·여러 음식이 실제 효과를 내고 특정 준비된 편성의 클리어를 바꾼다’까지는 뒷받침한다. 하지만 종려·진을 강제로 요구하는 면역 조건, 주인공 KO 이후의 방 진행, 준비 획득과 시즌 인원 확보를 생략한 fixture 때문에 **‘다양한 완성 편성으로 즐길 수 있는 최종 콘텐츠 밸런스가 완성됐다’는 결론은 뒷받침하지 않는다.**

구체적인 전투 버그와 기존 설계 조건은 별도로 보고, 최신 사용자가 요청한 읽기 전용 검사에 새 제품 수정이나 추가 너프를 섞지 않는다. 특히 일부 보스에 강한 특정 조합을 확인한 사실을 모든 5성 명함의 과도한 성능으로 확장하지 않는다.
