# 0.16.25 나선비경 규칙·준비 조건 읽기 감사

기준 게시 소스는 `46190377b713e6218e66b26bc4292f18fb5a348d`다. 제품 코드·DB·UI·수치는 변경하지 않았다. 소스 조립과 QA DB의 fingerprint는 `aeb110f1cb71c11b2d515e71c1a8f24189463d09eb26fd9959afe10b576aadd1`이며 0.16.25 최종2 검사와 같다. 모든 로드된 런타임·로드 순서·관련 표시·QA helper·DB 입력 해시는 [mechanics.json](mechanics.json)에 저장했고 실행 전후 입력 변경은 0개다.

**장비·요리·기믹 준비를 요구하는 조건은 실제 존재한다. 다만 특정 캐릭터·아이템을 소유하지 않으면 공격을 아예 막는 규칙과, 준비가 부족해서 실제 화력·생존력이 모자라는 난도는 구별해야 한다.** 현재 12층은 종려·진이 없는 완성 편성을 인정하지 않는다. 따라서 단순히 “5성 명함도 장비를 준비해야 하므로 최종 밸런스는 적절하다”로 결론낼 수 없다.

이 파일은 규칙과 좁은 관찰 계약만 맡는다. 최신 실제 전투 결과는 동료 담당의 `../native/`에서 확인한다. 아래 강제 승리 정산·상태 변형은 분기 검사용이며 실제 플레이 승률이나 실제 전투 승리로 세지 않는다.

## 생존·아이템·연전

- 현재 나선에는 별 개수나 실제 초 단위 시간 평가가 없다. 방마다 **10~15라운드** 제한이 있고 세 방을 모두 이겨야 그 층 정복이다. 적을 못 잡고 치유로 버티기만 하면 살아 있는 파티도 `TIMEOUT`이다. 마지막 허용 라운드 END 피해까지 포함하며 다음 라운드 START 효과는 받지 않는다.
- HP와 `PERSISTENT` 상태만 방 사이에 이어진다. 보호막·장판·일반 전투 상태·재사용 대기 시간은 새 전투에서 초기화된다. 보상 경험치는 0이라 방 승리 레벨업에 의한 자동 완치는 없다.
- 방 사이 자동 완치는 없다. 음식은 보유 수량을 실제 소비하고 회복·다음 전투 효과를 적용한다. 같은 회복 음식만 연속으로 먹을 수 없으며, “한 사람당 하나”는 **한 번의 식사 요청** 제한이다. 다른 회복 음식을 번갈아 여러 번 먹는 것은 재고가 있는 한 가능하다. 한 방에 하나만 먹을 수 있는 제한으로 계산하면 안 된다.
- 음식은 전투 중 사용할 수 없다. 전투 치료품은 주인공 행동을 소비하며 회복 물약은 본인 최대 HP 기본 20%, 응급 붕대는 살아 있는 아군 기본 15%, 여행자 응급치료 세트는 기본 25%를 회복한다. 포션 잠금과 붕대/치료 세트 공통 잠금이 있어 한 전투에 같은 대상에게 계속 쓰는 경로를 막는다. 전투불능 아군의 일반 식사·치료는 허용하지 않는다.
- 방 사이에는 일반 이동·숙박 구매·제작·파티 교체·회복 명령이 잠긴다. 보유 음식 사용, 장비·진형·역할 조정은 가능하다. 새 음식을 그 자리에서 제작하거나 숙박으로 완치하는 경로는 없다.
- 7층 3번 방은 동료 2명 전투불능을 요구하는 희생 조건이 있다. 치유를 많이 넣어 아무도 쓰러지지 않게 하면 적 피해가 차단된다. 이 조건이 있어서 치유 생존만을 좋은 편성의 기준으로 삼을 수 없다.
- 저장 재로드는 진행 중 방의 runtime 전체와 층 진행 상태를 보존했다. 방 사이 저장도 `BREAK`, HP, 준비 음식 효과를 유지했고 다음 방 입장에 동일 HP가 적용됐다. 이번에는 나선 구조나 수치를 바꾸지 않았다. 방 규칙은 여전히 `roomOf`가 현재 `FLOORS`에서 읽으므로, 나중에 층 규칙을 수정할 때 진행 전투 보존은 별도 주의 대상이다.
