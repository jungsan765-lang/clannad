## 최초 잠정 실패의 구체적인 차이

- 진 Q: `ATK×0.035+300 = 312.8366`; 테스트는 옛 `ATK×0.05+450 = 468.338`을 기대한다.
- 종려 E: 새 최종 보호막 888, 옛 계수 0.65 기대값1925. 새 계수는0.30이다.
- 종려 C2: 새 최종 보호막700, 옛 기대값1516. 새 계수는0.30이며 E/Q 보호막을 합치지 않는 기존 검증을 유지했다.
- 운영자 보호막 배율: `100×2×0.30×1.1 = 66`; 옛 `100×2×0.65×1.1 = 143`을 기대했다.

`FAILURE_CLASSIFICATION.json`에 판정과 확인 한계를 적었다. 치유의 첫 반복 사례나 운영자 테스트가 중단된 이후의 계약까지 통과했다고 세지 않는다. 최초 중단된 뒤 계약은 교정한 최종 재실행에서 계속 검사했다. 이 검사들에서 시전자 오귀속 오류를 입증한 실패는 없었지만, 이 결과만으로 그 오류가 모든 경우 사라졌다고 주장하지 않는다. 부모 담당자의 새 캐릭터/원래 저장/오귀속 전용 검사는 별도 원장이다.

## 입력과 재실행

`provisional_source_8/`에는 정확한 명령·시작/끝 시각·종료 코드·stdout/stderr·테스트 SHA·제품 입력 SHA를 보존했다. 실행 도중 `runtime_constellations_v01411.js`와 package 버전의 변경이 있었다. 해당 실행은 최종 동결판으로 세지 않는다. 실행 중 다른 담당자가 편집한 새 캐릭터 테스트는 이 선정 목록에 포함하지 않았다.

최종 명령은 `COMMANDS_KO.md`, 각 실행 `selection.json`과 `*.result.json`에 있다. 선정8의 각 프로그램은 동일 source 로더로 실행했다. generated 서버는 source CJS 검사의 실행기가 아니며 해시는 출처 정보로만 기록한다.

## 승인한 테스트 최소 교정

원문3개를 `original_tests/{tests,tools}/`에 먼저 저장하고 SHA를 기록했다. 담당자의 명시 승인 뒤 Jean Q raw 기대식1곳, 종려 E/C2 보호막 계수2곳, 관리자 보호막 기대식1곳만 `combatHealingBudget()`/`combatCharacterBudget()`로 바꿨다. assert 제거·새 mock·장비/적 능력치 변경은 하지 않았다. 이후 별도 승인으로 백출 비교 하나의 종려 C3 선언을 추가했으며 그 단계도 분리 기록했다. `APPROVED_TEST_CHANGES.json`과 `approved_*.diff`가 정확한 변경을 보여 준다.

## 보존한 C0 fixture 실패와 승인한 C3 재실행

백출과 종려가 모두 명함인 동일 원래 fixture에서 보호막이740/758이었다. 입력759는 둘 다 소진시키며758을 흡수하고 HP피해1을 남겼다. 백출은455를 회복했고 실제 최종 HP는2336-1+455=2790으로 일치했다. 원래 검사는 종려가758보다 크다고 가정하여 `assert(jadeBefore>packet)`에서 중단한다. 제품 처리 오류 증거로 분류하지 않으며 해당 C0 실행은 그대로 실패 원장에 남겼다. 담당자의 추가 승인 뒤 이 백출 비교 사례만 기존 cons helper로 종려 C3를 선언해 실제 E 특성 +3을 적용했다. 같은 레벨·장비·적·공격과 모든 기존 assert는 유지했고, 수정한 제목/주석에 C3 조건을 명시했다. 전체 보호막11항목 재실행은 모두 통과했다. `baizhu_jade_fixture_facts.json`/`FIXTURE_SCOPE_DIFFERENCE.json`에 원 C0 조건과 실제 보호막·피해·회복 로그가 있다. `APPROVED_NATIVE_C3_FIXTURE.json`/`approved_native_c3_fixture.diff`와 `pre_c3_fixture/`에 추가 승인 변경 전/후가 있다. `final_native_c3_fixture_corrected/`의 로그·종료 코드와 제품 SHA는 11항목 통과를 증명한다.

## 해소한 정적 의심

exclusive weapon heal wrapper가5번째 meta를 inner 호출에 넘기지 않는다는 정적 의심은 실제 로드 순서를 확인하며 해소했다. 호출은 admin→constellations→rhythm→formations→exclusive→base라 외부 두 wrapper가 먼저 FIELD/FOLLOWUP meta를 읽는다. 실제 source 로더에서 무시전·같은 시전자 E·다른 시전자 Q의6개 격리 상황 모두 회복100이었다. `PERSISTENT_CONTEXT_ASSESSMENT.json`에 정정과 한계를 남겼고 이 의심으로 제품을 수정하지 않았다. 이 격리 사실은 자연 전투 승리율 검사에 합산하지 않는다.

이 문서는 기존 처리의 회귀 점검이다. 새로운 수치의 전 구간 승리율·육성 시간·숙박 수요 균형을 보장하는 실측은 아니다.
