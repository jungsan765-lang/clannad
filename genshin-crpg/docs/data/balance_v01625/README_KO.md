## 재현할 때 주의할 점

진단은 QA DB 원문 SHA256 `254c9294c7787b421f38c84b3ad8fed9f00c207a8ef74855868c0cda48dc0962`를 사용했다. 압축본은 `field/release_final/harness/qa_db.json.gz`에 있고, 같은 자료가 0.16.24 검증 폴더에도 있다. **이 DB를 운영 content/db.json에 덮어쓰지 않는다.** 원격 authored DB·assets·게임 화면을 보존한 선별 게시다. 재현이 필요하면 별도 검사 체크아웃에만 QA DB를 풀고 각 runner에 명시한 인자로 실행한다.

진단 준비의 캐릭터 소유·해금·모라 지급은 테스트 fixture다. 자연 진행 계정이 그 장비·재료·모라를 이미 획득했다는 의미가 아니다. 최초 정수6조건은 첫 반복 재료 수급 경계를 검사하며 이야기 최초 토벌 전체를 검증한 자료는 아니다. 재현 명령, 시드·편성·진형·장비·특성·실제 공개 행동은 각 원장과 cases JSON에 남았다.

대형 입력 체크아웃/전체 복제 tar는 중복 게시하지 않는다. 고정 게시 커밋+보존된 QA 압축본+원장 runner/cases/해시 목록으로 검사 환경을 복원한다. `source_before`에는 실제 이전 7모듈과 해시가 있어 이전 저장 계약의 기준을 복원할 수 있다. 캐릭터 계약은 소스와 실제 서버의 기존 관계 모듈 설치 부트스트랩을 양쪽에 동일 적용한 뒤 전체 상태를 비교한다.

## 다음 담당자가 이어 볼 부분

모든 4성 풀돌·5성 명함 편성에서 수동 공략이 필수인 목표는 달성했다고 주장하지 않는다. 동료 AI가 핵심 공략을 수행하거나 적합 편성이 강한 보스는 남아 있다. 일부 필드 완치와 타르탈리아·야타 반복 승리는 실제 관측이다. 추가 조정은 원장에 명시한 편성·투자·시드와 동일 조건으로 비교한다. 드롭 감소·숙박 인상·등급별 숨은 규칙을 난도 대용으로 넣지 않는다.

당시 일반 연전52회 전승 중 주인공KO2회만으로 종려·진 너프를 기각했던 판단은 철회했다. 첫 입장 봉쇄와 승리 후 연전 손상은 분리하며, 이번에는 음식·숙박의 역할까지 고려해 조정을 채택했다.

다인 모드의 동일 캐릭터 이름이 겹치는 모든 지속 회복 경로는 아직 native 재현하지 않았다. 이번 두 지속 발동의 actor ID 수정과 전체 다인 치유 검증을 혼동하지 않는다. 추가 제품 변경이 필요하면 원장을 먼저 재현하고 당시 저장 정책을 보존한다.
