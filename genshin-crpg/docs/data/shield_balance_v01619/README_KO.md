# 0.16.19 보호막·반복 전투 최종 근거

최종 공동 패치에서 수집한 **54조건은 모두 완료**했습니다. 저장된 원자료를 다시 읽어 검증했으며 전투를 중복 실행하지 않았습니다. 전투 실행 오류는 원본·최종 모두 0건, 첫 전투의 적 종류·레벨·최대 HP는 54조건 모두 같습니다. 원본 147전과 최종 142전은 패배 시 종료하는 길이가 달라 직접 승률로 비교하지 않습니다.

최종 런타임 지문은 `73cd503e06bbde8330651f8847691df2354b2e5545019ce9c81f5fa89f0dbb42`입니다. 이는 118개 런타임 스크립트와 로컬 DB 원문으로 계산한 지문이며 게시 커밋 SHA와 다릅니다. 수집에 사용된 122개 파일(런타임·기존 표시 코드·presentation·DB)의 해시는 현재와 모두 같습니다. 별도로 고정한 제품 233개 파일도 변경 없이 유지됐습니다. 원격 DB 원문은 보존하고 로컬 DB와의 런타임 의미 동일성은 `../qa_v01619/db_runtime_semantic_parity_v01619.json`에 기록했습니다.

## 조건과 결과

초기 편성·장비·특성·seed를 고정하고 실제 공개 전투와 동료 AI를 사용했습니다. 전투 사이의 HP·경험치·보상은 이어지며 숙박·음식·강제 회복은 하지 않았습니다. 층암거연은 실제 대기 행동으로 지역 적을 만납니다. 특정 적을 다시 뽑거나 수치를 고쳐 승리시키지 않았습니다. 첫 전투 이후에는 전투 길이와 네이티브 난수 소비가 달라 다음 적 구성이 달라질 수 있습니다.

초기 장비는 제작 +6, 동료와 주인공의 레벨은 같습니다. 기초 특성은 Lv25/40/50/60에서 각각 4/6/8/10이며 운명의 자리 보정은 실제 런타임을 따릅니다. 성유물은 넣지 않았습니다. `FIVE_DEF_C2`는 종려·다이루크·진 모두 C2, `FOUR_HEAL_C6`는 향릉·행추·바바라 모두 C6입니다. `SCREEN_C232`는 별도 편성으로 여행자 C3·다이루크 C2·감우 C0·진 C2이며 위 표의 종려 편성과 합치지 않습니다. 어느 조건도 사용자 저장 파일의 정확한 재현이라고 주장하지 않습니다.

반응·회복·보스·보호막 변경을 합친 결과입니다. 보호막만 줄인 초기 파일럿은 `shield_only_pilot.json.gz`, 동시 소모 적용 전 중간안은 `before_parallel_candidate.json.gz` 및 `after_sequential_native.json.gz`로 분리했습니다. 중간안의 결과를 최종 결과로 사용하지 않습니다.

## 보호막 계산과 저장

아군 보호막은 같은 피해를 동시에 소모합니다. 예를 들어 300·400 두 보호막에 물리 피해 500이 들어오면 풀 소모는 700이지만 실제 막은 HP 피해는 400이고 HP는 100 줄어듭니다. 여러 보호막을 붙여 총합 700의 방어력을 얻지 않습니다. 적의 보호막·원소 장벽은 기존 처리 순서를 유지합니다.

최종 `absorbed`는 실제로 막은 HP 피해이며 `shieldBefore - shieldAfter`는 풀 소모 합계입니다. 원본 아군 `absorbed`는 보호막의 원시 단위를 세던 값이어서 서로 그대로 빼거나 방어력 감소 비율로 계산하지 않습니다. 실제 HP 손실은 각 native 로그의 `hpBefore - hpAfter`를 합산하고 초과 피해는 제외했습니다. 표시 게이지도 아군은 가장 큰 기본 풀, 적은 기존 합계를 사용합니다. 같은 원소에 대한 흡수 효율은 개별 보호막의 실제 피해 계산에 적용합니다.

기존 저장의 HP·상태·필드·남은 보호막 수치와 진행 데이터는 보존합니다. 다만 **기존 진행 중 전투도 이후 피격부터는 고친 아군 동시 소모 규칙을 적용**합니다. 저장 바이트를 보존한다는 말이 모든 이후 전투 계산을 옛 규칙으로 유지한다는 뜻은 아닙니다. 종려 신규 보호막의 배율과 기존 남은 보호막 수치도 구분합니다.

승리 정산 중 주인공 10% 복귀와 레벨 상승 회복이 생길 수 있습니다. 정산 후 HP 100%를 힐러가 전투 중 완전히 유지한 근거로 사용하지 않습니다. `final_summary.json`에 정산 전 HP·전투 중 사망·레벨 상승·주인공 복귀를 별도 기록했습니다. 숙박 행동을 하지 않아 `lodgingMora=0`인 것은 숙박이 필요 없다는 뜻이 아닙니다.

## 파일과 재현

| 파일 | 역할 |
| --- | --- |
| `baseline_native.json.gz`, `final_native.json.gz` | 원본·최종 실제 전투, 행동 로그, 초기·최종 배우 상태, 회복·보상 원자료 |
| `final_summary.json` | 54조건의 짝 비교와 정산 전/후 구분 |
| `cases.json` | 54개 조건과 운명의 자리·레벨·seed |
| `final_loaded_sources.json`, `final_validation.json` | 수집 파일 해시 및 원자료 완결성 검사 |
| `mechanics_final_test.json` | 실제 시전·넘친 피해·원소 효율·기존 저장 등을 검사한 11/11 동작 검사 |
| `meter_test.json`, `playback_test.json` | 기존 게이지 값 4/4, 실제 impact 시점 갱신 2/2 검사 |
| `lanyan_probe.json` | 변환 보호막의 전체 피해 반감과 개별 250% 흡수 효율을 구분한 후보 진단; 공개 전투 승률 자료가 아님 |
| `MANIFEST.json` | 근거 파일별 바이트 수와 SHA256 |

저장소 프로젝트 루트에서 기존 근거를 재집계합니다. 제품 코드나 서버를 바꾸지 않습니다.

```bash
python tools/summarize_shield_balance_v01619.py --before docs/data/shield_balance_v01619/baseline_native.json.gz --after docs/data/shield_balance_v01619/final_native.json.gz --out /tmp/crpg-shield19-summary.json
```

현재 코드의 실제 전투를 다시 확인하려면 다음처럼 별도 결과 파일을 사용합니다. 게시본의 DB 원문이 다르면 raw 지문이 달라질 수 있으므로 지문만으로 동작 차이라고 결론내리지 않습니다.

```bash
node tools/audit_shield_balance_v01619.cjs --cases docs/data/shield_balance_v01619/cases.json --out /tmp/crpg-shield19-current.json.gz
node tests/test_shield_balance_v01619.cjs
node tests/test_shield_meter_v01619.cjs
node tests/test_shield_playback_v01619.cjs
```

선택한 소수 seed는 경계·문제 재현을 위한 사례입니다. 지역·희귀도·운명의 자리를 섞은 인구 전체의 승률이나 육성 소요 시간으로 해석하지 않습니다.
