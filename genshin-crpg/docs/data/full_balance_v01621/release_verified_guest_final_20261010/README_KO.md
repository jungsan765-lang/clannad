# 0.16.21 최종 릴리스 회귀 검사

`tools/verify_release.py`의 실제 177개 검사 프로그램을 최종 소스에서 다시 실행한 증거이다. 임시 동행의 예전 무료 완치 분기는 현재 경로에서 도달할 수 없어 제품 수정에 넣지 않았다. 이 폴더 이름은 검사 준비 시 지정한 이름이며, 검사 대상은 최종 제품 소스 4개 변경안이다.

이전 후보의 18개 통과 결과를 여기의 통과 수에 합산하지 않는다. 완료 수와 실제 실패는 `results.json`, 진행 상황은 `checkpoint.json`, 모든 검사 완료 후 합계는 `summary.json`에서 확인한다.

- `run_release.py`: 체크포인트를 보관하는 실행기. 177개 목록을 AST로 읽고, 프로그램당 900초 제한을 적용한다. 기존 릴리스 실행기를 import하거나 빌드를 다시 실행하지 않는다.
- `plan.json`: 실제 실행한 검사 목록과 실행 조건.
- `input_manifest.json`: 시작 시 제품 소스, 데이터, 서버 엔진, 177개 검사 및 관련 도구의 바이트 수와 SHA-256. 마지막에 입력 변경 여부를 대조한다. 별도 증거 검증용 도구 2개와 사용하지 않는 임시 동행 검사는 대상에 넣지 않는다.
- `per_gate/*.json`, `results.json`, `journal.jsonl`: 원래 결과. 실패를 재시도로 덮어쓰지 않는다.
- `logs/*.log.gz`: 각 검사의 원래 표준 출력과 오류. 결과의 `logSha256`은 압축을 푼 원문 기준이다.
- `workers.json`: 동시에 실행할 검사 수. 다른 성장 검사가 모두 끝난 후 2개로 시작했고, 안전하게 체크포인트를 저장한 뒤 최대 3개로 높인다. 전체 사용 메모리가 4 GiB 이상이면 새 작업을 2개까지, 6 GiB 이상이면 1개까지 제한한다. 실행 중 검사를 강제로 끊지는 않는다.
- `runner_transition.json`, `run_release_initial_workers2.py`: 처음 2개 실행기의 원문과 해시, 안전 정지 시점, 재개 실행기 해시를 보관한다. 제품·검사 입력은 바꾸지 않는다.
- `checkpoint.json`: 완료 수와 실행 중 검사.
- `summary.json`: 177개 완료 후 통과·실패·입력 변경 목록.

과거 0.13.43 원본 데이터베이스 및 저작용 편집 행이 필요한 검사도 실제로 실행한다. 입력이 없으면 실패로 남기며, 해당 검사를 통과로 바꾸거나 임의의 편집 행을 만들어 넣지 않는다. 실제 최종 브라우저·서버의 218개 동작 일치 검사와 빌드 원본은 상위 `build` 증거에서 확인한다.

`PAUSE_REQUESTED` 파일을 만들면 실행 중 검사를 끝내고 다음 검사를 시작하기 전에 멈춘다. 해당 파일을 없앤 뒤 아래 명령을 다시 실행하면 완료하지 않은 검사부터 재개한다. 입력 해시가 바뀌었다면 재개를 거부한다.

```bash
python3 docs/data/full_balance_v01621/release_verified_guest_final_20261010/run_release.py
```

## 실제 완료 결과

177개 검사 프로그램을 모두 실행했다. 175개가 통과했고, 아래 원본 입력 부족 2개는 실패로 보관했다. 제품 동작에서 발견된 실패와 미분류 실패는 0개이며, 시간 제한 초과와 SIGKILL도 각각 0개이다. 전체 통과라고 표시하지 않는다.

| 원래 실패 검사 | 실제 실패 원인 | 분류 |
|---|---|---|
| `tests/test_save_v01344.cjs` | 과거 0.13.43 커밋 `f0c08d6`이 현재 체크아웃에 없어 `git show`가 실패했다. | 과거 원본 입력 부족 |
| `tests/test_release_isolation_v01513.py` | 현재 검사 DB의 편집용 표는 머리글 1행만 있어, 저작용 원본의 편집 행을 요구하는 검사가 실패했다. | 저작용 원본 입력 부족 |

`final_verification.json`에서 원래 `per_gate` 결과 177개와 `results.json` 177개가 일치함을 확인했다. 압축을 푼 원출력 177개 모두의 길이와 SHA-256을 대조했고, 실행 전후 소스·검사·서버·데이터 입력 변경은 0개였다. 원래 전투 소스 `runtime_combat.js`의 SHA-256은 `544b8ffcdafcc55d686f757026a25fc940bc08bbdc235115ab71a29894ffcdaa`로 일치한다. 검사 결과나 실패를 통과로 바꾸지 않았다.

원래 `journal.jsonl`은 175행을 그대로 보관한다. 파일 복구 이후 `test_local_dev_config.cjs`와 `test_save_v01344.cjs`의 저널 행 2개가 누락되어 있었다. 두 검사의 독립 원결과와 원출력은 남아 있으며, 이를 포함한 177개의 독립 `per_gate` 원결과를 근거로 `journal_reconstructed_from_per_gate.jsonl`을 별도로 만들었다. 재구성본을 원래 출력 스트림으로 표시하지 않는다.

로컬에는 복구 스냅샷의 비압축 `.log` 84개, `active/*.json` 84개, `__pycache__` 1개가 남아 있다. 이 169개는 실제 실행 중인 검사가 아니며 게시와 최종 파일 목록에서 제외한다. 게시 증거는 독립 `per_gate` 177개, 검증한 압축 원출력 177개, 요약·입력 해시·실행기·별도 재구성 저널이다. `run.stdout`도 일부 출력만 남은 스트림일 수 있으므로, 완료 증거는 독립 결과와 원출력 대조를 기준으로 한다.
