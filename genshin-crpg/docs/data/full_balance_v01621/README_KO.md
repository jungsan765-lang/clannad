## DB를 같은 파일로 착각하지 않기

로컬 QA용 DB와 게시 DB에는 작성용 표의 차이가 있다. 게시할 때 QA용 DB로 교체하지 않는다.

| 입력 | 정확한 식별값 |
|---|---|
| Canonical QA raw | 23,049,439 bytes, SHA256 `254c9294c7787b421f38c84b3ad8fed9f00c207a8ef74855868c0cda48dc0962` |
| 보존할 게시 authored raw | 23,098,055 bytes, Git blob `cc3996929c885d41289038ff501640039a4cc71e` |
| 양쪽에 요구하는 정리된 runtime DB | 23,049,438 bytes, SHA256 `c3d5eef26ac21e19136131ba3ab24ab542c1dbe63d428f6e47ab7743d1e75aa1` |

`tools/runtime_data.py`의 실제 `clean_runtime_db()`를 적용하고 `json.dumps(..., ensure_ascii=False, separators=(',', ':'))`의 UTF-8 bytes를 비교한다. 정렬이나 추가 개행을 넣지 않는다. QA 입력은 이 native clean 해시를 실제로 확인했다. 원격 authored raw를 확보해서 같은 비교를 실행한 결과는 아직 없으므로 **게시 DB 보존 확인과 runtime 내용 일치 확인을 별도로 기록한다.**

검증기는 알려진 raw 두 입력만 허용한다. 정리된 내용이 같더라도 개행만 추가된 다른 raw 입력은 거절한다. 결과 JSON의 `database.mode`는 `canonical_qa` / `published_authored` / `unknown_raw`이고 실제 raw SHA256·Git blob·정리된 bytes/SHA256·일치 결과를 함께 출력한다.
