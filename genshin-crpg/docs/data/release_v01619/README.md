# 0.16.19 전체 회귀 검사 자료

## 원시 결과와 재검증의 구분

`results.json`은 지정된 **173개 검사 프로그램의 최초 완료 결과**를 보존한다. 168개 통과, 5개 실패이다. 실패한 행을 통과로 덮어쓰지 않았다.

`post_rerun_evaluation_v01619.json`은 원시 결과 뒤에 시행한 정당한 재검증을 따로 기록한다. 현재 격리 복사본에 누락된 부모 `.github/workflows` 입력을 원본과 같은 SHA256으로 복원한 뒤 `test_test_banner_v01510.cjs`만 재검증하여 통과했다. 이어 교착 종료 검사의 입력과 기대 조건을 재검토한 뒤, 정상 전멸 처리 2건·안정적인 실제 AI 교착 처리 1건·생존 플레이어 조작권 1건의 네 가지 검사가 통과했다. 성장 검사도 같은 18조건의 실제 전투와 정산을 확인하여 통과했다. 최종 평가는 **171개 통과, 과거 입력 결손으로 미통과인 2개**이다.

미통과인 아래 2개는 0.16.18 점검 때부터 확인된 로컬 입력 결손이다. 두 검사를 통과했다고 처리하지 않는다.

- `test_save_v01344.cjs`: 정확한 과거 `f0c08d6` Git 객체/검증된 0.13.43 DB가 로컬 복원 저장소에 없다. 현재 DB로 대체하지 않았다.
- `test_release_isolation_v01513.py`: 이 로컬 DB의 편집 이력 2개 표가 이미 머리글만 남은 상태여서, 정제 전 원고행이 있어야 하는 입력 조건을 충족하지 않는다. 해당 실패는 `1 not greater than 1` 한 건이다. 원격 원본 DB는 이 작업에서 바꾸지 않았다.

`test_growth_balance_v01522.cjs`도 최초 원시 실패를 보존한 채 별도로 재검증하여 통과했다. 원래의 편성·장비·특성·시드·18조건은 유지했다. 실제 전투 결과는 **17승 1패**이며, 낮은 레벨의 1패는 아군 전원 HP 0·살아 있는 적·무보상·단일 정산·저장 복구·중복 정산 불변까지 검사한 정상 전멸이다. 중간·최고 레벨의 전승, 적 능력치 고정, 승리한 동일 시드에서 성장 후 턴 수가 늘지 않는 조건, 리월 최고 레벨의 절반 이하 턴 수 보장은 유지했다.

| 성장 검사 조건 | 레벨 | 승리 전투의 평균 턴 | 전투 결과 |
| --- | --- | --- | --- |
| 몬드 조건 | 17 → 30 → 45 | 15.5 → 5.67 → 3.33 | 2/3승 → 3/3승 → 3/3승 |
| 리월 조건 | 32 → 45 → 60 | 14 → 8.33 → 5.67 | 3/3승 → 3/3승 → 3/3승 |

평균은 승리한 전투만 집계한다. 레벨 17의 25턴 전멸을 승리의 평균에 섞지 않았다. 이 전멸은 다중 보호막이 각자 같은 피격에 소모되도록 고친 변화에서 발생했으며, 옛 순차 소모를 격리 재현하면 이전 승리가 복구되는 반례를 보존했다. 성장 검사 원본·수정본 해시, 실제 한 번의 실행 로그, 18조건 전체 결과는 `../qa_v01619/growth_regression_validation/`에 있다.

교착 검사의 옛 보스 조합은 과도한 회복 때문에 409/454라운드의 교착에 도달했으나, 수정 후에는 45/44라운드에서 아군 전멸로 정상 종료한다. 제품의 `autoUntilPlayer` 함수는 바꾸지 않았다. 기존 두 조합은 정상 패배 정산을 확인하고, 물 원소에 면역인 적과 바바라의 선언된 안정 입력은 실제 AI로 반드시 교착 종료가 발생하도록 검사한다. 교착 방지 함수가 없을 때는 `COMBAT_LOOP`가 발생하는 반례도 보존했다. 검사 코드 원본과 수정본의 해시, 네 가지 통과 로그는 `../qa_v01619/stalemate_regression_validation/`에 있다.

## 이어서 실행한 방식

메시지 오류 전 완료된 신규 8개 검사, 이후 재개 중 완료된 기존 22개 검사, 합계 30개의 결과와 로그를 보존했다. 원본 실행은 root의 정확한 실행 세션 `12691`에서 Ctrl+C로 종료했다. 다른 프로세스를 일괄 종료하지 않았다.

미완료 143개만 원본과 분리된 3개 복사본에 53/38/52개로 배분했다. 각 복사본은 기존 검사기와 같은 작업자 2개를 사용했다. 생성물과 서버 빌드가 서로 섞이지 않으며, 테스트 실행 중 제품이나 CI 검사기를 수정하지 않았다.

제품의 `source` 및 DB 233개 해시는 고정 시점과 검사 종료 후 원본·3개 복사본에서 같았다. 최초 검사 시점의 검사 파일 173개와 검사기/빌더 3개, 합계 176개도 원본·3개 복사본에서 같았다. 후속 교착·성장 검사 수정본은 별도 재검증 항목에 원본·수정본 해시를 명시한다.
