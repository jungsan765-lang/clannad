# 0.16.19 성장 검사 실패의 읽기 전용 진단

`tests/test_growth_balance_v01522.cjs`가 몬드 Lv17·시드22 조건에서 실패했다. **적을 강화한 결과는 아니며, 노엘의 보호막과 결정 보호막이 한 공격을 동시에 소모하도록 고친 결과다.** 제품 수치와 테스트 기대값은 이 진단에서 수정하지 않았다.

## 그대로 재현한 조건

원래 `tests/helpers_balance_v0141.cjs`의 `fixture`와 `run` 코드를 바꾸지 않고 각각 0.16.18·최종 0.16.19 엔진의 별도 VM에 로드했다. 이세계인·엠버·케이아·노엘 4인, 같은 레벨, +3 장비, 기본 특성 1, 시작 HP 100%다. 원래 검사는 전투 시작 후 주인공까지 전원 AI로 바꾸고 `autoUntilPlayer`를 최대 200회 호출한다. 사람이 이세계인의 지원 기술을 선택하는 실전 정책은 아니다.

- 몬드: `MAP_MOND_WOLVENDOM`, `EG_MOND_HILI_ELITE`, Lv17/30/45 × 시드11/22/33.
- 리월: `MAP_LIYUE_PLAINS`, `EG_LIYUE_HILI_ROCK`, Lv32/45/60 × 시드11/22/33.
- **각 엔진 18조건·18전**, 합계 36전. 별도 원인 분리 4전. 런타임 예외·멈춤 0.
- 초기 아군·적 능력치 행, 적 전체 actor 정보, 편성·장비·특성·돌파는 **18/18 조건 모두 동일**했다. 최종 제품에서 이 필드 적의 HP/ATK/DEF/명중/회피/편성 수를 변경한 흔적이 없다.

각 시드 안에서 아군 레벨을 올려도 몬드 적은 계속 **Lv17**, 리월 적은 계속 **Lv32**였다. 세 아군 레벨 구간의 적 능력치 행도 동일하다. 실패 조건인 몬드 시드22의 적은 아래 3명으로 이전·최종 모두 같다.

| 적 source | 실제 레벨 | 최대 HP | ATK | DEF |
|---|---:|---:|---:|---:|
| `MON_HILI_FIGHTER` | 17 | 3,880 | 1,136 | 74 |
| `MON_MITACHURL_AXE` | 17 | 9,825 | 1,544 | 103 |
| `MON_HILI_SHOOTER` | 17 | 3,880 | 1,136 | 74 |

### 몬드17·시드22에서 달라진 이유

3라운드의 첫 차이는 노엘에게 들어온 같은 물리 피해 229다. 그 직전 결정 보호막 483, 호심경 713, 노엘 HP 3,804로 같았다.

| 같은 공격 뒤 | 이전 순차 처리 | 최종 동시 소모 |
|---|---:|---:|
| 결정 보호막 잔량 | 483 | 254 |
| 호심경 잔량 | 484 | 484 |
| 그 공격의 HP 피해 | 0 | 0 |

이전에는 큰 보호막을 먼저 썼기 때문에 작은 보호막을 다음 공격용 예비 풀처럼 남겼다. 최종에서는 두 보호막 모두 같은 공격을 소모한다. 노엘의 기존 일반 공격 회복은 **호심경이 남아 있을 때만** 발동할 수 있어, 이후 회복 기회와 난수 흐름도 달라진다. 노엘의 실제 요청 회복식은 두 엔진 모두 그대로였다.

| 실패 조건의 전투 전체 | 이전 | 최종 |
|---|---:|---:|
| 실제 회복된 HP | 700 | 280 |
| 회복 함수 호출 수 | 32 | 16 |
| 노엘 호심경 생성 | 7 | 6 |
| 결정 보호막 생성 | 13 | 11 |
| 공격 빗나감 로그 | 7 | 5 |
| 반응 | 결정13·융해1 | 결정11·융해1 |

회복 호출에는 이미 사망한 대상에게 들어가 실제 회복 0인 호출도 포함된다. 이 수를 실제 회복 횟수로 쓰지 않는다. 명중·회피 능력치는 초기 actor에서 같고, 전투 후반의 공격 수와 난수 소비가 바뀌어 빗나감 총수도 달라진 것이다.

## 최소 원인 분리

같은 최종 소스와 실패 조건에서 아래 부분만 VM 안에서 되돌렸다. 제품 파일을 수정한 것이 아니다.

| 격리 VM | 결과 | 실제 회복 |
|---|---|---:|
| 아군 보호막을 이전 순차 소모로만 복원 | **27라운드 승리** | 700 |
| 융해 뒤 빙결이 남던 처리만 복원 | 25라운드 패배 | 280 |
| 이전 반응 선택 방식만 복원 | 25라운드 패배 | 280 |
| 위 세 가지 모두 복원 | 27라운드 승리 | 700 |

보호막 소모만 복원하면 원본 결과가 돌아왔다. 이 조건에 유라·풀 원소·물 원소 동료가 없고 실제 쇄빙/격화/발산/개화 로그도 없다. 이번 다른 힐러의 계수 하향이나 격화 특성 배율 수정 때문에 실패했다고 설명할 수 없다.

## 패배가 진행을 막는지

같은 패배를 별도로 재현하고 저장 후 다시 읽어 **기존 실제 회복 행동**을 확인했다.

1. 25라운드 패배 뒤 `runtime`은 종료됐고, 모라 3,000 → 2,700, `DOWNED` 상태와 기존 60초 패배 대기만 남았다.
2. 해당 저장은 정상 복구됐다. 대기 중 `RECOVER`는 기존 “60초 남음” 이유로 막혔다.
3. VM 시계만 60,001ms 지난 것으로 놓으면 `RECOVER`가 정상 허용됐다.
4. 실제 `action('RECOVER')`는 몬드성으로 이동하고 전원 HP 100%, `LOCATION`·`FREE` 상태로 복구했다. 패배 벌금 이후 모라를 추가 차감하지 않았다.

따라서 이 조건에서 **불가역적인 필드 진행 잠김은 재현되지 않았다.** 처음 같은 야외 장소의 여관을 찾았던 보조 검사에서는 여관이 없다는 결과가 나왔다. 이는 야외에 여관이 없는 정상 결과이며 실제 전투불능 회복 경로는 위 `RECOVER`다. 그 첫 보조 자료도 `recovery_inn_probe.json`에 보존했으며 최종 회복 검증 `recovery_validation.json`의 오류는 0이다.

## 판단과 한계

원래 검사의 “약한 기본 특성 편성도 세 시드 모두 반드시 승리” 가정은 보호막의 예비 풀 누적 이득에 의존한 조건 하나에서 더 이상 성립하지 않는다. 성장 관계나 고정 적 수치가 무너진 회귀와 구분해야 한다. 현재 근거로 보호막 오류를 되살리거나 필드 적 전체를 약하게 할 이유는 없다. 실패한 기존 검사 자체는 통과로 표시하지 않는다.

### 진단 뒤 승인된 기존 검사 보강

위 근거를 검토한 뒤 기존 `tests/test_growth_balance_v01522.cjs`만 보강했다. **18조건·편성·+3 장비·기본 특성·시드·적 고정성은 그대로** 두었다. 각 지역 최저 레벨에는 실제 승리 샘플이 있어야 하고, 중간·최고 레벨은 계속 시드 세 개 모두 승리해야 한다. 같은 시드의 연속된 승리에서 성장 후 라운드가 늘어나는 것도 실패로 처리한다. 리월 최고 레벨의 평균 처치 라운드가 최저의 절반 이하라는 기존 보장은 유지했다.

최저 레벨에서 패배한 경우 그냥 넘어가지 않고 실제 마지막 아군 전원 HP 0·적 생존, 런타임 종료, 결과 `DEFEAT`, 경험치와 보상 0, 성장값 유지, 한 번의 영수증/로그, 저장 복구, 중복 정산 뒤 저장·벌금 불변을 엄격히 확인한다. **패배한 25라운드는 평균 처치 시간에서 제외**한다.

보강한 검사의 네이티브 실행은 한 번, 종료 코드 0이었다. 몬드 최저 레벨은 2승1패·승리 평균 15.5라운드, 중간/최고는 3승씩·평균 5.67/3.33라운드였다. 리월은 세 레벨 모두 3승씩·평균 14.0/8.33/5.67라운드였다. 고정된 제품 233개 경로의 해시는 실행 뒤에도 바뀐 것이 0개였다. 원본 실패를 없던 일로 바꾼 것이 아니라, 변경된 보호막 규칙 아래의 합법적인 승패와 성장을 검증하게 바꾼 것이다.

`updated_test_result.json`에 원본/새 검사 SHA256·종료 코드·로그 해시·제품 드리프트 0을 저장했다. `updated_test_native.log`는 한 번의 실행 로그, `updated_growth_balance.json`은 그 실행의 18조건 결과다. 이 개별 실행이 전체 출시 회귀 검사도 통과했다는 의미는 아니다.

이 결과만으로 전체 초반 이야기 난이도가 적정하다고 판정한 것은 아니다. 해당 검사는 이미 이야기 커서를 `END`로 둔 명시적 필드 조우와 전원 AI의 기본 특성 편성이다. 실제 초반 이야기의 강제 순서·제공 장비·수동 지원 행동·계정 저장과는 구분한다. 정상 회복 경로의 UI가 실제 화면에서 잘 보이는지까지 브라우저로 검사한 결과도 아니다.

## 원자료·재현

- `native.json.gz`: 두 엔진 36전과 격리 VM 4전의 전체 actor·피해 패킷·회복·보호막·행동/반응 로그.
- `summary.json`: 관측 소스와 VM 치환, 조건별 능력치·결과·계수·지표.
- `comparison.json`: 18조건 초기 수치 일치 및 원인 분리·회복 결과.
- `recovery_validation.json`: 저장 복구와 실제 `RECOVER` 행동 결과.
- `manifest.json`: 원본 파일 및 사용 도구/변경하지 않은 기존 검사 코드의 SHA256.
- `test_growth_balance_v01522_before.cjs.txt`: 이 진단 시점의 기존 검사 원문. 후속 담당이 기대값 검사를 보강해도 원래의 무조건 전승 가정을 확인할 수 있게 보존했다.
- `updated_test_result.json`·`updated_test_native.log`·`updated_growth_balance.json`: 승인된 기존 검사 보강과 한 번의 실행 증거.

```bash
node tools/audit_growth_recovery_v01619.cjs /tmp/crpg-growth-recovery.json
```

회복 검사 단독 실행은 현재 제품 소스만 사용하며 이전 소스가 없어도 된다. 18조건의 전후·원인 분리를 다시 실행하려면 게시된 0.16.18 고정 커밋의 별도 체크아웃을 준비하고 경로를 `--baseline`으로 명시한다. 아래는 **현재 프로젝트 디렉터리에서** 실행하는 예다.

```bash
CRPG_BASELINE_SHA='1e1b2442b53d42873d29556898f5f612d52d0c7a'
git fetch origin "$CRPG_BASELINE_SHA"
git worktree add --detach /tmp/crpg-0.16.18-evidence "$CRPG_BASELINE_SHA"
python3 - <<'PY'
from pathlib import Path
import json, sys
baseline = Path('/tmp/crpg-0.16.18-evidence/genshin-crpg')
sys.path.insert(0, str(baseline / 'tools'))
from runtime_data import clean_runtime_db
p = baseline / 'content/db.json'
data, removed = clean_runtime_db(json.loads(p.read_text()))
p.write_text(json.dumps(data, ensure_ascii=False, separators=(',', ':')) + '\n')
PY
node tools/audit_growth_regression_v01619.cjs --baseline /tmp/crpg-0.16.18-evidence/genshin-crpg --out /tmp/crpg-growth-regression
```

전처리는 새로 만든 별도 체크아웃의 DB에만 적용한다. 현재 작업 소스나 운영 DB를 바꾸는 명령이 아니다. 압축된 이전 소스 스냅샷을 사용하는 경우에도 먼저 정상적으로 복원하고 그 안의 `source/index.html`·런타임 파일과 `content/db.json`이 있는 프로젝트 경로를 `--baseline`으로 넘긴다. `source/index.html` 없는 빈 디렉터리나 사라진 이전 `/tmp` 경로를 그대로 사용하면 안 된다.

VM 후보의 fingerprint는 치환 전 소스 해시이므로 `substitutions`와 함께 읽어야 한다. 사용된 이전 소스의 파일별 해시는 `summary.json`의 `environments`에 남겼다.
