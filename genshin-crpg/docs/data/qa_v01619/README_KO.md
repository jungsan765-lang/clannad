이 88개는 동작 경계 검사이며 전투 45승이나 서버 API의 모든 저장 경로 검사를 뜻하지 않습니다. 기존 저장 검사는 원본 런타임에서 만든 전투를 네이티브 직렬화·복원한 뒤 선택한 HP·상태·필드·보호막 값이 같음을 확인한 것입니다. 실제 운영 서버의 저장 요청을 발송하지 않았습니다. 기존 수치를 그대로 읽으면서도 이후 아군 피격의 다중 보호막 소모는 고친 동시 소모 규칙을 적용합니다.

반응의 최종43은 고정 제품 233개 스냅샷을 만든 뒤 실행한 release 로그에서 확인합니다. `final/completed_release_before_stream_error.json`에 중단 전에 끝난 신규 8개 프로그램이 모두 통과한 기록을 보존했습니다. 당시 source를 고정했으며 현재도 233개 해시가 같습니다. 앞선 반응 상세43 자료는 이후 `runtime_combat.js`와 `runtime_liyue_cards.js`가 바뀌기 전의 자료라 최종과 같은 실행본이라고 표시하지 않습니다. 중단 후 이어간 전체 회귀의 나머지 결과는 별도의 전체 회귀 기록에서 확인해야 합니다. 이 폴더의 신규8개 통과 기록을 전체173개 통과로 부풀리지 않습니다.

보호막 담당의 최종 54조건 캠페인은 `../shield_balance_v01619/final_native.json.gz`와 `final_summary.json`에서 확인합니다. 최종 지문이 같고 로드한 122개 파일 및 고정 제품 233개의 해시가 유지됐습니다. 첫 적 구성 54/54 동일, 실행 오류 0입니다. 적정 레벨 비경 30조건은 원본·최종 모두 3연승이며 Lv25 층암거연의 저레벨 반복은 정산 전 HP와 레벨 상승/복귀를 분리해 보고합니다. 서로 다른 길이의 반복 캠페인을 전체 승률 하나로 합치지 않습니다.

런타임 지문과 게시 커밋 SHA는 다른 식별자입니다. 지문은 118개 런타임 스크립트와 로컬 DB 원문을 사용합니다. 원격 DB 원문을 보존한 게시본에서는 같은 런타임 의미여도 DB의 공백·원문 숫자 표기 때문에 raw 지문이 다를 수 있습니다. DB 의미 동일성 근거와 source 해시를 함께 확인해야 합니다.

## 전체 회귀와 마지막 실패 진단

전체 회귀의 원시 결과·중단 전 완료 기록·입력 복원 후 재검증은 `../release_v01619/README.md`, `results.json`, `release_summary_v01619.json`에서 확인합니다. 이 QA 폴더의 88개 동작 검사와 전체 회귀의 프로그램 수를 합산하지 않습니다. 전체 회귀의 미통과 항목을 진단 자료가 존재한다는 이유만으로 통과 처리하지 않습니다.

- `stalemate_regression_validation/`: 원래 교착 검사가 정상 전멸까지 반드시 `STALEMATE`로 요구하던 조건을 분리했습니다. 실제 AI·면역을 사용하는 독립 교착 조건, 전멸 후 종료·XP 0·단일 영수증·저장 복구·중복 정산을 확인하고 수정한 **기존 검사 4개**의 로그를 보존했습니다. 보호장치 제거 반례의 `COMBAT_LOOP`는 기대한 실패입니다.
- `growth_regression_validation/`: 기존 성장 검사의 동일한 18조건에서 원본·최종 초기 아군·적 수치를 비교하고, 한 패배가 보호막 동시 소모에서 생기는지 격리 VM으로 분리했습니다. 저장 후 기존 `RECOVER` 행동으로 회복하는 경로도 따로 확인했습니다. 기존 성장 검사의 원래 실패 기록은 남기고, 동일한 18조건을 유지하면서 승리 전투의 성장 비교와 정상 패배 정산을 엄격히 구분한 기존 검사의 1회 재실행 통과 로그를 `updated_test_result.json` 등에 별도로 보존했습니다. 패배를 평균 처치 라운드에 넣거나 단순히 오류가 없다는 이유로 통과시키지 않았습니다.

이 추가 조건·전투·반례·회복 확인은 앞의 88개 검사 수에 더하지 않습니다. 진단 중 제품 233개의 고정 해시는 유지했습니다. 테스트 fixture와 격리 VM 치환은 제품 수치 변경이나 실제 계정 저장 수정과 구분하며, 원본 로그와 수정 검사 결과도 각각 남깁니다.

기타 힐러 검사에서 3승 34조건 중 전원 생존은 30조건, 최종 저장 HP가 전원 100%인 경우는 6조건입니다. 3승에는 전투 중 KO와 여행자의 승리 정산 후 10% 복귀가 포함될 수 있습니다. 패배 후 숙박 견적을 성공한 반복 사냥의 비용 비교에 넣지 않았습니다. 전원 회복일 때의 숙박 견적 20은 **회복비 0 + 객실료 20**이며 무료 숙박을 뜻하지 않습니다. 실제로 숙박을 구입하지 않는 검사와 숙박 영수증을 받은 검사를 구분합니다.

동시 보호막 소모에서 보호막 풀의 감소 합계는 실제로 막은 HP 피해와 다를 수 있습니다. 예를 들어 300·400 보호막에 500 피해가 들어오면 두 풀은 합계 700 소진하지만 막은 HP 피해는 400이며 HP는 100 감소합니다. 아군의 실제 방어량에는 native `absorbed`를 사용하고, 풀 소모량은 별도로 적습니다. 과잉 피해가 포함된 피해 로그 총합도 실제 HP 손실과 구분해야 합니다.

## 재현

저장소 루트에서 실행합니다. 원격 작업 폴더 위치가 다르면 `CRPG_AUDIT_ROOT`를 지정할 수 있습니다. 검사 결과는 `CRPG_QA_OUT`을 지정한 별도 경로에 저장하는 편이 좋습니다.

```bash
CRPG_QA_OUT=/tmp/crpg-qa19 node docs/data/qa_v01619/serpent_burrow_independent.cjs
CRPG_QA_OUT=/tmp/crpg-qa19 node docs/data/qa_v01619/shield_concurrent_independent.cjs
CRPG_QA_OUT=/tmp/crpg-qa19 node docs/data/qa_v01619/legacy_combat_healing_shield.cjs
CRPG_SCREEN_OUT=/tmp/crpg-qa19-other node docs/data/qa_v01619/other_healers_noinn_screen.cjs
```

`qa_helpers_v01619.cjs`는 원본 런타임 120개 파일을 압축 스냅샷에서 임시 폴더로 복원하고, 현재 DB의 런타임 내용을 원본과 비교한 뒤 사본을 사용합니다. 원격 DB의 공백/숫자 원문 표기가 달라도 파싱한 내용이 같으면 사용할 수 있습니다. 원본 DB를 따로 보유했다면 `CRPG_DB_PATH`, 검증된 원본 체크아웃이 있다면 `CRPG_BASELINE_ROOT`를 지정할 수 있습니다. `CRPG_SCREEN_ROOT`는 기타 힐러 검사에 한해 다른 런타임을 명시적으로 선택합니다. 값이 달라진 DB는 자동으로 원본인 척 사용하지 않고 검사를 중단합니다.

반응과 제어의 원래 테스트는 저장소의 `tests/test_reaction_fixes_v01619.cjs`, `tests/test_control_grace_v01619.cjs`를 사용합니다. 이 폴더의 원시 결과와 반례 로그는 수집 당시 근거를 보존한 것이며 새 실행 결과로 덮어쓰지 않습니다.

`MANIFEST.json`에 현재 원자료/보존 사본 해시와 경로를 기록합니다. `MANIFEST_PRE_FINAL.json`은 중간 시점의 역사적 목록이며 현재 수정한 README의 해시 검증에는 사용하지 않습니다. 재현 스크립트는 루트·출력 경로와 출력량만 조정했고 fixture 및 기대 숫자는 바꾸지 않았습니다. 원래 스크립트는 `original_scripts/*.gz`로 별도 보존합니다. 압축 런타임 스냅샷은 QA 복원에만 사용하며 **제품 소스로 덮어쓰거나 VM 원문을 배포하면 안 됩니다.**
