# 0.16.22 리월 장 완료와 성장·성유물 해금 연결

이세계인 경로는 리월 1~3장의 마지막 장면을 실제로 마쳐도, 기존 설계상 해당 퀘스트를 리월 4장 마지막에서 일괄 완료한다. 성장 조건과 성유물 조건은 이 중간 상태를 인정하지 않아 **오셀 이전에는 Lv40·특성6에서 성장이 막히고 황금옥 성유물 반복 도전도 열리지 않는 연결 오류**가 있었다. 모든 이야기 퀘스트를 완료로 채워 넣은 전투 QA 저장은 이 문제를 가렸다.

## 좁게 수정한 기존 조건

- `source/runtime_liyue.js`의 `liyueChapterEnded(quest)`는 기존 저장의 장 END gate, 동일한 저장/경로/부모 갈래/선택 갈래/퀘스트/노드의 두 사건 영수증, 실제 장 수락 entry와 활성 DB의 canonical END 정의를 함께 확인한다. 조회 자체는 저장을 바꾸지 않는다.
- `source/runtime_growth_v01522.js`는 이세계인 리월 01~03에 한해서 위 증거를 기존 성장 선행 조건에 연결한다. 기존 여행자 완료 처리와 퀘스트 완료/보상 시점은 그대로다.
- `source/runtime_liyue_artifacts.js`는 같은 리월 03 END 증거를 기존 타르탈리아 성유물 도전 해금에 연결한다. 새 보상·전투·성유물을 만들지 않았다.

| 실제로 끝낸 장 | 인정되는 돌파 선행 | 이후 성장 상한 | 특성 상한 |
|---|---|---:|---:|
| 리월 1장 | phase3→4 | Lv50 | 8 |
| 리월 2장 | phase4→5 | Lv55 | 9 |
| 리월 3장 | phase5→6 | Lv60 | 10 |

해금은 재료·모라·레벨과 해당 전투 승리를 대신하지 않는다. Lv60 재료 비경에는 기존 주인공 Lv55와 마지막 성장 선행 조건이 필요하다. 단순 완료 flag, 다른 저장의 영수증, 다른 갈래 END, 수락 기록 없는 사건으로 새 경로를 해금하지 않는다. 새 상태 필드나 과거 퀘스트 완료/보상 강제 처리는 없다.

## 전후 검증과 범위

원시 근거는 `observations.json`/`after/observations.json` 및 각 END 이름의 `.json.gz`에 있다. 압축 원장에는 starting/final save를 보존했다. `after/manifest.json`은 입력 파일 해시, DB 원문 END 행과 사건 정의, 검증 횟수, 조건 한계를 묶는다.

| 검사 | 수정 전 | 수정 후 |
|---|---|---|
| 여행자 리월 END 4개 | 해당 장 성장 선행 인정 | 기존 결과 유지 |
| 이세계인 리월 END 24개 | END 저장 후에도 해당 장 성장 선행 불인정 | 24개 모두 인정 |
| 이세계인 리월 03 END 8개 | 성유물 도전 불인정 | 8개 모두 인정 |
| 틀린 gate/수락/영수증 312개 | 새 helper 없음 | 312개 모두 거부 |
| 조회 직전·직후 save | — | 변형 0 |
| 이세계인 퀘스트 완료/claimed 강제 | — | 0, 진행중 상태 유지 |
| 표본 END 처리의 재고·모라 차이 | — | 0 |

이는 **각 DB END 경계의 기존 선행 사건·전투 기록을 명시적으로 준비한 네이티브 처리 검증**이다. 전체 이야기를 처음부터 이동·전투하며 진행한 28회 완주가 아니다. 실제 기존 `storyApplyEffects`로 해당 END 효과를 처리했고, 그 결과에 대하여 실제 성장·성유물 조회를 했다. 선행 사건과 전투 기록은 준비 조건이므로 실제 수집/전투 완주 증거로 인용하지 않는다.

수정 전 prepared fixture는 수락 entry를 END 노드로 선언했는데 기존 END handler는 이 필드를 확인하지 않았다. 수정 후 fixture는 소스의 실제 `chapter_enter` entry로 교정했고, 1장 수락 leaf도 실제 코드의 `NONE`으로 교정했다. 원래 before 원장은 덮어쓰지 않았으며 after 각 행에 entry 교정을 기록했다. 코드가 임의 수락 entry도 받아들이도록 느슨하게 만든 것이 아니다.

## 오셀 이전 준비의 실제 접근 조건

| 준비 수단 | 필요한 기존 선행과 비용 | 제한 |
|---|---|---|
| 일반 장비 +12 | +10 장비 한도 돌파: 3,000모라·보스 정수3·보스 핵1·수정5, 이후 기존 확률 강화 | 몬드 드발린/안드리우스 실제 승리로 재료 수급, 반복은 게임 내 48시간. +12 재고를 무료 기본 조건으로 가정하지 않는다. |
| Lv60·특성10 | 실제 리월 1~3장 END와 단계별 레벨·모라·재료 | END 연결 오류를 고친 것이며 육성 비용을 없애지 않았다. |
| 돌파/특성 Lv60 비경 | 천둥 연산 밀궁 `MAP_D163_LIANSHAN_FORMULA`, 태산부 `MAP_D163_TAISHAN_MANSION`; 주인공 Lv55와 리월3장 선행 | 입장 조건이 열리는 것과 그 편성으로 승리하는 것은 별개다. |
| 황금옥 성유물 | 실제 리월3장 END 인정 후 `MAP_LIYUE_GOLDEN_HOUSE` 타르탈리아 반복 도전 승리 | 게임 내 48시간에 1회. 획득 종류·품질 무작위. 야타용왕 결정은 별도 성유물 강화에 필요하며 기본 획득에는 필요하지 않다. |
| 제작 음식 | 기존 조리법·재료·runtime 조리비·시설, 실제 보유 음식 | 전투 중 일반 식사 불가. 다음 전투 버프는 이동 중 앞선 조우에서 먼저 소비될 수 있다. 시장의 실제 공급도 보장하지 않는다. |
| 전투 치료품 | 일반 물약·붕대·응급치료 세트의 구매/제작과 실제 보유 | 살아있는 대상, 행동 1회 사용. 물약은 본인 20%·전투당 별도 잠금, 붕대15%/치료세트25%는 대상당 공통 전투당 잠금. |

일반 음식은 현재 전투를 중간에 전부 회복시키는 수단이 아니다. 선도장/황금크리스피치킨 계열의 기존 만찬 버프는 ATK12%·치확5, 어부토스트/달빛파이 계열 방어 버프는 DEF8%이다. 전투 전 회복 음식에는 전투불능 대상 금지·직전 동일 회복식 반복 금지·1회 식사당 사람별 한 개 제한이 있다. 조리법은 기존 소유 조건을 따른다. 원시 DB의 조리비를 그대로 현재 조리비로 사용하면 안 되고 기존 runtime 견적을 따른다.

공통 연금 상점 원시 재고는 물약150모라/매일3개, 붕대45/매일5개, 치료세트180/3일2개다. 다른 기존 현장 공급과 제작은 별도다. 치료세트 4개를 가정한 전투 실험은 해당 재고/제작 준비를 명시해야 한다. 제작은 물약 박하2·슬라임응축액1·20모라, 붕대튼튼한천1·박하1·10모라, 치료세트튼튼한천2·박하2·물약1·25모라의 기존 조리법을 사용한다.

## 전투 수치와의 분리

후반 적 직접 피해의 최종 pivot35는 일반 전투에 적용한다. 오셀의 기존 `PROTECT_FORMATION` 기지방어는 정해진 8라운드 공격 예산에 새 방어 보정이 겹친 회귀가 확인되어, 해당 기존 목표에만 원래 K100을 보존한다. 성장 해금 오류를 고친 사실을 고레벨/고투자 오셀 전투가 모든 실제 진행 조건에서 안전하다는 증거로 사용하지 않는다. 오셀과 최종 전체 회귀의 실제 승패 원장은 전투 담당 자료를 따른다.
