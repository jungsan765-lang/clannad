# 0.16.22 현금 비용 후속 조정 최종 검증

현재 관련 36개 프로그램의 대응 상태는 모두 PASS다. 최초 고정 입력 실행은 **35 PASS / 1 FAIL**이며, 누락된 검사 기대값 1개를 승인 교정한 뒤 해당 프로그램 전체를 재실행해 PASS했다. 최초 36개가 한 번에 모두 PASS했다고 표시하지 않는다. 등록된 전체 181개를 재실행한 결과도 아니다.

실패한 검사는 `test_ascension_efficiency_v01613.cjs`의 Lv55 첫 3회 보너스 기대값이다. 승인된 지급량 1,932 × 2 = 3,864가 실제 지급됐지만 옛 1,843 × 2 = 3,686 기대값이 남았다. **3,686→3,864 literal 하나만** 바꿨으며 적·편성·승리 assertion·나머지 사례를 바꾸지 않았다. 교정 후 전체 6계약과 여행자/이세계인 두 루트 native 전투가 통과했다. 원 FAIL·당시 입력·원 테스트·exact diff·교정 PASS를 모두 보존한다.

- 최초 입력 475파일의 시작/종료 SHA 드리프트 0. 교정 재검사 입력 475파일도 전후 드리프트 0이다.
- 최초 입력과 현재 입력의 차이는 승인된 QA 1파일뿐이다. 예상하지 못한 차이는 0이다. 제품 236파일·실제 END fixture 28파일은 변경 0이다.
- 최초 검사·원자료 의존성 216파일은 최초 실행 전후 변경 0이다. 최종 대조에서는 위 QA 1파일 변경을 숨기지 않고 별도 기록한다.
- 최초 `per_gate`·`results.json` 36건과 원 `journal.jsonl` 36행이 일치한다. 압축 원출력 36개와 교정 재검사 1개의 길이·SHA를 대조했다.
- 서버·별도 브라우저 빌드·엔진 식별자 검사와 실제 소스/브라우저/import한 서버 대조 218/218이 통과했다. 빌드 4단계 원출력도 대조했다.
- timeout·signal은 0이다. 실행한 native는 최대 2개, 관측 메모리 최고 4,318,359,552bytes다.

원 35검사·32 PASS/3 FAIL은 상위 폴더에, 바로 이전 제품의 36/36 PASS와 100파일 봉인은 `../final_protect_formation/`에 그대로 보존한다. 이전 봉인 SHA와 100파일 원문을 이번에 다시 대조했다. 이 후보는 그 이후 성장 보상·요구량과 릴리스 노트만 조정한 것이다. 이전 제품의 전투·회복·리월 END 판정은 그대로다.

최초 실행 중 해당 실패 프로그램이 이미 종료한 뒤, 담당자가 승인된 QA 교정을 잠시 적용했다가 정확한 원 SHA로 복원한 사건은 `transient_approved_qa_event.json`에 기록한다. 시작/종료 SHA 일치는 실행 중 어떤 파일도 한순간도 바뀌지 않았다는 주장으로 사용하지 않는다. 이후 최초 실행 종료와 원자료 대조를 마친 다음 교정 파일을 적용하고 따로 재검사했다.

`original_run_verification.json`은 최초 35/36, `qa_correction/recheck/`는 교정 1개의 실제 재검사, `final_verification.json`은 둘을 구분한 최종 대응 상태다. 입력과 승인된 차이는 해당 manifest와 `qa_correction/approval_and_delta.json`에 있다. `run.stdout`은 진행 스트림이며 완료 근거는 원 결과·압축 원출력이다. `MANIFEST.json`은 게시 증거를 봉인한다. 비압축 임시 `.log`, `active` 기록, `__pycache__`는 게시 대상이 아니다.

효율 계약의 현금 보정은 합법 부의 꽃 지급 1회 120초를 가정한 민감도 계산이며, 같은 계정의 모라 재수급 전체를 실제 측정한 자료가 아니다. 성장 담당이 보존한 첫 Lv55 최종 돌파 접근 경계의 0승/1패도 별도 실패 자료이며, 최고 단계 25/50승 수량을 첫 Lv55 편성의 무조건 승리 보장으로 읽으면 안 된다.

0.16.21의 177프로그램·175 PASS/2 입력 부족 FAIL은 그대로 보존한다. 정확한 옛 DB가 없는 저장 검사와 원본 서술행이 없는 편집 분리 검사 2건은 이번에 재검증하지 않았고 해결·PASS로 표시하지 않는다. 실제 원격 workflow와 보호된 authored DB 전체를 이 로컬 검사로 검증했다고 주장하지 않는다.
