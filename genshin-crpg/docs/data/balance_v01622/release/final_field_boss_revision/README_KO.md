# 0.16.22 필드보스 공략 수정 — 최종 적용 소스 검증

새로 시작하는 무상의 바람·뇌전·바위·얼음 전투에서, 부활 공략을 실패한 뒤 본체만 다시 쓰러뜨려 승리하던 우회를 막았다. 공략을 해결할 때까지 부활 단계가 반복된다. 신규 전투는 `behaviorRevision: 3`을 쓰고, 이미 저장된 무표시·버전 2 전투의 기존 한 번 부활 정책은 유지한다.

이 폴더는 앞서 봉인한 `final_cash_margin` 이후의 추가 검증이다. 앞선 성장·방어·회복·리월 진행 수정 6개 소스는 그대로다. 추가 제품 변경은 `source/runtime_field_bosses.js`와 승인된 `content/release-notes.json` 문구뿐이다. 적 능력치·보상·돌파 요구량은 이 추가 수정에서 바꾸지 않았다. 이전 봉인 폴더를 수정하지 않았다.

현재 등록된 전체 검사는 182개지만 이번에는 영향 있는 11개만 실행했다. 앞선 36개 회귀와 0.16.21의 177개 기록은 별도로 보존했다. 과거 두 입력 공백(`test_save_v01344.cjs`, `test_release_isolation_v01513.py`)은 이번에 재검사하거나 통과로 바꾸지 않았다.

## 공략과 다른 시스템 연결

무상 4종 각각 공략 실패를 두 번 반복한 뒤, 세 번째에 필요한 공략을 실제로 수행하여 정상 승리 정산까지 이어지는지 세 엔진 모두 검사했다. 부활 중 저장·불러오기, 구버전 정책 유지, 소환체 정리와 제한, 면역 및 피해 접근 조건도 포함한다.

바람 핵에는 실제 원거리·전장·대공 범위가 전달된다. 향릉의 실제 누룽지 카드와 END 불 피해가 핵에 닿는 계약을 포함했고, 그 범위가 중첩 반응 피해나 다음 공격으로 잘못 새지 않는지도 검사했다. 부활을 반복해도 보상·임무 승수·보스 기록·횟수 제한은 마지막 정상 승리 한 번만 집계한다.

54개는 새 공략 계약의 세 엔진 검증이다. 218개에는 이 신규 부활 계약이 없으므로 두 수치를 구분한다. 단계 경계 검사는 큰 피해량을 직접 넣는 조건을 명시한 검사다. 전체 실전 난이도·승률·파밍 시간이나 캐릭터 획득 가능성을 그 결과로 보장하지 않는다. 별도 실제 대응 편성 측정은 회복 담당 원장에 있다.

## 입력과 원문 보존

최초 11개 실행의 입력 450개, 제품 입력 236개, 보조 테스트·헬퍼 214개는 종료 시점에 모두 변경 0이다. 최초 원문 로그 11개와 원래 journal 11행을 대조했다. 실패 원문도 삭제하거나 통과로 바꾸지 않았다. 이후 승인된 QA 파일 1개만 변경되었고, 교정 재검사의 입력 450개는 실행 전후 변경 0이다. 제품 변경은 0이다.

새 3엔진 54개 실행의 입력 784개는 실행 전후 변경 0이다. QA·어댑터·실제 브라우저 119개 스크립트 및 데이터·실제 서버 엔진을 포함한다. 이후 교정된 옛 QA 1개는 이 실행 중에는 변경되지 않았으며 승인된 사후 차이로 따로 기록했다. 원 DB 파일과 각 엔진의 DB 객체도 변경되지 않았다.

- `original_run_verification.json`, `input_manifest_after_original.json`: 최초 10 PASS / 1 FAIL 및 당시 변경 0의 증거.
- `qa_correction/`: 교정 승인, 원본·수정본, 정확한 diff, 전체 26개 계약 재실행 원문과 전후 입력.
- `strategy_three_engines/`: 실제 세 엔진의 각각 18개 계약 보고서·gzip·원문 로그·전후 입력.
- `build/`: 실제 빌드와 218개 검사 원문·입력 출처.
- `final_verification.json`: 최종 합산 상태와 승인된 QA 사후 차이를 함께 기록.
- `before_revision3/`, `final_revision3/`: 이번 제품·QA 변경의 전후 파일. 전체 적용 패키지가 아닌 감사용 복사본.

보스 담당의 최초 준비 오류와 정상 누룽지 핵 파괴 후 QA가 비어 있는 핵을 읽은 오류는 `docs/data/balance_v01622/field_boss_strategy/`에 남아 있다. 이 폴더의 `verification_preparation_failure.json`도 증거 집계 스크립트의 AST 처리 오류를 보존한 것이다. 제품 오류로 숨기거나 통과 결과를 대체하지 않았다.

이전 `final_cash_margin`의 116개 봉인 파일 및 `final_protect_formation`의 100개 봉인 파일을 전부 SHA256 대조하여 변경 없음을 확인했다. 진행용 `.stdout`은 상태 스트림이며, 완료 증거는 프로그램별 종료 코드와 원문 gzip, JSON 계약 보고서다. 로컬 `__pycache__`는 게시 및 MANIFEST에서 제외한다.
