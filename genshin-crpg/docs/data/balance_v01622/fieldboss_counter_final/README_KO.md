# 최종 필드보스 공략 조건 비교

0.16.22의 새 전투 정책 `behaviorRevision: 3`을 네이티브 실행기에서 4조건으로 측정했다. 적절한 공격 수단 없이 회복·보호막만으로 버텨도 부활 단계를 건너뛰어 승리하지 못하는지 확인한 최소 비교다. 제품 수치·음식·숙박·재고를 추가로 변경하지 않았다.

## 같은 조건의 두 편성

여행자·종려·진은 동일하게 두고 다이루크 C0와 모나 C0를 교체했다. 전원 같은 레벨, C0, 기본 특성은 합법 상한의 65%, 동일 등급의 제작 무기·보강 가죽갑옷·치유사의 브로치다. 뇌전은 Lv20/+3, 얼음은 Lv30/+6이다. 성유물·음식·숙박 없이 초기 완전 체력 한 번으로 시작하며 seed는 717이다. 장비 12개와 실제 특성·체력·파쇄 특성을 원장에 기록했다. 이 편성은 선언한 보유 장비를 갖춘 진단 조건이며 자연 획득 시간을 측정한 것이 아니다.

실제 다이루크의 `ARMOR_BREAK`는 25다. 따라서 얼음의 대응 편성은 **불 또는 파쇄 수단을 보유한 편성**이며 불만의 독립 효과를 입증한 비교는 아니다. 모나 편성은 전원 `ARMOR_BREAK: 0`이고 불·얼음·풀 캐릭터가 없어 두 보스의 해당 공략 수단을 모두 갖추지 않았다.

|---|---|---|---:|---:|---|---:|---:|

| 무상의 뇌전 Lv20 | 모나, 해당 공격 수단 없음 | 실행 한도 정체 | 401 / 400 | 82회 | 성공 없음 | 100% | 0 |
| 무상의 얼음 Lv30 | 다이루크, 파쇄 25 | 승리 | 18 / 15 | 2회 | 냉기 핵 4타 달성·핵 파괴 | 100% | 0 |

HP는 보상 처리 전의 실제 전투 actor 합계 비율이다. 두 미대응 조건은 전투불능 패배가 아니라 살아 있는 채 전투가 끝나지 않아 진단 실행기의 400입력 한도에 도달했다. 원시 실행기의 `losses: 2`는 승리가 아닌 두 조건을 합한 옛 필드명이다. 실제 패배 0·정체 2로 구분한 수치는 `summary.json`의 `actualDefeats`와 `inputLimits`를 사용한다. 실행 오류는 0, 프로세스 종료 코드는 0이다.

두 승리 편성도 부활 실패를 겪었다. 뇌전은 13번째 부활 준비를 프리즘 파괴로 저지했고, 얼음은 세 번째 냉기 핵에서 4타를 달성했다. 방어·치유 지원을 둘 둔 편성이므로 오래 버틸 수 있지만 대응 공격 수단 없는 편성에는 전투 완료와 보상이 없었다. 이 결과로 같은 레벨의 모든 지원 편성에 반드시 상처가 남는다고 주장하지 않는다.

## 검증 범위

이 실행기는 기존 `H.play`의 일반적인 Q/E/기본 공격 우선순위를 그대로 사용한다. 표적은 실행기와 동료의 기존 AI가 선택한다. 별도의 수동 예고 대응이나 최적 공략 순서를 넣지 않았다. 따라서 **공략 수단 보유 여부가 실제 처치에 영향을 준다는 검증**이며 수동 조작의 재미나 모든 보스의 균형을 완전히 검증한 결과는 아니다. 각 조건 seed 한 개만 측정했으므로 이를 전체 승률로 해석하지 않는다.

기존 presentation 관측 방식과 입력당 3초·재진입/결과 6초를 적용하면 뇌전 대응 승리는 약 12.13분, 얼음 대응 승리는 약 4.55분이다. 표시 2배속의 기존 추정 방법이며 이동·장비 획득·통신·사람의 실제 조작 지연은 측정하지 않았다. 방어 위주의 일반 AI 편성이 오래 걸렸다는 관측이지 최적 공략 소요 시간은 아니다.

## 원장과 입력 봉인

- `native.json.gz`: 전체 네이티브 원시 JSON을 바이트 그대로 복원하는 유일한 게시 원장. 압축 전 44,091,979바이트, 압축 후 1,481,458바이트.
- 원시 SHA256: `79fe3bd2a217742233c7557cad6a858048e8a6870d2655db00f47f86446d3b85`
- gzip SHA256: `53598a4a2907b00439f3a96b24e5cef9ca92412f890e467d86be3550bb770a7c`
- 네이티브 지문: `2a143c669f2e73ee1921e255ae795a9088957da75acafa076de2f0264faf11bc`
- 필드보스 제품 SHA256: `dab1e585bf696116d05affbcc1ceb58420d5fc23144ca0ad85d7742f1dd4b04b`
- `input_manifest.json`: 실행한 index·118개 네이티브 스크립트·presentation·DB의 121개 실제 파일을 고정한 입력 목록. 심볼릭 링크 0.
- `input_verification.json`: 실행 후 제품/복제본 121입력 차이 0, 원시 실행기 해시 120개 일치, 독립 재계산 지문 일치, 도구/원본 helper 차이 0, 기존 회복 원장 80파일 변경 0, gzip 복원 바이트 일치.
- `summary.json`, `native.log`, `cases.json`: 결과 요약·프로세스 출력·조건. `audit_fieldboss_counter.cjs`는 기존 보스 실행기에 관측/경로만 추가했고, 복제한 `audit_protagonist_v01618.cjs`의 전투 정책은 변경하지 않았다.

재실행할 때는 `input_manifest.json`과 같은 입력을 갖춘 소스 경로를 사용한다. 아래 명령은 새 출력 경로로 실행하며 기존 봉인을 덮어쓰지 않는다.

```bash
node docs/data/balance_v01622/fieldboss_counter_final/audit_fieldboss_counter.cjs \
  --source-root /path/to/identical/source-snapshot \
  --cases docs/data/balance_v01622/fieldboss_counter_final/cases.json \
  --out /tmp/fieldboss-counter-rerun.json
```

압축 원장의 원문은 다음과 같이 복원할 수 있다. 복원한 파일의 SHA256이 위 원시 SHA256과 같아야 한다.

```bash
gzip -dc docs/data/balance_v01622/fieldboss_counter_final/native.json.gz > /tmp/fieldboss-counter-native.json
sha256sum /tmp/fieldboss-counter-native.json
```
