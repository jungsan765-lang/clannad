# 실제 세 엔진 검증 범위

이 폴더의 최종 결과는 동결한 소스를 별도 검증 작업 폴더로 복사하여 실제 정적 배포본과 실제 `server/generated/engine.mjs`를 만든 뒤 기록한다. 원본 DB와 assets는 변경하지 않는다. 정적 배포본의 실제 런타임 스크립트를 Node VM에서 실행하므로 그래픽·화면 배치 검증은 아니다.

동일한 나선 오류 계약 테스트 본문을 소스·브라우저 배포 스크립트·서버 ESM에서 실행한다. 기존 캐릭터 효과 48개, 효과 귀속 18개, 일일보스 전투 정책 21개, 기본 공격 사거리 5개 계약도 같은 실제 엔진에서 재검사한다. 전투불능 정산 경계는 적 HP를 0으로 놓는 통제 fixture이며 실제 플레이 승률이나 자연 계정 육성 시간으로 해석하지 않는다.

`compatibility_before_v01624/`는 0.16.25의 검증에 사용한 일곱 원본 모듈과 이후 수정된 나선·진형의 실제 이전 소스를 따로 보관한다. 기존 0.16.24/0.16.25 검증 원본은 수정하지 않는다. 이 아홉 모듈 오버레이로 기록된 0.16.24 엔진 fingerprint를 재구성해 기존 저장 전투 동작을 비교한다. 성장 모듈의 0.16.24 원본은 원래 일곱 모듈에 포함되어 있다.

`preliminary2source/`는 세 번째 관련 오류를 발견하기 전 두 소스만 반영한 초기 빌드 기록이다. 최종 결과에 포함하지 않으며 세 엔진 계약 검사도 실행하지 않았다. 최종 빌드와 결과는 완료 뒤 별도 폴더에 기록한다.

## 최종 결과

| 엔진 | 나선·초기 순서 신규 계약 | 기존 효과·저장·공격 계약 | 합계 |
| --- | ---: | ---: | ---: |
| 소스 | 35 / 35 | 92 / 92 | 127 / 127 |
| 브라우저 배포 스크립트 | 35 / 35 | 92 / 92 | 127 / 127 |
| 서버 ESM | 35 / 35 | 92 / 92 | 127 / 127 |

총 381개 계약을 통과했고 실패는 0개다. `final4source/summary.json`과 각 엔진 원본 결과·stdout·stderr를 보관한다. 원본 입력 1,905개와 실제 정적 배포 파일 1,889개의 해시·크기도 맞았다. 120개 런타임 모듈은 소스/브라우저 바이트가 같고, 서버 코드는 빌더가 선언한 CommonJS 치환을 제외하고 소스 전체와 일치한다. 실제 브라우저·서버의 64개 런타임 DB 표도 같다.

공유 배포 엔진 fingerprint는 `engine3-9161b50c708ba80f3d770774c9ba5ffa9132c5efe8e6d62369c9324c10426d2d`이며 서버 ESM SHA256은 `d0ed796f75cbf115bc388f8eb5f30776e3b12fd7014ba1c8ff109b0c7ab1111c`다. 소스 진단 helper의 fingerprint는 별도 해시 방식이므로 배포 엔진 식별자와 문자열이 다르다. 실제 모듈/DB 일치와 배포 브라우저·서버 식별자 일치는 별도로 검증했다.

재현은 동결된 저장소를 별도 폴더로 복사하고 `python tools/build.py`, `python tools/build_server.py`를 실행한 뒤 `node --max-old-space-size=640 --expose-gc tools/audit_abyss_engines_v01626.cjs dist <새 결과 폴더>`를 실행한다. 새 결과 폴더를 써야 기존 원자료를 보존한다. 빌드 입력 검증은 `python docs/data/abyss_fixes_v01626/engines/verify_build.py --root <원본 저장소> --snapshot-root <별도 빌드 저장소> --out <결과 폴더>`로 재현한다.
