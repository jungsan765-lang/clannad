# 0.16.26 나선비경 오류 수정 · 실제 전투 변경 전후

같은 21개 조건을 0.16.25와 최종 수정본에서 각각 실행했다. 총42회 층 도전·87개 방이며, 수정 전50개 방과 수정 후37개 방을 구분한다. 1·2번 방에서 주인공이 실제 전투불능이 된 뒤 다음 방으로 넘어간 13건은 수정 후0건이다. 해당 오류를 사용하던9회 도전은 실제 `DOWNED`로 끝났다. 과거 전투불능 없이 클리어했던6회는 그대로 클리어했다.

캐릭터·층별 각인·장비·성유물 조건과 적 HP/ATK/DEF/SPD 수치는 그대로다. 첫 행동 순서의 점수에 기존 최종 SPD가 반영되도록 고쳤으며 새 난수를 뽑지 않았다. 이번 실제 전투의 진형은 모두 `DOUBLE_LINE`(연계 진형)이다. 추가로 발견된 기동 진형의 첫 SPD 보정은 별도 동작 계약에서 검사하며 이 전투 표를 기동 진형의 결과로 확대하지 않는다.

실행 오류·입력 상한·입장 불가 판정은 변경 전후 모두0건이다. 클리어 감소6건은 주인공 전투불능으로 연전을 끝낸 결과다. 음식·장비·공격·치유 수치를 추가 너프한 결과가 아니다. 마지막3번 방에서 동료가 이기는 승리와 1·2번 방의 다음 방 진행 오류를 구분한다.

나선 종료 뒤 일반 승리의 주인공10% 회복 처리는 남아 있다. 따라서 저장 HP가 양수이고 최종 저장 KO 배열이 비어 있어도 `DOWNED`가 될 수 있다. 실제 정산 전 배우 HP·로그·`nativeProtagonistKO`를 기준으로 검사했다. 수치가 양수로 보인다는 이유로 무전투불능 승리로 분류하지 않았다.

## 최종 속도와 난수 확인

12층 명함·공격/치명 음식3종·시드717의 첫 라운드 적 두 명은 최종SPD가 각각50인데 예전 순서 점수는 각각35였다. 이전 템플릿SPD28+기존 주사위7로 계산한 값이다. 수정 후 각각57(50+같은7)이 된다. 아군의 첫 점수는 그대로다. 모든 수정 후 방에서 적의 `순서 점수−최종SPD`가 기존 주사위 범위0~9임을 확인했고, 각 조건의 첫 방은 변경 전 주사위와 정확히 같았다.

이번 Lv60 장비 fixture의 아군은 모두 적보다 빠르므로 이 표에서 SPD 보정만으로 상대적인 순서가 바뀌었다고 주장하지 않는다. 첫 점수가 실제 최종 속도를 사용한다는 근거와 실제 KO 연전 종료의 효과를 구분한다.

## 입력과 검증

- `cases.json`: 7개 편성·준비 조건, 전투 시드717/4242/9031. `fixed_` 조건은 성유물 선택 시드717을 고정하고 전투 난수만 바꾼다.
- `baseline/`와 `final4/`: 당시 runner·사례·입력120소스 해시·원시 전투 gzip·간단 결과. 같은 장비·자연 성유물 및 추첨 기록·특성·돌파·운명의 자리·운영자 설정·첫 방 실제 배우 수치·첫 음식 소모·전투 시드를 직접 대조했다.
- `baseline_existing_audit_parity.json`: 기존0.16.25 공식 원자료18회와 새 기준선의 장비/성유물/HP/KO/피해/회복/소모/결과/라운드/공개 입력이 일치한다. 고정 성유물 풀돌3회는 이번 기준선에 추가한 조건이다.

최종 runner의 입력 검사부는 승인된 진형·성장·운영자 첫 순서 수정도 허용한다. 운영자 소스는 명시적으로 받은 승인 SHA로만 기존 봉인 값을 대체하고 나머지5개 핵심 소스는 그대로 강제한다. 수정 전 runner는 보존했으며, 실제 fixture·음식·난수·행동·요약·원시 기록 실행부 전체가 코드상 정확히 일치함을 검증했다. 승인4개 소스는 시작에 기록한120해시와 종료 실제 파일에서 다시 대조했다.

## 재현

현재0.16.26 소스에서 최종 기록을 재현한다. 원자료 폴더를 덮어쓰지 않도록 출력 경로를 별도로 지정한다.

```bash
node --expose-gc --max-old-space-size=640 docs/data/abyss_fixes_v01626/native/final4/runner.cjs \
  --root "$PWD" --phase final \
  --admin-order-source-sha 838f10fab7738ece5ad232ad606cbf2ed952bf1098416132e5e9a5ddc6db015f \
  --cases docs/data/abyss_fixes_v01626/native/final4/cases.json \
  --seeds 717,4242,9031 --out /tmp/crpg-v01626-native-replay

python3 docs/data/abyss_fixes_v01626/native/verify_native.py
```

변경 전 재현은 `baseline_runtime.tar.gz`를 임시 루트에 풀고 위 DB gzip을 `content/db.json`으로 복원한 다음 `baseline/runner.cjs --root <임시 루트> --phase baseline`을 사용한다. 원자료와 스크립트의 해시는 `MANIFEST.json`에 봉인했다.

`final2/`에는 나선·진형2소스 직후의 중간21회와 당시 비교를 보존했다. 최종4소스에서21회를 새로 실행한 `final4/`가 최종 근거이며, 중간21회는 위42회에 합산하지 않는다. `final2_to_final4_parity.json`은 같은21회에서 최초 순서·최종 속도·배우 수치·공개 입력·실제 KO/피해/회복/소모/결과가 중간 단계와 최종 단계에서도 그대로임을 확인한다.

## 해석 범위

초기 보유·선행 층 기록·Lv60/돌파6·특성10·+12 장비·+5 성유물·음식 재고를 지급한 진단 fixture다. 성유물 수치는 실제 추첨에서 처음으로 적합한 것을 골랐고 전투는 주인공의 공개 조작과 실제 동료AI로 했다. 방 사이 HP와 유한 재고는 그대로 이어지며 매 방 완치·무료 부활·숙박을 주입하지 않았다. 자연 계정의 수급 기간·전체12층 등반·모든 편성의 난도/승률이나 육성 경제 전체를 재검증한 결과는 아니다. CPU 실행 시간을 사람이 플레이한 시간으로 사용하지 않는다.
