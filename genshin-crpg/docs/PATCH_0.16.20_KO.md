# 0.16.20 · 회복 요리의 재료 수고와 실제 효율

## 무엇이 잘못됐고 무엇을 바꿨나

이전0.16.17은 조리비만2~4모라로 구분했고, 어려운 재료를 쓰는 음식의 옛 회복량을 유지했다. 그 결과 재료2개를 쓰는 단순 구이와 가공·다종 채집·낚시가 필요한 음식의 실제 효율이 역전됐다. 대상 레벨에 따른 회복 성장식은 작동했지만, 식재료를 구하는 수고를 음식별 회복 원액에 반영하지 못한 설계였다.

기존 회복 음식45종 중39종의 회복 원액을 조정했다. 새 요리·재료·부활·화면·시스템은 만들지 않았다. 달걀 프라이90·닭고기 스튜180·스테이크110·침옥 차90은 초반/단순 기준식으로 유지했다. 현재 실제 공급이 없는 글루포프 호밀빵과 베리 아이스크림도200을 유지했다. 조리법의 재료·수량·결과물·조리비와 해금은 그대로다.

## 사용자가 체감할 차이

같은 대상·레벨의 회복 배율을 적용하기 전 비교다. 실제 회복은 대상 레벨/돌파에 맞춰 성장하고, 부족한 HP보다 많이 회복할 수는 없다.

| 음식 | 이전 → 변경 회복 원액 | 이유 |
|---|---:|---|
| 몬드 생선 구이 | 100 → 120 | 생선1개 기준식 |
| 생선 면 | 170 → 360 | 생선2개에 금어초·쌀도 필요: 구이 두 끼240보다 한 끼360이 유리 |
| 채식 전복 | 170 → 360 | 실제 재료는 송이버섯·금어초: 직접 채집 수고를 반영 |
| 몬드 감자전 | 220 → 340 | 솔방울과 잼 가공·다종 재료 수급 |
| 삶은 검정 농어 | 260 → 440 | 낚시·채집·구매 재료를 함께 준비 |
| 꽃게알 야채찜 | 230 → 400 | 사냥 재료의 햄 가공과 다종 재료 |

음식별 실제 이름은 아래 확정표를 따른다. 대상마다 기본 HP와 장비가 달라 같은 음식도 HP 비율이 다르다. 5성이나 HP 장비가 많은 캐릭터에게 같은 회복 비율을 보장하는 패치가 아니다. 바바라 특제의 기존10% 보너스, 생명의 계약 흡수, 연속 동일 음식 제한, 전투불능 대상 식사 거절을 유지했다.

## 상점·숙박·시장을 같이 맞춘 범위

강화한 완성품을 옛 가격에 NPC에게 사면 직접 준비할 필요가 줄어들므로 실제 상점 가격을 회복 원액에 비례해 올렸다. 감자전105→163, 버섯고기말이120→150, 세계 평화180→315, 버섯피자65→130이다. 달걀35·스튜80은 유지했다. 실제 판매8행/6종에서 구매 차감과 매각을 실행해 확인한다.

판매가 상승이 NPC 매각 상한까지 올리지 않도록 기존 실매각값8/20/26/30/45/16을 보존했다. 재료와 음식의 기존NPC 매각값·시장 진입·수수료·수급·숙박 계산은 그대로다. 사용자 간 시장 가격은 플레이어가 정하므로 모든 시장 가격에서 같은 경제 효율을 보장하지 않는다.

전부 구매하는 새우 요리처럼 비싸지만 현장에서 쓰기 편한 음식도 남아 있다. 모든 음식을 모든 레벨에서 숙박보다 싸게 만들었다고 주장하지 않는다. 재고0에서 직접 모으는 시간, 이미 모아둔 재료의 식사, NPC 완성품 구매, 숙박 왕복을 분리했다. 준비 중 전멸하거나 식사 후 HP가 덜 차는 조건을 숙박과 같은 완전회복 비교로 쓰지 않는다.

기존 나선 음식 숫자는 대상 자신의 레벨/돌파 및 실제AUTO 선택의 일반/특제 회복량을 표시하도록 좁게 고쳤다. 화면 배치·버튼은 유지했다.

## 변경 범위와 저장

제품은 `runtime_economy.js`, `runtime_growth_v01522.js`의 음식 설치 훅1줄, `app_abyss.js`의 기존 표시 숫자만 바꿨다. 음식별 canonical 행은 런타임의 복제DB에 설치한다. 공용 입력DB·원격원문DB·assets·index/styles·전투·성장 요구량/보상·숙박비는 유지했다. 같은DB에서 여러 실행기를 만들거나 저장을 재로드해도 가격이 중복 상승하지 않는다.

남은 음식 재고는 이번 기존 음식 수치를 사용한다. 이미 완료한 구매/식사 영수증과 동일 요청 재시도는 과거 결제를 재계산하지 않는다. 임의의 과거 가격 보상이나 기존 재고 회복량 보존 시스템을 만들지 않았다.
