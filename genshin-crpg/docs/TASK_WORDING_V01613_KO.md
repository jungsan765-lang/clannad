# 0.16.13 캐서린 의뢰의 이름과 목표 설명

사용자가 말한 “스토리”는 임무 내용이다. 새 이야기, 대사, 사건, 임무 시스템을 만들지 않는다. 이번 변경은 기존 의뢰의 표시용 이름·목표 설명·용도 분류만 다룬다.

## 화면에서 달라지는 내용

| 대상 | 표시 방식 |
| --- | --- |
| 24개 활동 안내 | `모험 길잡이`. `경험치 비경으로 레벨링`을 `비경에서 쌓는 경험`으로 변경하고, 행동을 설명하는 본문은 유지한다. |

연속 활동 의뢰의 본문은 실제 기존 목표에 `수락 후 집계, 캐서린에게 보고`를 짧게 붙여 집계 시작 시점과 보고 방법을 설명한다. 수락 전의 전투나 재료 수집을 소급해서 세는 변경은 없다. 원래 기존 완료 기록을 인정하던 활동 안내는 그 안내 문장을 유지한다.

## 수락 기록을 보존하는 구현

- `runtime_task_learning_catalog_v0169.js` 끝의 `displayWordingsV01613`은 의뢰 ID별 표시용 메타데이터다. `chains`, `snapshotV0169`, `snapshotV01611`과 172의 선행 조건 정의는 바꾸지 않는다.
- `runtime_tasks_v0167.js`의 `taskPresentation()`이 이름·분류·설명을 만든다. `commissionEntries()`는 행과 정의를 복사해 화면에 보여 주며, 이미 수락한 목표의 저장 정의를 덮어쓰지 않는다.
- 이미 수락한 의뢰의 목표 본문은 그 수락 정의에서 가져온다. 새로운 현재 조건으로 바꿔 보여 주지 않는다. 첫 접수 연습은 기존 이행 완료 처리가 적용된 실제 접수·보고 절차를 설명한다.
- 동적 임무 DB의 표시용 제목도 바꿔 진행 중 목록과 길잡이에서 과거 제목이 다시 나오지 않게 한다. 배포 DB 파일은 변경하지 않는다.
- 임무 revision은 172를 유지한다. 목표 횟수, 보상, 선행 조건, 일일·주간 갈래, 의뢰 동시 수락 상한 5개는 유지한다.
- 저장 안의 역사적 원문 `경험치 비경으로 레벨링`은 검증을 위해 그대로 남는다. 플레이어에게 보이는 제목에는 사용하지 않는다.

## 검사

`node tests/test_task_wording_v01613.cjs`가 다음을 확인한다.

1. 169·171·172 목표 정의와 세 갈래 그래프의 변경 전 SHA-256이 유지되는지.
2. 새 계정은 접수 연습부터 시작하고, 실제 수락·보고 후 다음 의뢰가 열리는지.
3. 경험치 안내의 새 제목·2승 목표·계시의 꽃 설명이 표시되며 목표 미달 보고가 거부되는지.
4. 현재 수락 정의와 보상이 목록 표시·재시작 후 그대로인지.
5. 과거 수락 정의의 편성·난이도·횟수 설명을 보존하는지.
6. 전체 288개에 분류가 있으며 납품 조건과 기존 일반 의뢰의 내용이 유지되는지.

새 이야기나 새 임무는 추가하지 않았으므로 기존 이야기 작성자의 내용도 그대로다.
