# 0.15.6 패치 노트 (알파 테스트) — 제작 버튼 · 운명의 자리 재사용 대기 · 장비 렉과 정렬 · 리월 지도

기준: 0.15.5(`a1edcb8`). 사용자가 알파 테스트 중에 화면과 함께 짚은 것들이다.

## 바뀐 내용

### 제작 · 강화 화면의 버튼 (`app_forge_v0148.js`)
- 사용자: 「각 시설 준비 제작이 안돼.(제작 버튼이 안나오는 버그인듯 전용무기에도 같은 문제 있었음)」.
- 원인: 작업장 화면(타일과 오른쪽 상세)은 고른 항목의 버튼을 원래 카드에서 꺼내 상세 아래(foot)로 옮긴다. 버튼을 고를 때마다 카드에서 다시 찾았는데, 처음 보여 줄 때 이미 옮겨져 버려진 foot 안에 있어서, 다른 항목을 눌렀다가 돌아오면 「이 시설에서 준비」 · 「공동 제작 완료」 · 「제작」 · 「강화」 버튼이 없었다. 요리와 강화 · 돌파 목록도 같은 코드를 쓴다. 강화 목록은 다음 단계 설명(+6 → +7 · 성공 확률 · 비용 · 부족한 재료)도 같은 이유로 사라졌다.
- 이제 버튼과 설명을 항목마다 한 번 꺼내 두고 다시 고를 때 그대로 붙인다. 공동 제작의 규칙(`runtime_places_joint.js`)은 그대로다.
- 확인(로컬 서버, 실제 클릭): 바그너 · 대장간에서 만국 항해용해도 → 황금 호박 프로토타입 → 다시 만국 항해용해도에서도 두 버튼이 있다. 대장간에서 준비 → 연금 · 약제 보급처에서 준비 → 「공동 제작 완료」로 만국 항해용해도를 만들었다(수정덩이 3 · 공명 수정 2 · 220 모라가 한 번만 빠짐). 강화 · 돌파에서 녹슨 활 +6 → 여명신검 → 녹슨 활에서도 설명과 「강화」 버튼이 남는다.

### 운명의 자리 재사용 대기 (`runtime_constellations_v01411.js`)
- 사용자: 「이세계인 2돌파하니까 그냥 Q스킬 무한으로 쓰던데 이것도 고치고」.
- 원인: 효과 목록을 만들 때 각 효과에 자리 번호(1/2/4/6)를 `n`으로 붙였는데, 「재사용 대기 N턴 감소」(`cd()`, 중운 2번째 자리의 `teamCast`)도 줄일 턴 수를 `n`에 담고 있어서 덮어써졌다. 그래서 1번째 자리 효과만 맞고, 2 · 4 · 6번째 자리 효과는 2 · 4 · 6턴씩 줄였다. 이세계인 2번째 자리: 함께하는 일격 3 → 1(재사용 대기 1은 다음 차례가 시작할 때 0이 되므로 매 턴 사용).
- 이제 효과 자신의 값은 `cut`으로 남기고(`n`은 전투 기록이 자리 이름을 찾는 데 계속 쓴다) 줄이는 곳은 `cut`을 쓴다. 덧붙여 운명의 자리로 줄일 때 원소폭발은 2보다 작아지지 않고(바로 다음 차례에 다시 쓸 수 없음), 이미 더 짧은 재사용 대기를 늘리지도 않는다.
- 결과(같은 측정): 이세계인 C2 원소폭발 3 → 2(전투에서 C0은 3턴마다, C2는 2턴마다), 케이아 C6 4 → 3(전에는 1), 미카 C4 5 → 4(전에는 1), 다이루크 C6 원소전투 스킬 3 → 2(전에는 1), 소 C2 5 → 4(전에는 3). 여행자 바람 C2 · 바위 C4와 중운 C2(파티 전체)도 이제 1턴씩 줄인다(전에는 2 · 4 · 2턴). 1번째 자리 효과(바바라 · 디오나 · 달리아 · 타르탈리아 · 운근)는 원래 맞았다. 운근 C1은 원소전투 스킬 2 → 1로 매 턴 쓸 수 있는데, 효과 글 그대로이고 원소폭발이 아니므로 두었다.

### 장비 고르기 렉 (`runtime_party.js`, `runtime_market.js`)
- 사용자: 「그리고 장비 아직도 렉 있어」. 0.15.4의 서버 쪽 개선 뒤에도 남은 렉이다.
- 원인: 장비 고르기 창(캐릭터 화면의 칸)은 후보 장비마다 장착한 뒤 능력치를 미리 계산하는데(`equipmentPreview`), 그때마다 게임 엔진을 새로 만들었다(저장 복사 두 번, 저장 전체 검사, 이야기 색인). 한 번에 약 0.3초라 같은 종류 장비가 많을수록 창이 늦게 열렸다(한손검 61개: 18초). 상점의 장비 비교(`shopEquipmentPreview`)도 같았다.
- 이제 지금 엔진을 바탕으로 저장 사본만 따로 가진 가벼운 엔진에서 계산한다(같은 규칙 · 같은 내용). 같은 숫자인지는 시험에서 새 엔진과 비교한다. 측정: 한손검 41개 13ms(node), 브라우저에서 활 35개 창이 58ms에 열림.

### 장비 정렬 (`app_gear.js`, `inventory_presenter.js`)
- 사용자: 「장비 좋은거랑 자기 전무를 맨 위로 올려서 보여지게 해. 기원 하면서 많이 나오면 장비 찾기도 힘들어.」
- 장비 고르기 창: 그 캐릭터의 전용 무기가 맨 위(「전용 무기 · …」 표시), 그다음 지금 낄 수 있는 것, 그 안에서 별 등급 → 강화 → 오르는 능력치(공격력 · 방어력 · 체력 · 치명타 · 속도의 가중합) 순. 낄 수 없는 것(레벨 · 무기 종류)은 아래에 같은 순서로.
- 가방: 장비는 분류 안에서 별 등급 → 강화가 높은 것부터(전에는 이름순).

### 리월 지도 (`app_liyue_areas.js`, `shell.css`)
- 사용자: 「별도 확인 필요나 좌표 아님 등등 저건 뭔 말인지 모르겠는데 저건 맵도 작게 만들고 제작중인게 다 보이는 느낌이라 보기에도 좋지 않아. 글 깨지는것도 잘 해주고.」
- 리월 세부 지역 26곳의 `anchor`(지도에 점을 찍은 사람의 메모: 「…생성 좌표는 아님」, 「수직 층은 표현하지 않음」, 「…별도 확인 필요」)가 지도 아래 한 줄, 지도 아래 상자, 목적지 카드마다 나왔다. 이제 어디에도 나오지 않는다(데이터에는 남아 있다). 카드는 「지역 · 하는 일」(예: 「벽수원 · 물가 낚시와 길목」)만, 장소 설명은 첫 화면의 설명(`description`)과 「주변 살펴보기」 그대로다.
- 지도 칸은 높이가 고정된 세로 묶음이고 지도는 0까지 줄어들 수 있었다. 「리월 세부 지역 찾아보기」를 펼치면 지도가 납작해지고 그림이 아래 경로 칸과 목록 위로 넘쳐 글이 겹쳤다(사용자 화면 3). 이제 「세부 지역 찾기 · 26곳」은 지도 위쪽 버튼으로 따로 창을 열고(고르면 창이 닫히고 지도가 그곳을 비춘다), 지도는 최소 높이를 지키며 아래 내용이 넘치면 지도 칸이 스크롤된다. 지도 칸과 새 창은 한국어 낱말을 줄 끝에서 쪼개지 않는다(전에는 경로 줄의 「리 / 월」, 버튼의 「임무 목적 / 지」).
- 확인(실제 클릭): PC 틀 800×600과 폰 375×812에서 적화주 · 갈대 물가 → 세부 지역 창 → 망서 객잔 · 아래 광장 / 리월항 · 부두 선택 → 경로 칸, 「지도 보는 법」을 펼쳐도 겹침 없음(지도 368px 유지, 칸 스크롤).
