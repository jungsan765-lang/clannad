# 0.15.10 — 감사 후 수정 후보

2026-10-03 사용자가 확인된 오류의 적용과 나머지 점검 준비를 요청했다. 기준은 테스트 브랜치 `test/crpg-v01414-story`의 `a8cf7925692eefcbd0bb4c2a72c54cde0b80db7f`(0.15.9)다. 이 문서는 코드 변경 내역이며 실제 서버 설치 완료 증명은 아니다.

## 수정 범위

| 영역 | 변경과 보존한 동작 |
|---|---|
| 창과 입력 | 닫힌 거래 창이 제목 화면을 덮지 않는다. 현재 최상단 팝업으로 포커스와 키 입력을 한정하고 Tab 순환·기존 Esc 닫기를 유지한다. 전투·이야기·퍼즐이 뒤에서 입력을 받지 않는다. |
| 화면 크기 | 태블릿 상단 메뉴를 두 줄로 배치한다. 모바일 채팅 버튼 자리를 하단에 확보하고 이야기 그림과 대사를 별도 영역에 둔다. 실제 초상이 없는 주인공의 빈 공간을 없앤다. 동료 안내의 펼침 상태와 읽던 카드 위치를 너비 변경 후 복원한다. |
| 테스트 안내 띠 | 실제 높이를 측정하여 제목·상단 메뉴·본문·고정 창에 공간을 확보한다. 글자가 두 줄이 되어도 고정 높이를 가정하지 않는다. |
| 안내와 획득 | 실행 불가능한 장비 안내와 강화 화면 제작 메모를 고친다. 개인 임무의 표시·수락·차감은 동일한 최종 비용을 쓴다. 오래된 숨은 재료 조건을 제거하며 비용·눈동자·레벨·이벤트 전용 조건은 유지한다. 재합류 위치와 페이몬 두 대사의 초상 연결을 고친다. |
| 저장과 동기화 | 같은 여정의 낮은 revision, 새 행동 전에 시작된 조회, 이전 로그인 세션의 응답을 폐기한다. 제목 화면 복귀 뒤 늦은 조회가 게임 화면을 다시 여는 것도 막는다. 관리자 초기화의 새 여정 revision 0은 허용한다. 같은 여정의 런타임 인덱스를 재사용하지만 저장 검증은 유지한다. 대사마다 서버에 저장하지 않는다. |
| 요청과 캐시 | 채팅을 닫으면 fallback 조회를 15초 간격으로 되돌리고 중복 조회를 합친다. 서비스워커는 같은 등록 경로의 현재·직전 버전 캐시를 보존한다. 사용자 저장 DB는 건드리지 않는다. |
| 편지·시장·토벌 | 편지 재전송의 같은 요청은 한 번만 차감한다. 시장은 전체 등록 물건을 검색한 뒤 응답 개수를 제한한다. 기존 7일 수령 기한 내 모든 종료 토벌을 확인·수령할 수 있다. |
| 다인 모드 | 손님 행동을 영구 영수증과 표시된 전투 차례에 연결한다. 오래된 명령과 변경된 의도를 구분하며 서버 재시작 후 방장이 같은 전투의 방을 다시 열 수 있다. 전투·보상·손님 위치 정책을 바꾸지 않는다. |
| 계정과 운영자 기능 | 외부 재화와 연결된 되돌리기의 재되돌리기, 구형 거래의 레벨 우회를 막는다. 가입 일일 제한을 원자적으로 확정한다. 초기화 후 프로필 캐시와 이름 변경의 원본 저장을 일치시킨다. 일반 개인 저장만의 되돌리기는 유지한다. |

본편 원고, 캐릭터 성격, 전투 난도, 보상량, 수수료, 획득 비용을 새로 설계하지 않았다. 그림 교체와 스토리 전면 개작도 이번 변경에 포함하지 않는다.

## 검증 방법과 현재 한계

- 새 회귀는 실제 런타임·SQLite 또는 실제 소스 함수를 실행하여 중복 요청, 동시성, 복원, 입력 경계를 확인한다. `tools/verify_release.py`의 전체 릴리스 검사에 등록했다.
- 과거 테스트가 함수만 떼어 실행하면서 누락한 DOM·세션 의존성은 테스트 대역에 보충한다. 원래의 시간 초과·저장 보호 단언은 유지한다.
- 자동화한 임무·관계·분기 순회가 대사 문학성 검수나 정상 능력치의 전투 난도 확인을 대신하지 않는다.
- UI 코드와 합성 DOM 검사가 통과해도 실제 좌표 클릭·화면 캡처·휴대폰 키보드 확인은 별개다. 이 작업 중 CUA 브라우저는 자격 증명 보호 오류로 새 로컬 문서 관찰도 차단했다. 보호를 우회하거나 브라우저 검증을 했다고 기록하지 않는다.
- `QA_AUDIT_MATRIX_2026-10-03.md`와 로컬 QA 생성기로 남은 화면·입력·기기 검사를 이어 간다. 합성 저장은 배포 묶음과 실제 사용자 계정에 넣지 않는다.
- SSE 연결 집중/느린 소비자의 메모리 위험과 영수증·세션의 장기 증가(SV-07/08)는 별도 용량 시험과 보존 설계가 남았다. 자동 삭제나 이용 제한 정책을 임의로 추가하지 않았다. 감우 개인 이야기의 서사 시점(C05)도 편집 검토 대상으로 남긴다.

## 테스트 배포와 이후 확인

1. 로컬 회귀 및 빌드 결과를 확인하고 테스트 브랜치만 갱신한다. main 병합·운영 승격은 하지 않는다.
2. PR의 `CRPG Verify and Publish Artifact` 검증 및 `test-package` 성공을 확인한다. 소스/빌드 결과물의 기존 브라우저 CI도 여기에 포함된다. 이 CI는 전 기기 육안 검사와 다르다.
3. `crpg-test-latest`의 SHA 표시 파일과 두 묶음의 커밋·엔진이 같은지 확인한다. GitHub 게시와 VPS 설치를 구분한다.
4. `tools/install-fixed-region-test-release.sh`에 `CRPG_EXPECTED_TEST_SHA=<검증한 40자리 커밋>`를 전달한다. 최신 릴리스가 다른 커밋으로 바뀌면 로컬 변경 전에 거절한다. 실제 VPS에서는 다운로드와 교체만 수행하며 npm/build/test를 돌리지 않는다.
5. 설치 뒤 공개 `release.json`, 테스트 API `/health`, 브라우저 버전 표시를 함께 확인한다. 신규·기존 저장, 재접속, 거래·편지·다인 기능을 격리된 테스트 계정으로 점검한다.

GitHub 성공만으로 실제 테스트 서버 또는 운영 서버 반영 완료라고 보고하지 않는다. 화면 확인과 정상 플레이 검수가 남았으면 `전체 점검 완료`로 표시하지 않는다.
