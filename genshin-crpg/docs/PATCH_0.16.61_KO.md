## 1. 서버 최적화: 동시 접속 약 100명 → 약 300명

**원인.** 서버는 계정의 게임을 메모리에 16개까지 들고 있다(`CRPG_RUNTIME_CACHE_MAX`, 기본 16). 그보다 많은 사람이 놀면 행동마다 그 계정의 게임을 새로 만든다. 새로 만드는 데 약 27ms가 들었고, 그중 80%는 모든 계정에 똑같은 표(성장·시장·지도·지역·이야기 …)를 매번 다시 만드는 일이었다.

**고침**(`runtime_balance_admin_v01623.js`): 그 표는 저장(세이브)을 읽지 않는다. 같은 원문 DB·운영자 밸런스 판마다 한 번만 만들고, 새 게임에는 줄(row)을 복사해 준다. 0.16.28의 이야기 공유와 같은 방식이다.

- 계정마다 자기 표 복사본을 갖는다. 한 계정이 표를 바꿔도 다른 계정에 번지지 않는다(0.16.28 검사 `test_runtime_capacity_v01628` 그대로 통과).
- 고칠 수 없게 잠근 이야기 줄은 전처럼 함께 쓴다.
- 만드는 중인 게임이 기준과 다른 상태이면(설치 표시가 이미 있거나 표가 다르면) 예전처럼 전부 다시 만든다.
- `runtime_tasks_v0167.js`: 의뢰 288개를 넣을 때 이미 있는지 목록 전체를 훑던 것을 집합(Set)으로 바꿨다(결과 같음).

게임 하나 새로 만들기: **27ms → 4.8ms**. 게임 하나 메모리: 2.7MB → 1.7MB.

**측정**(`tools/benchmark_players_v01661.mjs`, 이 컴퓨터, 실제 HTTP 서버 + SQLite 파일). 사람마다 평균 5초 생각하고(지수 분포) 행동한다. 40%는 전투 행동, 60%는 메뉴. 모두 필드 보스 전투 중인 Lv20 계정이다. 게임 보관 16개(기본값).

| 동시 접속 | 전: 행동/초 | 전: 응답 p50 · p95 | 이제: 행동/초 | 이제: 응답 p50 · p95 | 이제 CPU |
|---:|---:|---|---:|---|---:|
| 100 | 16.4 | 61ms · 212ms | 16.2 | 15ms · 36ms | 29% |
| 200 | 21.4(포화) | 2.3s · — | 31.8 | 20ms · 69ms | 54% |
| 300 | — | — | 47.1 | 50ms · 649ms | 79% |
| 400 | ~22(포화) | — | 54.6(포화) | 590ms · 1.9s | 88% |

- 이 컴퓨터에서 쾌적한 한계는 동시 접속 약 **250~300명**이다(전에는 약 100명).
- 서버 VPS의 CPU 한 개가 이 컴퓨터 한 코어보다 느리면 그만큼 줄어든다. 1GB 서울 VPS는 대략 150~250명으로 본다(실측 아님).
- 메모리: 300명일 때 끝난 뒤 RSS 약 240MB, 힙 약 95MB. 힙을 192MB로 묶고 250명을 돌려도 멈추지 않았다(최고 RSS 411MB). 다만 메모리 정리(GC)가 CPU를 더 써서 p95가 0.64초로 늘었다. 1GB VPS는 메모리보다 CPU가 먼저 찬다.
- 서버를 키울 때: 사람이 150명을 넘게 꾸준히 몰리면 CPU 2개·메모리 2GB 이상을 권한다(서버는 한 프로세스라 CPU 1개를 주로 쓰고, 나머지는 메모리 정리와 SQLite가 쓴다).
- **가입한 계정 수**는 사실상 제한이 없다. 계정은 SQLite 파일에 있고, 동시에 노는 사람만 CPU를 쓴다. 디스크만 본다(행동마다 영수증 한 줄이 남는다, 0.16.28부터 지우지 않음).
- 사람이 더 몰리면 아래 「서버 문」이 새로 들어오는 사람을 막는다.

## 2. 서버 문(운영자 → 서버)

`server/gate-v01661.mjs`, 운영자 화면 「서버」 탭의 「서버 문」 카드.

- **닫기/열기(점검):** 닫으면 플레이어는 로그인·가입·행동을 할 수 없고 「서버 점검 중입니다. (안내)」가 보인다. 운영자 계정은 그대로 들어간다. 대화창을 연 사람에게 바로 알린다. 서버를 다시 켜도 닫힌 상태가 남는다(SQLite `server_gate`).
- **최대 동시 접속:** 최근 5분 안에 행동한 사람 수. 가득 차면 새 로그인·가입은 「접속 인원이 가득 찼습니다 (N / 최대명)」. 이미 들어와 있는 사람은 계속 논다. 기본 300명(`CRPG_MAX_ONLINE`), 운영자 화면에서 1~5000명.
- **붐빔 자동 막기:** 서버가 밀리면(2초 평균 지연이 120ms를 넘는 구간이 두 번 연속) 새 로그인·가입을 「서버가 붐빕니다 … 1~2분 뒤 다시」로 돌려보낸다. 평균이 40ms 아래로 내려오면 다시 받는다. 이미 들어온 사람은 막지 않는다. 켠 뒤 20초는 재지 않는다.
- 카드에 지금 접속 수, 붐빔 여부, 평균·p99 지연, 연결 수, 메모리가 보인다. 바꾸면 운영 기록에 「server-gate」가 남는다.
- 거절한 행동은 적용하지 않는다(`outcome:'REJECTED'`). 클라이언트는 다시 보내지 않는다.

## 3. 대화 채널 5개

`fixed-region-live.mjs`, `app_chat.js`: 「월드」 대화를 채널 1~5로 나눴다. 대화창 위에 채널 번호 띠가 있고 누르면 옮긴다.

- 처음 들어오면 60명이 안 찬 첫 채널, 모두 찼으면 가장 한산한 채널로 간다. 고른 채널은 그 기기에 기억한다.

## 4. 평범한 보물상자가 정교한 상자보다 원석을 많이 주던 것

몬드의 숨은 보물 둘이 「평범한 보물상자」로 표시됐지만 보상은 진귀한 보물상자와 같았다(원석 90 · 모라 2,500 · 영웅의 경험). 정교한 보물상자(원석 60)보다 많았다. 이 둘을 「진귀한 보물상자」로 고쳤다(`runtime_chests_v01415.js`). 보상은 그대로다.

이제 등급별 원석: 몬드 45 · 60 · 75~90 · 120, 리월 60 · 75 · 90~105 · 120(평범한 · 정교한 · 진귀한 · 화려한). 숨은 보물의 위치는 문서에 적지 않는다.

## 6. 다인(함께하기) 점검

서버 코드를 그대로 돌려 재현한 문제를 고쳤다.

1. **방장이 떠나도 방이 닫히지 않음:** 손님의 행동·자동 차례·상자가 방장 저장을 읽을 때마다 「방장이 있다」로 기록했다. 이제 방장 자신의 행동만 센다.
2. **다른 방 전투 ID:** 남의 세계에서 만난 손님 전투에 그 방 ID가 붙어 자기 방으로 잘못 읽혔다. 이제 남의 세계(`coopAway`)에서는 읽지 않는다.
3. **손님 전투에 들어간 방장이 걸어 나감:** 방장이 다른 사람 전투에 들어가 있는 동안 이동·새 전투를 막는다(「함께 싸우는 동안에는 …」). 전에는 방장 캐릭터가 AI로 넘어가고 보상을 잃었다.
4. **미니게임 도중 자동 차례:** 손님 차례 20초 안에 미니게임(서리 열매 치기는 3초 + 14초)을 끝내지 못하면 AI가 대신 쳤다. 미니게임이 있는 차례는 그 게임 시간 + 8초를 더 준다(최대 25초). 미니게임 중에는 화면도 자동 차례를 보내지 않는다.
5. **두 걸음 한꺼번에:** 손님이 이동을 두 번 빠르게 보내면 둘 다 처음 자리에서 길을 확인해, 이웃이 아닌 곳으로 건너뛸 수 있었다. 이제 한 걸음씩(「이동하는 중입니다」).

남은 의심(재현 못 함, 그대로 둠): 자기 차례에 아무것도 안 하는 방장 전투에 들어간 사람은 나가기 전까지 기다린다. 4인 전투 한 번 알림이 약 75KB다.
