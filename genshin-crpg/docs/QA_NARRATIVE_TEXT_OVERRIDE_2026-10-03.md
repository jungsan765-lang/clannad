## 판정

**확정: @text가 CHOICE 행을 가리키면 새 문장은 본문 열에만 들어가고, 화면 선택지는 기존 label로 남는다.** 전체 @text 173개 중 CHOICE 대상은 38개이며, 그중 원문과 실제로 다른 28개가 영향을 받는다. 나머지 10개는 원문과 같아 보이는 차이가 없다.

제품 코드·승인 원고·compiled content를 수정하지 않았다. 재컴파일·일괄 반영·커밋도 수행하지 않았다. 대표 2개는 허용된 임시 Node 검사로 실제 Runtime과 표시 함수를 호출했다. 서버·브라우저·사용자 저장 데이터에는 접근하거나 변경하지 않았다.

## 코드 근거

1. [runtime_local_story.js:16](../source/runtime_local_story.js#L16)~25: 화자가 나이면 CHOICE를 생성한다. row[9]는 빈 본문, row[10]은 선택지 label이다.
2. [runtime_main_story_k.js:60](../source/runtime_main_story_k.js#L60)~61: @text 적용은 행 종류와 관계없이 r[9]=e.text만 수행한다. row[10]은 유지된다.
3. [runtime_main_story_k.js:91](../source/runtime_main_story_k.js#L91): 별도의 ??@ 경로는 CHOICE일 때 c[10]=o.label을 사용한다. 이 경로와 이번 @text 문제는 구분해야 한다.
4. [app.js:36](../source/app.js#L36): appendChoices는 displayText(c[10]||c[9])로 버튼 문구를 만든다. 비어 있지 않은 원본 row[10]이 새 row[9]보다 우선한다. [app.js:37](../source/app.js#L37)이 실제 선택지 화면에서 이를 호출한다.
5. [app_legacy.js:13](../source/app_legacy.js#L13), [app_journey.js:2](../source/app_journey.js#L2)~9의 displayText는 이름·조사·표기 변환을 한다. row[9]/row[10] 우선순위를 바꾸지 않는다.

원고만 읽으면 인사·존댓말·감정 표현이 고쳐진 것으로 보이지만 게임 선택지에 일부 옛 문장이 남는다. 행추 재회 인사, 감우에게 쓰는 존댓말, 짐꾼을 두고 온 고백도 포함된다.

## 대표 2개 실제 Runtime 재현

각 사례마다 tests/helpers_v011.cjs의 fresh('MAP_LIYUE_PLAINS','ROUTE_ISEKAI')로 독립 Runtime을 만들었다. installMarketContent() 후 storyIndex()를 구성하고 대상 CHOICE_GROUP을 메모리상 현재 커서로 지정했다. prepareStory() → storyChoices()로 얻은 행을 현재 소스의 appendChoices, app_legacy의 displayText, app_journey의 displayText 변환에 전달했다. readable_text.js도 실제 파일을 로드했다.

DOM 대신 버튼 문구를 수집하는 작은 메모리 객체를 사용했다. 브라우저 시각 검사나 전체 루트 재생 검사는 아니다. 실제 선택 확정이나 스토리 효과 실행은 하지 않았다.

공통 결과: **41개 원고 체인 설치, 설치 실패 0개**, 선택지 1개. 실제 행 유형 CHOICE, 화자 {PLAYER_NAME}, 검사 이름으로 변환하면 클라나드. 표시 함수 호출 전후 게임 상태 동일.

## AB 화자 위험 — 코드와 별개로 원고 확인 필요

V141_AFTER_ISK_L01_AB_069_2의 원본 화자는 **나**다. 앞에서는 연비가 주인공을 칭찬하고 각청이 현장 얘기로 돌린다. 원래 주인공의 “내 칭찬이었어. 조금만 더 듣고 싶었는데.”는 그 흐름과 맞는다. 새 원고는 “칭찬 중이었는데. 한 조항만 더 읽어 주려고 했는데.”로 되어 있다.
