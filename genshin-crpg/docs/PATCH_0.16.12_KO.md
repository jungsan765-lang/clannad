# 0.16.12 · #291 실패 수정과 주간 리월 지역40승 제거

기준 소스: `f07aa6ded6c6281e7590e4673ddec5ff452f4276`(0.16.11). 사용자 확인 뒤 누락된 주간 리월 지역40승을 추가 제거한다. 화면·전투·성장·시장·재료 수치는 이번에 바꾸지 않는다.

## 임무 변경

`W_V168_LIYUE_PATROL`(리월 평야·산악·절운간 전투40승)을 활성 주간 목록과 연결에서 제거했다. 기존 네 삭제와 합쳐 다섯 개다. 몬드·리월 지역40승은 모두 활성 목록에 없다.

현재 정의 수는 일일11·주간27·일회성288개다. 접수 연습 수락→캐서린 보고로 다른 갈래를 여는 방식, 선행 보상 수령 후 반복 후속을 공개하는 방식, 다른 목표 횟수·개별 보상, 일일/주간 모두 달성20/200원석, 동시 의뢰 상한5개를 유지한다.

현재 연결 표와 데이터: [TASK_BRANCHES_V01612_KO.md](TASK_BRANCHES_V01612_KO.md), [data/task_branches_v01612.json](data/task_branches_v01612.json). 이전0.16.11 표와 감사자료는 해당 버전의 역사로 남긴다.

## 기존0.16.11 저장

169 카탈로그와 별도로 171 카탈로그·정의·선행 연결을 보관한다. 실제171 엔진으로 만든 저장을 당시 규칙으로 검증하고 172로 이어받는다. JSON 속성 순서가 다른 옛 기본 목표도 원래 생성 순서로 검증한다.

리월40승만 해당 기간 배정에서 제외한다. 다른 목표의 고정 정의·진척·활성 시점과 이미 받은 보상 기록을 유지한다. 삭제 목표에서 이미 지급한 돈과 원석을 회수하거나 재지급하지 않는다. 삭제 목표만 미달이던 저장은 남은 전체 목표가 완료되어 있으면 주간 모두 달성200원석을 한 번 받을 수 있다.

171의 잠긴 후속 진척·수령, 누락/미래 활성 시점, 위조 보상, 두 선행 조건 누락을 거부한다. 172에서 삭제 목표를 다시 넣거나 직접 청구할 수 없다. 168/169에 한정한 접수 연습 보정이 171 저장에 확대되지 않도록 유지한다.

0.16.11에서 문서화한 기존 주의 일일 보고5회 조건은 그대로다. 이미 배정된 옛 목표의 남은 날짜가 부족하면 이번 주 전체 달성이 어려울 수 있으며, 다음 주부터 남은 날짜를 확인하는 배정을 적용한다.

## #291 실패 원인과 수정

[원본 실행](https://github.com/jungsan765-lang/clannad/actions/runs/37669375647)은 검증 프로그램150개 중149개 통과·1개 실패다. `regression shard 3`의 `tests/test_feature_boundaries_v01513.cjs`가 실패했고 뒤의 verify/pages/test-package는 실행되지 않았다. source UI와 다른 세 regression shard는 통과했다.

해당 검사는 요청 시각을 과거10월3일로 설정했지만, 저장 복구의 Runtime 생성은 실행일 시각을 사용했다. 생성자에서 임무 날짜를 현재로 갱신한 뒤 다시 과거 요청 시각을 넣어 저장하면서 미래 날짜 거부에 걸렸다.

테스트의 복구 준비만 고쳐 Runtime 생성부터 같은 모의 요청 시각을 사용하고 `Date.now`를 반드시 원복한다. 기존13개 검사와 assert73개를 유지한다. 서버의 미래 날짜·진척 검증과 워크플로의 검사 목록·병렬 실행·배포 조건을 제거하거나 약하게 바꾸지 않는다. release gate에는 새171→172 회귀 프로그램 하나만 추가한다.
