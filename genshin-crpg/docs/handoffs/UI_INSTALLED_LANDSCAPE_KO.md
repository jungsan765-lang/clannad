# UI 담당 AI 인수인계 · 2026-10-06 13:20 KST 사용자 결정

이 문서의 결정이 `NEXT_STEPS_KO.md` 및 0.15.22의 세로 휴대폰 설계보다 우선한다.

## 사용자 지시

- 휴대폰 홈페이지에서 그대로 플레이하는 방향을 중단한다. 설치해서 실행하는 형태를 요구하고 **가로 화면을 기준으로 UI를 전면 개편**한다.
- 설치 안내와 설치 후 실행 흐름, 세로로 들었을 때 가로 회전을 요구하는 화면까지 함께 설계한다. 기존 PWA/설치 코드부터 확인하고, Android·iOS 실제 제약을 검증한다. 설치 요구와 가로 차단을 단순한 안내문 하나로 구현 완료라고 하지 않는다.
- **13:25 추가 지시:** 사용자는 0.15.22 이전에 쓰던 전투 구도를 선호한다. 가로 실행에서도 **원래 구도와 그림 비율을 유지**한다. 0.15.21의 화면/소스부터 비교한다(기준 커밋 `b1b86bd5588c406fce4e5eba67313d166ed4f186`). 작은 가로형 적·아군 카드가 왼쪽에 몰리고 중앙·오른쪽에 큰 공백이 남는 현재 배치는 폐기 대상이다. 현재 스크린샷을 가로 UI의 목표 디자인으로 삼지 않는다.
- 현 담당은 **튜토리얼과 밸런스만** 계속 점검한다. 이 문서는 다른 UI 담당 AI가 이어받기 위한 것이다. 현 담당이 설치 강제·가로 UI를 완료했다는 뜻이 아니다.
- 일반 적 최대 8명, 최대 두 줄. 적 소환체와 아군 소환체는 각각 별도 공간에 최대 3명. 전투판은 스크롤하지 않고 창 크기에 맞아야 한다.
- 인원이 적을 때 빈 8칸과 빈 소환체 영역을 예약하지 않는다. 실제 인원에 공간을 배분하며 그림·이름·HP·버프·행동 버튼이 알아보기 쉬워야 한다.
- 소환 영역의 표기는 **아군 소환체 / 적 소환체**로 통일한다. 사용자가 “우리 소환체”라는 표현을 명시적으로 거절했다.
- 행동 순서를 1·2·3 숫자만으로 표시하지 않는다. 누구 순서인지 그림과 이름으로 알 수 있어야 하며, 라운드 중 재생으로 순서를 다시 그리는 경로도 확인한다.

## 제보된 실제 문제

1. 첫 이동 화면: 안내 카드가 화면을 크게 차지하고, 작은 지도 안의 목적지 목록은 잘리며 이동 버튼을 찾기 어렵다.
2. 첫 전투: 적 2명뿐인데 8명용 두 줄과 빈 소환체 공간을 예약해 큰 빈 공간이 생긴다. 그림은 과도하게 작다.
3. 행동 순서가 번호만 보인다. 실제 첫 전투에서는 기본 조작을 배우지 못하고 나중의 별도 훈련으로 미뤄져 있다.
4. 기존 검사의 '컨테이너 안에 있음'만으로 가독성을 통과 처리하지 않는다. 실제 그림 크기, 이름, 클릭 가능 영역, 겹침을 눈으로 확인한다.

## 튜토리얼과의 접점

- 안내용 고정 칸, 접기, '나중에 계속', 의미 없는 다음 버튼을 만들지 않는다.
- 배경을 어둡게 하고 실제 조작 대상만 밝히며 바깥 클릭·단축키를 막는 **강제 스포트라이트**를 사용한다.
- 이동 → 이야기 속 첫 편성·장비 → 실제 첫 전투 조작. 여행자는 엠버와 함께 싸우는 첫 장면에서 엠버 편성과 장비 장착을 배운다.
- 별도 훈련 전투·비경 입장·반복 육성까지 강제로 이어 붙이지 않는다. 생활 조작은 해당 활동을 처음 이용할 때 배운다.
- 현 담당의 `source/app_tutorial.js`, `source/runtime_tutorial_v01522.js`, `source/tutorial_v01523.css` 변경과 충돌하지 않도록 최신 HEAD 및 인수인계를 다시 읽는다. 0.15.23에서 실제 첫 이동·편성·장비·전투 조작으로 연결했다. 검사 범위는 `QA_V01523_KO.md`를 읽는다.

## 미완성 세로 UI 실험 보존

`UI_PORTRAIT_UNFINISHED_20261006.patch`는 사용자 방향 변경 직전의 **미완성·미검증 실험**이다. 자동 적용하지 않는다. 세로 UI를 계속 만들라는 뜻도 아니다. 활성 소스에서는 되돌려 두었다.

실험 과정에서 발견한 주의점:

- 기존 CSS는 `.combatant-copy`에 `grid-column:2`, 그림에 `grid-row:1/3` 등을 지정한다. 새 그리드를 얹기만 하면 암묵적 열이 생겨 그림이 사라지거나 이름이 밀린다. 사용하지 않을 옛 배치 규칙까지 정리해야 한다.
- 적 정보 버튼의 실제 클래스는 `.enemy-info-button`이다. 다른 이름을 대상으로 스타일을 작성하면 잘림이 남는다.
- 전투 시작 버튼은 실제 `data-action`이 없던 경로가 있었다. 클래스/DOM을 확인하지 않은 선택자로 검사를 통과시키지 않는다.
- 화면만 고칠 때 전투 수치·새 몬드 개인 이야기 원고를 바꾸지 않는다.
