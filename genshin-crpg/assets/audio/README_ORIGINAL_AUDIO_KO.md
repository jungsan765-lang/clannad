## 연결 정보와 검사

`audio-manifest.json`은 파일별 ID·경로·형식·길이·peak·RMS·반복 여부·작성자·바이트 수·SHA-256을 담습니다. `bindings`에는 탐색/전투, UI, 전투, 7원소, 4반응의 재생 ID를 연결했습니다. 음악의 `master_loop_check`와 `decoded_loop_check`는 WAV 원음 및 OGG 디코딩 후 각각의 반복 접합부 검사입니다.

검사 기준은 클리핑 샘플 0, 접합부 샘플 차이 −40 dBFS 미만, 접합부 차이가 음악 내부 샘플 차분의 99백분위 이내입니다. 두 루프 모두 통과했습니다. OGG 재생 길이도 원음의 40초·32초와 같습니다. 이는 파일 신호 검사이며 실제 기기 스피커에서의 청취 평가는 포함하지 않습니다.

앱에서는 처음 사용자 입력이 발생했을 때 오디오를 활성화하고, 음악은 native loop 또는 AudioBufferSourceNode의 `loop`를 사용하세요. 매 반복마다 타이머로 새 파일을 시작하면 파일 자체와 무관한 틈이 생길 수 있습니다. BGM 전환은 약 250~400 ms 음량 전환, SE는 한 번 디코딩한 버퍼 재사용이 적합합니다. 음악 WAV 원음과 생성 스크립트는 배포하지 않아도 됩니다.

## 재생성

이 폴더에서 `python synthesize_original_pack.py`를 실행하면 동일한 시드와 음표 배열로 원음·OGG·메타데이터를 재생성합니다. Python의 NumPy·SciPy와 FFmpeg의 libvorbis 인코더를 사용합니다. 코드, 음표, 합성 파라미터는 이 프로젝트의 오리지널 제작용으로 제공됩니다.
