# v0.13.18 — 1번: 층암거연 전투 시작 오류 수정

기준 프로젝트: v0.13.17. 작업 범위는 게임 시스템 점검 1번만이다.
작성일: 2026-09-26 KST. 원격 사이트 배포나 Google Sheets 수정은 하지 않았다.

## 원인과 수정

기준 버전에서 `EG_CHASM_HUSK`, `EG_CHASM_SERPENT`를 각각 생성하면 `UNSUPPORTED_ENEMY` 오류가 발생했다. 적 편성과 카드 원문은 존재했지만 일부 카드 효과를 실행하는 코드가 없었다.

기존 DB에 적힌 아래 네 기술을 실제 실행기에 연결했다. 새로운 원신 정경 설정이나 기술을 추가한 것이 아니라, 이 CRPG의 기존 하우스룰 데이터를 구현한 작업이다.

| 기존 카드 | 실제 연결한 처리 |
|---|---|
| 심연 기치 | 같은 진영의 생존자 최대 3명(시전자 포함)에게 공격력 +10%, 2라운드. 같은 기치 효과는 갱신하며 중첩 증폭하지 않음. 같은 강화가 없는 동료 2명 이상 조건과 재사용 3턴 유지. |
| 어둠의 일제사격 | 공격 가능한 상대 최대 2명에게 공격력 0.65배 물리 피해. 적중 후 기존 저항 판정으로 1라운드 감속. 대상 수 조건과 재사용 2턴 유지. |
| 흑검 연참 | 한 대상에게 공격력 0.48배 물리 공격 2회. 두 번 모두 맞고 생존했을 때 다음 행동 점수 -8. 첫 타로 쓰러지면 두 번째 타격을 시체나 다른 대상으로 넘기지 않음. |
| 방벽 절단 | 보호막이 있는 대상에게 공격력 1.15배 물리 피해. 보호막에만 피해 1.5배. 해당 주공격이 보호막을 파괴했을 때만 자신에게 공격력 +10%, 2라운드. 체력으로 넘어가는 피해는 보호막 배율을 적용하지 않음. |

주요 구현은 `source/runtime_chasm_skills.js`에 격리했다. 보호막 처리에만 기존 `runtime_combat.js`의 작은 확장 지점을 추가했다. 등록 플래그만 바꾸거나 미지원 검사 자체를 무력화하지 않았고, 적 편성을 삭제·대체하지 않았다. 카드 원문·소유자·대상·발동 조건이 바뀌면 실행기 불일치를 차단한다.

## 검증 결과

- 전용 런타임 검사 **45/45 통과**: 구버전 오류 재현 2건, 두 편성 × 두 주인공 × 1~4인 시작·저장 복원, 네 기술의 실제 피해·대상·조건·강화 만료·중첩 방지·재사용·AI·승패 정산 등을 포함한다.
- 몬드 일반전과 리월의 다른 일반전 등 세 편성은 동일 시작 조건·난수·행동에서 기준 버전과 새 버전의 직렬화 상태가 동일했다. 전 지역의 모든 전투 조합을 검증했다는 뜻은 아니다.
- 두 편성 모두 실제 기본 공격 및 동료/적 AI를 반복해 승리·정산까지 도달했다. 승리 영수증은 한 번만 남으며 재정산을 호출해도 중복되지 않았다. 패배 종료도 확인했다.
- 완료 경로 검사는 인공 시작 상태에서 플레이어 기본 HP 100,000, 전투 공격력 1,500을 설정해 끝까지 진행하는 시험이다. 이 수치는 테스트 사본에만 쓰였으며 게임 DB/정상 캐릭터 수치를 바꾸지 않았다. 따라서 적정 난이도·정상 파티 승률 검증으로 해석하면 안 된다.
- 전투 중 저장 후 같은 행동을 실행하면 원래 실행과 복원 실행의 난수·진행·직렬화 결과가 일치했다. 저장 형식의 신규 전투 버전과 강화 정보에 대한 오류 검출도 확인했다.
- 빌드 성공. 원본 이미지 재인코딩 대신 기존 파일의 SHA-256이 일치하는 검증된 캐시를 사용했다. 이미지 바이트는 변경하지 않았다.
- 빌드된 실행본 별도 검사 **6/6 통과**: 두 편성 시작/저장 파일 왕복, v0.13.17 호환 태그 파일 가져오기, 신형 저장을 구형 호환 목록에서 차단, 소스와 실행본 일치, 오프라인 목록의 **778개 파일 해시 일치**.
- 기존 기본 통합 검사 18/18 및 K계열 스토리 검사 15/15도 통과했다. 이 기존 검사들의 로더 범위는 새 전용 검사보다 좁으므로, 전용 검사 대신으로 사용하지 않았다.

실제 결과 파일: `runtime-tests.json`, `dist-tests.json`, `browser-tests.json`.
전용 검사: `node tools/test_chasm_step1.cjs`.
기준 버전 소스 비교까지 재현하려면 환경변수 `CRPG_BASELINE_SOURCE`에 변경 전 v0.13.17의 `source` 폴더를 지정한다. 지정하지 않으면 기준 버전 전용 5개 검사를 제외한 40개를 실행한다.
실행본 검사: `node tools/test_chasm_dist.cjs`.
재빌드: `python tools/build.py`.

## 보존한 항목과 다른 번호의 범위

`content/db.json`은 기준 v0.13.17과 바이트 단위 동일하다. SHA-256:
`d0605b21973841338f16be6eb45537e0c121cc8c31a9ac540465650d74191131`.

스토리, 기존 10루트 수정, 적 편성·출현 확률·레벨·기본 능력치, 모라·소재 드롭, 영입 조건, 지도, 장비, 보스 규칙, 이미지, 원본 시트와 개인 세이브를 변경하지 않았다. 최소 기술 레벨 11도 기존대로다. 2번 이후의 보상 누락·레벨 불일치 등은 이번 패치로 해결되지 않는다.

저장 호환 태그에 `-chasm1`을 추가했고, 기존 허용 목록과 v0.13.17 파일 형식을 유지했다. 새 전투를 저장한 파일을 구버전이 잘못 읽는 것은 차단한다. 이미 진행 중인 다른 지역 전투는 이전 상태를 유지한다. 새 버전 기록이 없는 손상된 층암거연 전투 저장은 조용히 추정 복원하지 않고 오류로 구분한다.

## 검증하지 못한 범위

Chromium에서 빌드 결과에 접속하는 시도는 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단됐다. 실제 화면·터치·브라우저 IndexedDB 자동 저장·서비스 워커 갱신·운영 사이트 동작은 검증 완료로 표기하지 않는다. 저장 검사는 런타임 직렬화와 SaveAdapter 파일 내보내기/가져오기 경로 기준이다.

기존 `tools/test_story_rev02.js` 재실행은 실행 시간 제한으로 종료되어 이번 작업에서 완료 결과를 얻지 못했다. 이전 패치의 214/214 기록을 이번 재검증 결과로 집계하지 않았다. 스토리 원문과 해당 런타임 파일들은 변경하지 않았다. 전 루트 수동 완주·전체 게임 밸런스 검증은 이번 범위가 아니다.

## 적용

이 ZIP은 단독 게임이 아니라 **v0.13.17 전체 개발 프로젝트용 증분 패치**다. 프로젝트에는 `package.json`, `source`, `content`, `dist`가 있어야 한다.

1. 게임에서 현재 저장을 파일로 내보내 별도 보관하고 게임 창을 닫는다.
2. 패치 ZIP을 다른 폴더에 푼다. 패치 폴더에서 아래를 실행한다.

```text
python apply_patch.py "기존 v0.13.17 프로젝트 폴더" --check
python apply_patch.py "기존 v0.13.17 프로젝트 폴더"
```

파일 불일치가 있으면 강제로 덮지 않고 중단한다. 정상 적용 시 변경 전 파일은 프로젝트의 `.patch-backups`에 남는다. 자동 백업은 소스 파일용이며 브라우저 개인 세이브 백업을 대신하지 않는다. 적용 후 기존 `start-game.bat` 또는 `start-game.sh`로 실행한다. 게임 내 버전이 v0.13.18인지 확인한다. 이전 사이트를 자동 배포하거나 업데이트하지 않는다.

이미 같은 패치를 적용한 프로젝트에는 중복 변경하지 않는다. 다른 세션에서 수정된 프로젝트는 충돌 파일을 확인하고 병합해야 한다.
