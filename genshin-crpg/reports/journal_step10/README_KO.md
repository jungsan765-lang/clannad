# v0.13.27 — 임무·호감도 가독성, 아이템 원본 아이콘

## 임무 화면
- 모든 개인 임무를 카드로 길게 늘어놓던 「개인 임무」 탭을 없앴다. 탭은 진행 중 · 동료 획득 · 완료 세 개다.
- 진행 중은 세 칸으로 나눈다.
  - 의뢰: 수락한 의뢰와 본편 연동 의뢰, 의뢰 접수 위치.
  - 동료 획득 임무: 소개받았고 아직 끝내지 않은 개인 임무만. 카드에는 진행 장소, 부족한 조건·준비물, 시작 또는 이동 버튼 하나만 두고 준비물 구하는 곳은 접어 둔다. 지금 시작 가능 → 이동 필요 → 조건 확인 필요 순서.
  - 호감도 임무: 만난 인물마다 지금 할 수 있는 다음 호감도 이야기 하나(현재 장소에서 시작 또는 그 장소로 이동). 조건이 남은 인물은 인원수만 보여주고 호감도 화면으로 안내한다.
- 현재 장면 때문에 모든 시작 버튼이 막혀 있으면 이유를 카드마다 반복하지 않고 목록 위에 한 번만 표시한다.
- 소개받기 전 임무와 소개처는 기존 동료 획득 탭이 그대로 담당한다.
- 완료 탭은 의뢰 · 동료 획득 임무 · 호감도 이야기를 한 줄씩 요약한다.
- 여행자 루트에서 개인 임무 9개를 소개받고 5개를 마친 검증 상태: 기존 개인 임무 탭(카드 38개) 33,939px → 새 진행 중 탭 2,366px.

## 호감도 화면
- 인물마다 호감도 임무를 열고 접을 수 있다(기본 접힘). 접힌 상태에서도 「호감도 임무 완료 수 / 전체 · 다음 단계와 상태」가 보인다. 열림 상태는 화면을 다시 그려도 유지되고, 모두 펼치기 / 모두 접기를 제공한다.
- 지금 진행할 수 있는 인물이 먼저 나온다. 그 외에는 기존 순서.
- 단계는 1~5단계 → 유대 이야기 1·2 순서로 정렬했다(기존에는 데이터 순서라 1, 3, 5, 2, 4로 섞였다).
- 기존에는 장소 조건을 먼저 검사해 모든 단계가 「해당 인물이 있는 장소에서…」로만 보였다. 이제 진행 장소에 있다고 가정해 다시 판정하므로 실제 막힌 이유(호감도 N점 필요 · 현재 M점, 앞 단계, 개인 임무)를 다음 단계에 표시하고, 이후 단계는 열리는 호감도 점수만 짧게 적는다.
- 14명 검증 상태에서 카드 높이 약 1,100~1,370px → 470~530px(접힌 상태).

## 구조
- 새 읽기 전용 모듈 `source/journal_presenter.js`(`CRPGJournalPresenter`)가 진행 중 목록·호감도 단계·인물 정렬을 계산한다. 액션을 호출하거나 저장을 바꾸지 않는다. `index.html`, `tools/build.py`, `sw.js` 코어 목록에 추가했다.
- 장소만 빠진 경우는 `legendIntroductionReason`과 같은 방식으로 현재 지도만 바꾼 읽기 전용 파사드에서 `storyEntryReason`을 다시 호출해 판정한다.
- 저장 형식·콘텐츠 시트·전투 규칙은 바꾸지 않았다.

## 아이템 아이콘
- 분류 아이콘으로만 보이던 138개(아이템·장비)에 원본 텍스처를 연결했다. `unavailable` 44개는 모두 해소.
- `exact_name` 46 · `verified_id_alias` 11 · `official_base_visual` 81(CRPG 자체 아이템은 가장 비슷한 원작 그림이며 동명 아이템이라고 주장하지 않는다).
- 출처 우선순위와 대응 근거는 `assets/icons/CREDITS.md`, 항목별 원본 URL·SHA-256은 `content/item-icons.json`, `content/item-icon-sources.json`에 있다.
- 시스템 전용 행, 스토리 전용 신의 심장, 아직 열리지 않은 스네즈나야 특별 보상 2종은 분류 아이콘을 유지한다.

## 빌드
- Windows에서 빌드할 때는 `python tools/build_windows.py`를 쓴다. 텍스트를 UTF-8·LF로 읽고 쓰며(CRLF로 쓰면 git이 LF로 저장한 뒤 오프라인 팩 SHA-256이 어긋난다), 이미 배포된 WebP를 캐시로 먼저 채워 다른 libwebp 버전이 기존 이미지를 다시 인코딩하지 않게 한다.
